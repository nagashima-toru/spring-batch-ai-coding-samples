# 要件定義書: 受注CSV取込・日次売上集計バッチ（order-daily-sales）

| 項目 | 内容 |
|---|---|
| 案件名 | 受注CSV取込・日次売上集計バッチ（order-daily-sales） |
| 作成日 / 更新日 | 2026-10-11 / 2026-10-11 |
| ステータス | 確定 |

## 1. 背景・目的

外部ECシステムから受注データが日次のCSVファイルで届くが、現状は取り込む仕組みがなく、
店舗別の日次売上を把握できない。
本バッチにより、受注CSVを毎日自動で取り込み、受注日×店舗の日次売上集計を作成する。

※ 本案件はハーネス（`/plan`・`/run`。`docs/development-guide.md` §2.4）の試走用の題材である。
要件定義〜設計レビューは人と Skills の対話で進め、実装〜システムテストをハーネスで進める。

## 2. 業務フロー概要

1. 外部ECシステムが前日分の受注CSV（1日1ファイル）を所定の場所へ配置する（本バッチのスコープ外）
2. **本バッチ**が毎日深夜、対象日の受注CSVを受注明細テーブルへ取り込む
3. **本バッチ**が取り込んだ受注明細から、受注日×店舗の日次売上を集計テーブルへ書き込む
4. 集計テーブルは売上照会・帳票（本案件スコープ外）が参照する

## 3. 機能要件

### 3.1 処理一覧

| No | 処理名 | 概要 | 入力 | 出力 |
|---|---|---|---|---|
| 1 | 対象日データの削除（洗い替え準備） | 対象日の受注明細・日次売上集計を削除する | 受注明細テーブル・日次売上集計テーブル | 同左（削除） |
| 2 | 受注CSV取込 | 受注CSVを1行ずつ検証し、正常行を受注明細テーブルへ登録する。不正行はエラーファイルへ出力する | 受注CSV | 受注明細テーブル・エラーファイル |
| 3 | 日次売上集計 | 対象日の受注明細を店舗ごとに集計し、日次売上集計テーブルへ登録する | 受注明細テーブル | 日次売上集計テーブル |

### 3.2 入力データ

| データ名 | 形式 | 文字コード | 件数規模 | 提供元 | 提供タイミング |
|---|---|---|---|---|---|
| 受注CSV | CSV（カンマ区切り・ヘッダ行あり・1行=受注明細1件） | UTF-8（BOMなし） | 1ファイル最大10万件 | 外部ECシステム | 毎日、実行開始（02:00）までに前日分を1ファイル配置 |

受注CSVの項目（案。§6 No.1 で確定する）:

| No | 項目 | 型 | 必須 | 備考 |
|---|---|---|---|---|
| 1 | 受注番号 | 英数字20桁以内 | ○ | |
| 2 | 明細番号 | 整数（1以上） | ○ | 受注番号＋明細番号で一意 |
| 3 | 受注日 | 日付（yyyy-MM-dd） | ○ | 対象日と一致すること |
| 4 | 店舗コード | 英数字10桁以内 | ○ | |
| 5 | 商品コード | 英数字20桁以内 | ○ | |
| 6 | 数量 | 整数（1以上） | ○ | |
| 7 | 単価 | 整数（0以上、円・税抜） | ○ | |

個人情報（顧客名・住所等）は含まない。

### 3.3 出力データ

| データ名 | 形式 | 出力先 | 利用者・後続処理 |
|---|---|---|---|
| 受注明細 | DBテーブル（CSVの1行=1レコード） | 受注明細テーブル（`app` スキーマ。新規設計） | 日次売上集計（本バッチ）・調査用 |
| 日次売上集計 | DBテーブル（受注日×店舗で1レコード） | 日次売上集計テーブル（`app` スキーマ。新規設計） | 売上照会・帳票（本案件スコープ外） |
| エラーファイル | テキスト（不正行の行番号・理由・元データ） | ジョブパラメータで指定したパス | 運用者による確認・ECシステムへの問い合わせ |

### 3.4 加工・変換ルール

- 明細金額 = 単価 × 数量（円・税抜の整数。端数は発生しない）
- 日次売上集計の単位は **受注日 × 店舗コード**。各店舗について次を求める
  - 受注件数: 受注番号の重複を除いた件数
  - 明細件数: 明細の件数
  - 売上数量: 数量の合計
  - 売上金額: 明細金額の合計
- 集計対象は取り込みで正常だった明細のみ（不正行は集計に含めない）
- 当日の受注が0件の店舗は集計レコードを作らない

### 3.5 エラーデータの扱い

- 次の行は**スキップして処理を継続**し、エラーファイルへ出力する。スキップが1件以上あればジョブは
  **警告終了（終了コード2）** とする
  - 必須項目の欠落、型・桁・値域の不正（§3.2 の項目定義に反するもの）
  - 受注日が対象日と一致しない行
  - 同一ファイル内での受注番号＋明細番号の重複（2件目以降）
- 次の場合は**異常終了（終了コード1）** とする
  - 受注CSVが存在しない・読めない、ヘッダ行が想定と異なる
  - システムエラー（DB接続断等）
- 異常終了・警告終了後のリカバリは、ECシステムから訂正ファイルを受け取り同じ対象日で再実行する
  （洗い替えのため二重計上は起きない。§5 リラン要件）

## 4. 実行条件

| 項目 | 内容 |
|---|---|
| 実行タイミング | 日次 02:00 開始 |
| 先行ジョブ / 後続ジョブ | 先行: なし（ECシステムのファイル配置が前提）／後続: なし |
| 処理時間の制約 | 05:00 までに完了必須（10万件で3時間以内。十分な余裕がある想定） |
| 実行単位・パラメータ | 対象日（受注日）をジョブパラメータで受け取る（省略時は実行日の前日）。入力ファイルパス・エラーファイルパスもジョブパラメータで受け取る |

## 5. 非機能要件

| 項目 | 内容 |
|---|---|
| データ量（現在/将来） | 1日最大10万件。将来の増加見込みは未確定（§6 No.2） |
| リラン要件 | 同じ対象日で再実行すると、その対象日の受注明細・日次売上集計を削除してから入れ直す（洗い替え・冪等）。途中再開は不要（先頭からやり直す）。再実行は運用者が手動で行う |
| 監視・通知 | 終了コード（0=正常 / 2=警告 / 1=異常）で判定し、1・2 は運用者へ通知する（通知手段は方式設計 architecture.md に従う） |
| データ保持・退避 | 受注明細・日次売上集計の保持期間は未確定（§6 No.3）。処理済み入力ファイルの退避は本バッチでは行わない（未確定 §6 No.4） |
| セキュリティ（個人情報等） | 個人情報を含まないため、マスキングは不要 |
