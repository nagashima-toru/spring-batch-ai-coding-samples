# creator ルール：/code-review の指摘を review-standards の区分で扱う

## 目的
`/code-review` の指摘を、規約レビューの区分（Must/Should/Ask）に合わせて、直す・残す・人に渡すに振り分ける。

## ルール
- 範囲・呼び方・回数などの手順の本体は `.claude/agents/creator.md` の「コードレビューを参照する基準がある時」節に従い、ここには写さない
- review-standards のタスクでは、手順1〜3のチェックリスト（規約）と手順4の `/code-review`（不具合）の両方を通す（PR #70 で、チェックリストだけでは不具合を拾えなかったため）
- review-standards の手順4の範囲（ジョブで変えた差分）と、受け入れ基準の `/code-review` の行の範囲（そのタスクの差分）は違う。受け入れ基準に `/code-review` の行がある時は、手順4で直した後に、タスクの差分でも実行する
- [Must] 相当の指摘（差分で変えた行へのクラッシュ・データ破損・誤った結果）は直す
- [Ask] 相当の指摘（直すのに設計・仕様の改訂が要る）は直さず、「進捗」に理由を書いて完了報告を `blocked: <質問文>` にする
- [Should] 相当の指摘は、review-standards のタスクでは直し、それ以外のタスクでは直さない
- 差分の外（既存コード）への指摘は直さず、「進捗」に `対象外（既存コード）: <指摘の要約>` として残す
- 「進捗」には、チェックリストと `/code-review` の指摘件数を出典ごとに分けて書く

## 確認方法
- 「進捗」に、出典ごとの指摘件数と、対象外として残した指摘（あれば）が書かれている
