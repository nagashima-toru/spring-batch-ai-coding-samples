# creator ルール：/code-review の指摘を review-standards の区分で扱う

## 目的
`/code-review` の指摘を、規約レビューの区分（Must/Should/Ask）に合わせて、直す・残す・人に渡すに振り分ける。

## ルール
- このルールは計画単位のレビュータスクで `/code-review` を実行する時に使う（`.claude/agents/planner.md` の「計画単位のレビュータスク」節。範囲は計画全体の差分）
- 範囲・呼び方・回数などの手順の本体は `.claude/agents/creator.md` の「コードレビューを参照する基準がある時」節に従い、ここには写さない
- review-standards のタスクでは `/code-review` を実行しない（`.claude/skills/review-standards/SKILL.md` の手順4。計画単位のレビュータスクに任せる）
- [Must] 相当の指摘（計画の差分で変えた行へのクラッシュ・データ破損・誤った結果）は直す
- [Ask] 相当の指摘（直すのに設計・仕様の改訂が要る）は直さず、「進捗」に理由を書いて完了報告を `blocked: <質問文>` にする
- [Should] 相当の指摘（性能・保守性・テスト不足などの致命的でないもの）は、計画単位のレビュータスクでは直さない（`.claude/agents/creator.md` の同じ節の4。致命的でない指摘は直さない）
- 差分の外（既存コード）への指摘は直さず、「進捗」に `対象外（既存コード）: <指摘の要約>` として残す
- 「進捗」には、`/code-review` の実行回数と、区分（Must/Should/Ask）ごとの指摘件数を書く

## 確認方法
- 「進捗」に、区分ごとの指摘件数と、対象外として残した指摘（あれば）が書かれている
