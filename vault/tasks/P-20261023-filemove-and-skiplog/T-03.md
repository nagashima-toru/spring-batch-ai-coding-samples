# T-03 加工時・書込時などの Skip の WARN ログに例外のメッセージをそのまま出さない（#100）

## 目的
`ErrorRecordSkipListener` の加工時・書込時の Skip と `FlatFileParseException` 以外の読込時の Skip で、WARN ログに例外のメッセージ（DB の制約違反の値など、行の値が入りうる）をそのまま出さず、#97（PR #101）の `onSkipInRead` と同じ規則で原因の種類だけを出す（方式設計 §8 の個人情報・機密情報のログ出力禁止。GitHub Issue #100）。

## 決定済み
- WARN ログの書式（`レコードをSkipしました。エラーレコードファイルへ退避します: file={} reason={}`）は変えず、`reason` に渡す値だけを変える
- `reason` の値
  - `onSkipInRead` で `t` が `FlatFileParseException`：今の `line=<getLineNumber()> cause=<原因>` のまま変えない（原因が `null` なら `FlatFileParseException`）
  - `onSkipInRead` で `t` がそれ以外・`onSkipInProcess`・`onSkipInWrite`：`cause=<t の原因>`
  - `<原因>` の規則は #97 と同じ：例外が `BusinessException`（派生を含む）ならその `getMessage()`、それ以外ならクラスの単純名（`getClass().getSimpleName()`）。この規則を private static メソッド1つにまとめ、`readReason` からも使う
- 位置情報（件番号など）は足さない。`SkipListener` の加工時・書込時の通知はレコードと例外だけを受け取り、件番号を持たないため。レコードの内容（フォーマッタの出力）はログに出さない
- エラーレコードファイルの中身（`元レコード<TAB>エラー理由`。エラー理由は `t.getMessage()`）は変えない。方式設計 §5.2 で元レコードを残すファイルであり、ログではないため。既存のテスト（`加工時Skipのレコードをフォーマットして退避する`・`読取時Skipは元の行を退避する`・`書込時Skipも退避され複数件は追記される` など）は変えずに通す
- `BusinessException` のメッセージを出す理由：Skip の中で送出される batch-core の部品（`ValidatingItemProcessorBase`・`ByteLengthLineTokenizer`・`ByteLengthLineAggregator`・`StrictCharsetEncoder`）はメッセージに値を含めない（PR #95）。batch-sample の `OrderItemProcessor` が含める受注番号・明細番号・受注日は業務キーと日付で個人情報・機密情報ではないので、`OrderItemProcessor` は変えない
- 追加する単体テストのメソッド名は次の4つにする（受け入れ基準が surefire のレポートで3つを探す）。ログの検証は既存のテストと同じく `ListAppender` を `ErrorRecordSkipListener` のロガーに付けて行い、テストの後で外す
  - `加工時Skipで原因がBusinessExceptionの場合＿WARNログにメッセージを出しレコードの内容を出さない`：入力のフォーマッタが `秘密` を含む文字列を返すようにし、`onSkipInProcess(item, new BusinessException("入力チェックエラー: email 形式が不正です"))` の WARN の `getFormattedMessage()` が `cause=入力チェックエラー: email 形式が不正です` を含み、`秘密` を含まない
  - `加工時Skipで原因がBusinessExceptionでない場合＿原因のクラス名だけを出す`：`onSkipInProcess(item, new IllegalStateException("値=秘密"))` の WARN が `cause=IllegalStateException` を含み、`秘密` を含まない
  - `書込時Skipで原因がBusinessExceptionでない場合＿原因のクラス名だけを出す`：`onSkipInWrite(item, new IllegalArgumentException("Key (code)=(秘密) already exists"))` の WARN が `cause=IllegalArgumentException` を含み、`秘密` を含まない
  - `読取時SkipでFlatFileParseException以外の場合＿原因のクラス名だけを出す`：`onSkipInRead(new IllegalStateException("値=秘密"))` の WARN が `cause=IllegalStateException` を含み、`秘密` を含まない
- テストの例外に Spring の `DataIntegrityViolationException` などは使わない（依存の確認を要らなくするため。JDK の例外で足りる）
- `ErrorRecordSkipListener` のクラスの Javadoc の「読込時の Skip の WARN ログには行の内容を出さず行番号と原因だけを出す」の文を、「WARN ログにはレコードの内容を出さず、原因（`BusinessException` ならメッセージ、それ以外は例外のクラス名）だけを出す。読込時のパースエラーなら行番号も出す（レコードの内容はエラーレコードファイルにだけ残る）」の趣旨の文に書き換える（Javadoc では `{@code ...}` を使う）
- `BusinessException` のクラスの Javadoc の「用途」の段落の後に、次の段落を足す：「<p>メッセージは Skip 時に {@code ErrorRecordSkipListener} の WARN ログへそのまま出るため、個人情報・機密情報（入力レコードの値など）を含めない（docs/architecture.md §8）。</p>」（受け入れ基準が `WARN ログへそのまま出るため` を探す）。コードは変えない
- `batch-sample/docs/sample01-csv-import.md` の「実装ポイント」節の末尾に、次の箇条を1行足す：「- 加工時・書込時の Skip と、`FlatFileParseException` 以外の読込時の Skip の WARN ログには、原因が `BusinessException` ならそのメッセージ、それ以外なら例外のクラス名だけを出す（`ErrorRecordSkipListener`）。元レコードはエラーレコードファイルにだけ残る」
- `batch-sample/docs/sample02-fixedlength-import.md`（読込時のパースエラーの記述）と `docs/projects/` 配下の設計書は、WARN ログの `reason` の中身に触れていないので変えない
