# T-04 計画の差分が `/code-review` を通過する

## 目的
T-01〜T-03 で変えた計画全体の差分を組み込みの `/code-review` で確かめ、致命的な指摘を残さない（計画単位のレビュータスク）。

## 入力
- 計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）
- `.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節
- `vault/rules/verifier/code-review.md`
- T-01〜T-03 のタスク票（`vault/tasks/P-20261023-filemove-and-skiplog/`）の「決定済み」

## 成果物
- 主な成果物：計画の差分への修正（致命的な指摘が無ければ変更なし）
- 直してよいファイル（先行タスクの「成果物」に宣言したパス）：
  - `batch-core/src/main/java/com/example/batch/core/tasklet/TempOutputFile.java`

  - `batch-sample/src/main/java/com/example/batch/sample/job03_file_export/Sample03JobConfig.java`
  - `batch-sample/src/test/java/com/example/batch/sample/job03_file_export/Sample03JobConfigTest.java`
  - `batch-sample/docs/sample03-file-export.md`

## 決定済み
- レビューの範囲は、ベースブランチ（`HARNESS_BASE_BRANCH`、前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）とする
- 計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない
- 致命的な指摘が無ければ成果物を変えず、「進捗」への記録だけでよい（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）
- 差分の外（既存コード）への指摘・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは、`.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節に従う
- 直す時も、各先行タスクの「決定済み」（`TempOutputFile` の API と例外の種類、sample03 の一時ファイルの場所と `tmp` を拒否する検証を変えないこと、`FileMoveTasklet` を変えないこと、WARN ログの書式と `reason` の規則、エラーレコードファイルの中身を変えないこと、`OrderItemProcessor` を変えないことなど）を変えない。変えないと直せない指摘は設計や仕様の変更が要る指摘として扱う
- ビルドは 3行目の `-pl batch-core` を2行目の後に実行するので、4行目・5行目は batch-core の、6行目は batch-sample の surefire のレポートを見る（`-pl batch-core` の `clean` は batch-sample の `target/` を消さない）
- 結合テスト（`./mvnw clean verify`）は、この環境では Docker のデーモンが動いていないので受け入れ基準に入れない。PR の CI で確かめる

## 進捗
- 読んだルール: vault/rules/creator/code-review.md, vault/rules/creator/skill-workflow.md, vault/rules/common/project-docs.md
- ベースブランチ: HARNESS_BASE_BRANCH が空なので main。範囲は `git diff --merge-base main`（計画一式4種は除く）
- /code-review 1回目: 指摘7件。Must 1件（TempOutputFile.inSubdirectory で dirName が "." の時、normalize されず重なり検査をすり抜ける）を修正（`parent.resolve(dirName).normalize()`、テスト `一時ディレクトリ名がカレントを指す場合＿SystemExceptionを送出する` を TempOutputFileTest に追加）。Should 5件（symlink/別FS検査なし、validateOutputFileName の二重検証、エラーファイルの改行、prepare が残骸を消さない、テストの Path.of("/") 依存）は直さない。Ask 相当: WARN ログへ BusinessException メッセージを出す点（決定済みの書式のため変えない）
- /code-review 2回目（確認）: Must 0件。Should/Ask 相当のみ（".." などの dirName 検証は API の仕様追加が要るため直さない、tempDir が祖先になる場合、normalize の symlink 差、二重検証、メッセージ無し BusinessException の reason、Javadoc 例の ".tmp"、並行実行）。クラッシュ・データ破損・誤った結果に当たる新規指摘なし
- 対象外（既存コード）: エラーレコードファイルへ書く t.getMessage() に改行が入りうる点（既存の書き方）
- 受け入れ基準7行を実行し、2行目・3行目のビルドは BUILD SUCCESS が1、4〜7行目の grep / smoke はすべて1
