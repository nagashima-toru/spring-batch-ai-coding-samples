# T-02 sample03 の一時ファイルのパスの決定と一時ディレクトリの作成を TempOutputFile に置き換える（#72）

## 決定済み
- sample03 の一時ファイルの場所（`<outputFile の親ディレクトリ>/tmp/<outputFile のファイル名>`）・ファイル名 `tmp` を起動時に拒否する検証（`validateOutputFileName` と定数 `TEMP_DIR_NAME`）・Step の構成・`FileMoveTasklet` の `overwrite=true` は変えない（理由は計画票の「分割方針」）。`Sample03FileExportJobIT` は変えない
- `Sample03JobConfig` の変更
  - `tempFileOf`・`outputDirOf`・`requirePath` を削除し、代わりにパッケージプライベートの `static TempOutputFile tempOutputOf(String outputFile)` を1つ置く。本体は `return TempOutputFile.inSubdirectory(Path.of(outputFile), TEMP_DIR_NAME);` の1文（受け入れ基準がこの呼び出しを探す。ほかの場所では `inSubdirectory` を呼ばない）。Javadoc に「配置先の親ディレクトリ配下の tmp/ に同名で置く」ことを書く
  - `sample03FileMoveTasklet` は `tempOutputOf(outputFile)` の戻り値の `tempFile()` と `outputDir()` で `new FileMoveTasklet(..., ..., true)` を作る
  - `sample03SalesWriter` は `Path tempFile = tempOutputOf(outputFile).prepare();` にし、`Files.createDirectories` と `try`/`catch` を削除する
  - 使わなくなった import（`java.io.IOException`・`java.nio.file.Files`・使わなければ `SystemException`）を削除する
  - クラスの Javadoc の「一時出力→配置」の段落に、一時ファイルのパスの決定と一時ディレクトリの作成は `{@link TempOutputFile}` で行うことを足す
- `Sample03JobConfigTest` の `配置先ファイルを指定した場合＿親ディレクトリ配下のtmpに同名の一時ファイルパスを返す` は、メソッド名と期待値（`dir.toAbsolutePath().resolve("tmp").resolve("sales.csv")`）を変えず、呼び出しだけを `Sample03JobConfig.tempOutputOf(...).tempFile()` に変える。ほかのテストは変えない
- `batch-sample/docs/sample03-file-export.md` の変更
  - 「デモする機能」の `FileMoveTasklet` の箇条の括弧の中の末尾に「。一時ファイルのパスは `TempOutputFile`」を足す
  - 「一時出力→配置」節の「一時ファイルの場所は」で始まる箇条に、「パスの決定と一時ディレクトリの作成は基盤部品の `TempOutputFile`（`inSubdirectory`）で行う」を1文足す
  - 同じ節の末尾に次の箇条を1行足す：「- 配置先のディレクトリを再帰的に監視する仕組みがある場合は、`tmp/` の書きかけのファイルを拾わないよう、`TempOutputFile.inDirectory` で一時ディレクトリを配置先の外に置く。一時ディレクトリは配置先と同じファイルシステムにする（別のファイルシステムだと移動がコピーになり、配置先に書きかけのファイルが見える）」
- `batch-sample/docs/README.md` の部品の実例表の `FileMoveTasklet` の行の直後に、次の行を足す：「| `TempOutputFile` | `job03_file_export` / `Sample03JobConfig`（一時ファイルのパスと一時ディレクトリの作成） |」
- `.claude/skills/implementation/SKILL.md` の「最重要ルール: 基盤部品を使わず独自実装してはならない」節の表の「ファイル存在チェック / 移動退避」の行の直後に、次の行を足す：「| 一時出力→配置（一時ファイルのパス・一時ディレクトリの作成） | `TempOutputFile`（配置は `FileMoveTasklet`） |」。ほかの行は変えない
- `.claude/skills/implementation/SKILL.md` は smoke の `(ref-1)` の対象。足す行のバッククォートはクラス名だけで、`vault/`・`scripts/`・`docs/`・`.claude/` で始まるパスを書かない
- 結合テスト（`./mvnw clean verify`）は、この環境では Docker のデーモンが動いていないので受け入れ基準に入れない。PR の CI で確かめる
- `Files` API を直接使うほかのジョブ（`OrderDetailWorkClearTasklet` のエラーファイルの削除など）は一時出力→配置ではないので、この計画の範囲外として変えない
