# T-02 サンプルカタログの案件ジョブ節を別表に拡充する

## 目的
サンプルカタログの「案件ジョブについて」節を、案件ジョブ3本の別表（設計書・近いリファレンスサンプル・違い）に拡充し、案件ジョブを SDD パイプラインの出力例として位置付ける（Issue #62 の後半）。

## 入力
- `batch-sample/docs/README.md`（T-01 で「## 基盤部品別の実例ジョブ索引」節が入った版）
- `docs/projects/order-daily-sales/detail-design/ORDER-001.md`・`docs/projects/member-point-expiry/detail-design/POINT-001.md`・`docs/projects/announcement-notification/detail-design/ANNOUNCE-001.md`（各案件の詳細設計書）
- `batch-sample/src/main/java/com/example/batch/sample/` の `job_order_daily_sales`・`job_point_expiry`・`job_announcement_notify` パッケージ
- 近いリファレンスサンプルの解説：`batch-sample/docs/sample01-csv-import.md`・`batch-sample/docs/sample03-file-export.md`・`batch-sample/docs/sample04-db-aggregate.md`・`batch-sample/docs/sample06-flow-job.md`

## 成果物
- `batch-sample/docs/README.md`（1ファイル。「## 案件ジョブについて」節の改訂）

## 受け入れ基準
- 「カタログには含めない」の記述がリポジトリの文書に残っていない：`grep -rlF 'カタログには含めない' batch-sample docs .claude README.md CLAUDE.md` の出力が空
- 案件ジョブをリファレンスサンプルとは別表で載せる旨がある：`grep -c 'リファレンスサンプルとは別表で載せる' batch-sample/docs/README.md` の出力が `1`
- 案件ジョブを SDD パイプラインの出力例として位置付けている：`grep -c 'SDD パイプライン（requirements→system-test）の出力例' batch-sample/docs/README.md` の出力が `1`
- 案件ジョブ3本の表があり、各行が4列で、設計書と近いリファレンスサンプルへのリンクが実在するファイルを指し、違いの要点のクラス名を含む：`python3 -c 'import re,os;D="batch-sample/docs/";s=open(D+"README.md",encoding="utf-8").read().split("\n## 案件ジョブについて\n")[1].split("\n## ")[0];K={"job_order_daily_sales":"OrderDailySalesJobParametersValidator","job_point_expiry":"TableCountCheckTasklet","job_announcement_notify":"RegionErrorWarningJobExecutionListener"};print(sorted((j,sorted(os.path.basename(x) for x in re.findall(r"\]\(([^)#]+)",r) if os.path.isfile(D+x)),len([x for x in re.findall(r"\]\(([^)#]+)",r) if not os.path.isfile(D+x)]),r.count(chr(124)),K.get(j,chr(0)) in r) for j,r in re.findall(r"(?m)^\x7c \x60(job_\w+)\x60([^\n]*)",s)))'` の出力が `[('job_announcement_notify', ['ANNOUNCE-001.md', 'sample01-csv-import.md', 'sample03-file-export.md'], 0, 4, True), ('job_order_daily_sales', ['ORDER-001.md', 'sample06-flow-job.md'], 0, 4, True), ('job_point_expiry', ['POINT-001.md', 'sample04-db-aggregate.md'], 0, 4, True)]`
- 命名の architecture §11 への参照が残っている：`grep -c 'architecture.md#11-命名規約' batch-sample/docs/README.md` の出力が `1`
- 節の並びが変わっていない：`grep '^## ' batch-sample/docs/README.md` の出力が順に `## コアサンプル（フル実装・テスト付き）`・`## 拡張サンプル（骨格＋解説）`・`## 基盤部品別の実例ジョブ索引`・`## 案件ジョブについて` の4行

## 決定済み
- 見出し `## 案件ジョブについて` はそのまま残し、節の中身だけを書き換える。T-01 の索引節・コアサンプル・拡張サンプルの節は変えない
- 節の冒頭の説明に、次の2つの文言をそれぞれ1回だけ、この文字列のまま含める（例：「案件ジョブは SDD パイプライン（requirements→system-test）の出力例として位置付け、リファレンスサンプルとは別表で載せる。」）
  - `SDD パイプライン（requirements→system-test）の出力例`（「SDD」と「パイプライン」の間は半角空白1つ、括弧は全角、矢印は「→」）
  - `リファレンスサンプルとは別表で載せる`
- 「案件ジョブはサンプルのカタログには含めない。」の文は削除する（「カタログには含めない」という語句をどこにも残さない）
- 命名の文（パッケージ名・ジョブ名・Step 名・設定クラス名の命名は architecture §11 に従う／`jobNN_` はリファレンスサンプルだけの例外）と、そのリンク `[docs/architecture.md §11](../../docs/architecture.md#11-命名規約)` はそのまま残す。設計書は `docs/projects/{案件名}/` 配下・development-guide §2 参照の文も残す
- SDD パイプラインの説明には `/sdd-pipeline` または development-guide へのリンクを付けてよいが、必須ではない
- 表は4列。ヘッダ行は `| ジョブ | 設計書 | 近いリファレンスサンプル | 違い |`、区切り行は `|---|---|---|---|`。行頭は「| 」＋バッククォートで囲んだパッケージ名（例：`` | `job_order_daily_sales`（ORDER-001） | ``）。セルの中に「|」を書かない
- 行と内容は次の3行（この順）。リンクは README からの相対パスで書く
  - `job_order_daily_sales`（ORDER-001）／設計書 `[ORDER-001.md](../../docs/projects/order-daily-sales/detail-design/ORDER-001.md)`／近いサンプル `[sample06](sample06-flow-job.md)`（ファイルチェック→取込→集計）／違い：ヘッダチェック（`CsvHeaderCheckTasklet`）とワークテーブル経由の取込を加え、集計を対象日分の洗い替え（`OrderDailySalesReplaceTasklet`）にする。パラメータ検証を `OrderDailySalesJobParametersValidator` で拡張する
  - `job_point_expiry`（POINT-001）／設計書 `[POINT-001.md](../../docs/projects/member-point-expiry/detail-design/POINT-001.md)`／近いサンプル `[sample04](sample04-db-aggregate.md)`（Tasklet＋SQL）／違い：単一 Step・単一 SQL で失効更新と履歴登録を1トランザクションで行う。失効対象0件が正常のため `TableCountCheckTasklet` を使わない
  - `job_announcement_notify`（ANNOUNCE-001）／設計書 `[ANNOUNCE-001.md](../../docs/projects/announcement-notification/detail-design/ANNOUNCE-001.md)`／近いサンプル `[sample03](sample03-file-export.md)`（カーソル読み）と `[sample01](sample01-csv-import.md)`（Skip・エラー退避）を「・」で併記／違い：ステータス更新の Tasklet で対象を確定してから Chunk で DB → DB 登録する4 Step の線形フロー。区域展開不能の件数で警告終了にする `RegionErrorWarningJobExecutionListener` を持つ
- 違いの列の文言は上の要点を保てば言い回しを整えてよいが、各行の上のクラス名（`OrderDailySalesJobParametersValidator`・`TableCountCheckTasklet`・`RegionErrorWarningJobExecutionListener`）は必ず書く
- 「カタログには含めない」が残っていないかの確認範囲は `batch-sample`・`docs`・`.claude`・ルートの `README.md`・`CLAUDE.md`。`vault/` は除外する（計画票・タスク票がこの旧文言を引用して記録するため）
- コード・architecture.md・ルートの README.md・implementation Skill は変えない。#61 は範囲外
- 受け入れ基準の `python3 -c` はリポジトリのルート（worktree のルート）で実行する前提。外部コマンドは呼ばない
