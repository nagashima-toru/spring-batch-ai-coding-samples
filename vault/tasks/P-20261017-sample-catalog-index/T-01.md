# T-01 サンプルカタログに基盤部品別の実例ジョブ索引を追加する

## 目的
implementation Skill の「最重要ルール」表の基盤部品ごとに、batch-sample のどのジョブ（パッケージ / クラス）が実例かを引ける索引を、サンプルカタログに追加する（Issue #62 の前半）。

## 入力
- `batch-sample/docs/README.md`（追加先。現状はリファレンスサンプル9本のカタログと「案件ジョブについて」節）
- `.claude/skills/implementation/SKILL.md` の「最重要ルール: 基盤部品を使わず独自実装してはならない」表（索引の行の正本。このタスクでは変えない）
- `batch-core/src/main/java/com/example/batch/core/` 配下（部品のクラス）
- `batch-sample/src/main/java/com/example/batch/sample/` 配下（実例のクラス）

## 成果物
- `batch-sample/docs/README.md`（1ファイル。新しい節の追加のみ）

## 受け入れ基準

## 決定済み
- 見出しは `## 基盤部品別の実例ジョブ索引`（この文字列そのまま。中黒「・」は GitHub のアンカーで消えるので使わない）。置き場所は「## 拡張サンプル（骨格＋解説）」の表の後、「## 案件ジョブについて」の前。見出しの直後に1〜2文の説明（implementation Skill の最重要ルール表の部品ごとに実例を引く索引であること）を書いてよい
- 表は2列。ヘッダ行は `| 部品 | 実例（ジョブのパッケージ / クラス） |`、区切り行は `|---|---|`
- 各データ行の形式は `` | `部品クラス名` | 実例セル | ``（行頭は「| 」＋バッククォートで囲んだ部品名＋「 | 」）。実例セルの各実例は `` `パッケージ名` / `クラス名` ``（パッケージ名は `job` で始まる batch-sample のパッケージの末尾、クラス名は拡張子なし。間は半角空白・スラッシュ・半角空白）とし、複数は「、」で区切る。実例セルの末尾に「（独自 Validator への拡張例）」のような短い補足を付けてよい
- 実例の無い部品の実例セルは `実例なし（#61 で追加予定）` とだけ書く（全角括弧・半角の `#61`・半角空白1つ）。この文言を索引の表以外（説明文など）に書かない（ファイル全体で5回の基準があるため）
- 行の順序は最重要ルール表の部品の出現順。最重要ルール表に無い `CsvHeaderCheckTasklet` も、実例があるので `FileMoveTasklet` の行の直後に1行加える（計23行）
- 各行の実例は次のとおり書く（grep で使用箇所を確認済み。リファレンスサンプル優先・最大3件、案件ジョブが使っていれば1件併記）
