# T-02 planner ルール：ジョブ1本を工程タスクに分けて after でつなぐ

## 目的
planner が、詳細設計がレビュー済みのジョブ1本を受け取った時に、implementation〜system-test の工程タスクに分けて `after` で順につなぎ、受け入れ基準にビルドの成功を入れられるようにする。

## 入力

- `vault/templates/rule.md`、`vault/rules/README.md`
- `docs/development-guide.md` §2.1・§2.2（工程と各工程の入出力）
- `.claude/skills/implementation/SKILL.md`・`.claude/skills/unit-test/SKILL.md`・`.claude/skills/integration-test/SKILL.md`・`.claude/skills/review-code/SKILL.md`・`.claude/skills/system-test/SKILL.md`（各工程の出力先）
- `.claude/agents/planner.md`（粒度の基準。1計画7タスク以下）

## 成果物
- `vault/rules/planner/job-task-split.md`（1ファイル、新規作成）

## 決定済み
- 見出しは `vault/templates/rule.md` の3つ（`## 目的`・`## ルール`・`## 確認方法`）をこの順で使う。ファイル先頭に `# ` のタイトル行を1行置いてよい
- 次の文言をそのまま「## ルール」節に書くこと：
  - `implementation → unit-test → integration-test → review-code → system-test`（ジョブ1本をこの順の5タスクに分ける）
  - `` `after` に直前の工程のタスク ID を書く ``（直列につなぐ。並行させない）
  - `詳細設計書がレビュー済み`（`/review-design` を通った `docs/projects/{案件}/detail-design/{ジョブID}.md` であることを計画の前提にする。ゴール文や設計書からレビュー済みと確かめられない時は、タスクを起こさず計画票末尾の `## 人への質問` に書く）
  - `` `./mvnw verify -DskipITs` ``（全タスクの受け入れ基準に成功を入れる）
  - `` 成果物に `*IT.java` を含むタスクだけ `./mvnw verify` の成功も入れる ``（同じ行に `*IT.java` と `./mvnw verify` をこの順で書く）
- 1計画で扱うジョブは1本にする（5タスクで、1計画7タスク以下の上限に収まるため）。複数ジョブは計画を分ける
- 各タスクの「成果物」のパスは、対応する工程の SKILL.md の「入力と出力」節と `docs/architecture.md` §2.1（パッケージ構成）に従って宣言する、と書く。具体的なパスの一覧はルールに書き写さない
- 要件定義〜設計レビュー（`requirements`・`basic-design`・`detail-design`・`review-design`）はハーネスのタスクにしない、と1行書く（設計文書の決定事項）
- 設計書と異なる実装が必要になりそうな点はタスクにせず `## 人への質問` に書く（`docs/development-guide.md` §5.5）、と1行書いてよい
- docs の本文は書き写さない。パスと節番号で参照する
- `vault/rules/planner/.gitkeep` は消さない
- `docs/`・`CLAUDE.md`・`.claude/skills/`・`.claude/agents/` は変更しない
