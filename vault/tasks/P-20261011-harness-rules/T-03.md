# T-03 creator ルール：工程 Skill に従い確認手順を読み替える

## 目的
creator が工程タスク（implementation〜system-test）を、既存の工程 Skill の手順に沿って進め、ユーザー確認の手順に当たった時は `sdd-pipeline` の読み替え表に従い、独断できない判断は blocked で返せるようにする。

## 入力
- `vault/designs/D-20261011-spring-batch-adapt.md`（冒頭の「決定事項」とフェーズ1節）
- `vault/templates/rule.md`、`vault/rules/README.md`
- `.claude/skills/sdd-pipeline/SKILL.md`（「レビュー指摘の扱い」「委譲先Skillの記述を上書きする点」「停止して確認するタイミング」）
- `.claude/skills/implementation/SKILL.md`・`.claude/skills/unit-test/SKILL.md`・`.claude/skills/integration-test/SKILL.md`・`.claude/skills/review-code/SKILL.md`・`.claude/skills/system-test/SKILL.md`
- `docs/development-guide.md` §5（検証ループ。§5.3・§5.4・§5.5）
- `.claude/agents/creator.md`（blocked の返し方）

## 成果物
- `vault/rules/creator/skill-workflow.md`（1ファイル、新規作成）

## 受け入れ基準
- `bash scripts/rules.sh creator | grep -cx 'vault/rules/creator/skill-workflow.md'` の出力が `1` である
- `grep -cE '^## (目的|ルール|確認方法)$' vault/rules/creator/skill-workflow.md` の出力が `3` である
- ``grep -cF '`.claude/skills/<工程>/SKILL.md`' vault/rules/creator/skill-workflow.md`` の出力が1以上である（各タスクで対応する工程 Skill に従うことが書かれている）
- `grep -cF '委譲先Skillの記述を上書きする点' vault/rules/creator/skill-workflow.md` と ``grep -cE '`\[Ask\]`.*blocked' vault/rules/creator/skill-workflow.md`` の出力がともに1以上である（ユーザー確認は読み替え表に従い、`[Ask]` は blocked にすることが書かれている）
- ``grep -cF '`docs/development-guide.md` §5.4' vault/rules/creator/skill-workflow.md`` と ``grep -cF '`docs/development-guide.md` §5.3' vault/rules/creator/skill-workflow.md`` の出力がともに1以上である（§5.4 の反則の禁止と、§5.3 のモデル昇格を使わないことが書かれている）
- `wc -l vault/rules/creator/skill-workflow.md` の行数が100以下で、``grep -c '^```' vault/rules/creator/skill-workflow.md`` の出力が `0` である
- § で示した節番号が参照先の docs に見出しとして実在し、読み替え表や docs の本文を書き写していない（verifier が `grep -n '^#' <docs>` と Read で確認する）

## 決定済み
- 見出しは `vault/templates/rule.md` の3つ（`## 目的`・`## ルール`・`## 確認方法`）をこの順で使う。ファイル先頭に `# ` のタイトル行を1行置いてよい
- 次の文言を「## ルール」節に書くこと：
  - `` `.claude/skills/<工程>/SKILL.md` ``（タスクの title・目的に書かれた工程の SKILL.md の「進め方」に従う。工程は implementation・unit-test・integration-test・review-code・system-test）
  - `委譲先Skillの記述を上書きする点`（SKILL.md の「ユーザーに確認・合意する」手順に当たったら、`.claude/skills/sdd-pipeline/SKILL.md` のこの表の「パイプライン実行時の扱い」に読み替える。表の中身は書き写さない）
  - `` `[Ask]` `` と `blocked` を同じ行に（`[Ask]` に当たる指摘や、読み替え表に無い確認が要る時は独断せず、完了報告を `blocked: <質問文>` にして返す）
  - `` `docs/development-guide.md` §5.4 ``（反則の禁止。検証を弱めて通さない）
  - `` `docs/development-guide.md` §5.3 ``（モデル昇格は使わない。同じエラーが2ラウンド続いて解消しない時は、昇格の代わりに §5.3 の1〜3を質問文に含めて `blocked:` で返す。再試行は attempt で run が行う）
- 読み替え表で「主エージェントに提示・報告」とある成果（unit-test のテストケース表、system-test のシナリオ一覧）は、タスク票の「進捗」に書く（creator の完了報告には経緯を書かないため）
- review-code のタスクは、`/review-code` の手順でレビューし、[Must]/[Should] を自分で修正したうえで `./mvnw verify -DskipITs` を通す。[Ask] が残ったら blocked にする、と書く
- system-test のタスクで、外部依存などでローカル実施できないシナリオがある時は blocked にする、と書く
- integration-test のタスクで `docker info` が失敗する（Docker が使えない）時は blocked にする、と書く
- 設計書と異なる実装が必要と分かった時は、設計書を自分で直さず blocked にする（`docs/development-guide.md` §5.5）、と書く
- 基盤部品（batch-core）で実現できる処理を独自実装しない（`.claude/skills/implementation/SKILL.md` の対応表）、と1行書いてよい
- 「## 確認方法」節には、完了報告の前に受け入れ基準のビルドコマンド（`./mvnw verify -DskipITs` など）を自分で実行して通す、と書く
- docs・SKILL.md の本文は書き写さない。パス・節番号・見出し名で参照する
- `vault/rules/creator/.gitkeep` は消さない
- `docs/`・`CLAUDE.md`・`.claude/skills/`・`.claude/agents/` は変更しない
