# T-01 共通ルール：正本の docs を役割ごとに案内する

## 目的
planner・creator・verifier の全員が、どの正本 docs のどの節を読めばよいかを1か所で分かるようにする。docs の本文は書き写さず、パスと節番号で案内する。

## 入力
- `vault/designs/D-20261011-spring-batch-adapt.md`（冒頭の「決定事項」とフェーズ1節）
- `vault/templates/rule.md`（見出しの雛形）、`vault/rules/README.md`（振り分けと書き方）
- `docs/architecture.md`、`docs/coding-standards.md`、`docs/development-guide.md`、`CLAUDE.md` の「禁止事項」「ハマりどころ」（見出しと節番号を確かめるため）

## 成果物
- `vault/rules/common/project-docs.md`（1ファイル、新規作成）

## 受け入れ基準
- `bash scripts/rules.sh creator | grep -cx 'vault/rules/common/project-docs.md'` の出力が `1` である（common のルールとして全役割に渡る）
- `grep -cE '^## (目的|ルール|確認方法)$' vault/rules/common/project-docs.md` の出力が `3` である（`vault/templates/rule.md` の見出しで書かれている）
- ``grep -cE '^- `(docs/architecture\.md|docs/coding-standards\.md|docs/development-guide\.md|CLAUDE\.md)` .*読む役割: ' vault/rules/common/project-docs.md`` の出力が `4` である（正本4つを1行ずつ、読む役割つきで案内している）
- `wc -l vault/rules/common/project-docs.md` の行数が100以下で、``grep -c '^```' vault/rules/common/project-docs.md`` の出力が `0` である（docs の本文をコードブロックで書き写していない）
- ファイル中の `§` で示した節番号が、参照先の docs に見出しとして実在する（verifier が `grep -n '^#' docs/architecture.md` などで照合する）。`CLAUDE.md` は節番号の代わりに見出し名（「禁止事項」など）で参照している
- ファイルの本文が docs の文章を書き写しておらず、各参照の説明が1行の要点（何のために読むか）に留まっている（verifier が Read で確認する）

## 決定済み
- 見出しは `vault/templates/rule.md` の3つ（`## 目的`・`## ルール`・`## 確認方法`）をこの順で使う。ファイル先頭に `# ` のタイトル行を1行置いてよい
- 「## ルール」節に、正本4つを1行ずつ、次の形で書く（この4行ちょうど。同じパスで始まる行を他に作らない）：
  `` - `<パス>` <節番号や見出し>：<何のために読むか> — 読む役割: <役割> ``
- 各行の中身（節番号は現在の見出しで確認済み）：
  - `docs/architecture.md`：方式設計書（SSoT）。特に §3 ジョブ設計方針・§5 エラー処理方針・§6 リラン設計・§7 終了コード規約・§9 データベース方針・§12 テスト方針・§13 Spring Batch 6 実装上の注意。読む役割: planner・creator・verifier
  - `docs/coding-standards.md`：コーディング規約。特に §4.2 部品の利用・§7 テストコード規約・§9 禁止事項まとめ。読む役割: creator・verifier
  - `docs/development-guide.md`：工程と検証ループ。§2.1 工程フロー・§2.2 各工程の入出力（planner・creator）、§5 検証ループ（creator・verifier）。読む役割: planner・creator・verifier
  - `CLAUDE.md`：「禁止事項」と「ハマりどころ（Boot 4 / Batch 6 固有）」。読む役割: planner・creator・verifier
- 4行のほかに、「## ルール」節へ次の趣旨を1行ずつ書いてよい：docs と食い違ったら docs が正（このルールは案内だけ）／docs の本文はここに写さない
- 「## 確認方法」節には、参照した節番号が `grep -n '^#' <docs>` で実在することを確かめる、と書く
- `vault/rules/common/.gitkeep` は消さない（`scripts/rules.sh` は `*.md` だけを列挙するので影響しない）
- 他の役割のルール（planner・creator・verifier）は別タスクで作る。このファイルから他のルールファイルを参照しない
- `docs/`・`CLAUDE.md`・`.claude/skills/` は変更しない

## 進捗
- 読んだルール: なし（着手時の rules.sh creator は出力なし）
- vault/rules/common/project-docs.md を作成。節番号は各 docs の見出しと照合済み
- 基準1〜4の確認コマンドは通過（1 / 3 / 4 / 16行・コードブロック0）。基準5・6は節番号照合済み・1行要点のみ
