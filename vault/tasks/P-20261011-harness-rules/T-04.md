# T-04 verifier ルール：ビルドを実行して判定する

## 目的
verifier が工程タスクを、creator の申告ではなく自分で実行したビルドの結果と docs を根拠に判定できるようにする。

## 入力
- `vault/designs/D-20261011-spring-batch-adapt.md`（冒頭の「決定事項」とフェーズ1節）
- `vault/templates/rule.md`、`vault/rules/README.md`
- `docs/development-guide.md` §5.1（レポートの場所）・§5.4（反則の禁止）
- `docs/architecture.md` §12（テスト方針）
- `.claude/agents/verifier.md`（判定と verdict の書き方）

## 成果物
- `vault/rules/verifier/build-verification.md`（1ファイル、新規作成）

## 受け入れ基準
- `bash scripts/rules.sh verifier | grep -cx 'vault/rules/verifier/build-verification.md'` の出力が `1` である
- `grep -cE '^## (目的|ルール|確認方法)$' vault/rules/verifier/build-verification.md` の出力が `3` である
- ``grep -c '^- `./mvnw verify -DskipITs` を必ず実行' vault/rules/verifier/build-verification.md`` の出力が1以上である（`./mvnw verify -DskipITs` を必ず実行することが書かれている）
- ``grep -cE '`\*IT\.java`.*`\./mvnw verify`' vault/rules/verifier/build-verification.md`` の出力が1以上である（結合テストを成果物に含むタスクでは `./mvnw verify` も実行することが書かれている）
- `wc -l vault/rules/verifier/build-verification.md` の行数が100以下で、``grep -c '^```' vault/rules/verifier/build-verification.md`` の出力が `0` である
- § で示した節番号が参照先の docs に見出しとして実在し、docs の本文を書き写していない（verifier が `grep -n '^#' <docs>` と Read で確認する）

## 決定済み
- 見出しは `vault/templates/rule.md` の3つ（`## 目的`・`## ルール`・`## 確認方法`）をこの順で使う。ファイル先頭に `# ` のタイトル行を1行置いてよい
- 「## ルール」節に次の行を書くこと：
  - 行頭が `` - `./mvnw verify -DskipITs` を必ず実行 `` で始まる行（工程タスクの判定では毎回自分で実行し、終了コードと末尾の `BUILD SUCCESS`／`BUILD FAILURE` を note に書く。creator の進捗や報告を根拠にしない）
  - `` 成果物に `*IT.java` を含むタスクでは `./mvnw verify` も実行する ``（同じ行に `*IT.java` と `./mvnw verify` をこの順で書く）
- Docker が使えず（`docker info` が失敗）`./mvnw verify` を実行できない時は PASS にせず FAIL とし、reasons に「Docker が使えず結合テストを実行できない」と書く、と書く（検証できないものを PASS にしないため。attempt の上限で blocked になり人に渡る）
- 失敗の原因は `docs/development-guide.md` §5.1 の表にあるレポートの場所を読んで note に要点を書く、と書く（表は書き写さない）
- 差分に `docs/development-guide.md` §5.4 の反則（カバレッジ閾値の変更・除外設定の追加・テストの削除や `@Disabled` 化・適用済み Flyway ファイルの書き換え）が見つかったら、受け入れ基準がこのルールや §5.4 を参照している時は FAIL の根拠にし、参照していない時は reasons に記録する、と書く（`.claude/agents/verifier.md` の「ルールは基準の判定方法を与える」に合わせる）
- 「## 確認方法」節には、verdict の note に実行したコマンドと `BUILD SUCCESS` の有無が書かれていること、と書く
- docs の本文は書き写さない。パスと節番号で参照する
- `vault/rules/verifier/.gitkeep` は消さない
- `docs/`・`CLAUDE.md`・`.claude/skills/`・`.claude/agents/` は変更しない
