# T-05 settings.json の permissions.allow にビルドと Docker の許可を足す

## 目的
無人実行（`claude -p`）で creator・verifier の `./mvnw` と Docker の起動・確認が権限で拒否されないようにする。

## 入力
- `vault/designs/D-20261011-spring-batch-adapt.md`（冒頭の「決定事項」の `permissions.allow` の行）
- `.claude/settings.json`

## 成果物
- `.claude/settings.json`（1ファイル。`permissions.allow` に3項目を足すだけ）

## 受け入れ基準
- `python3 -c "import json;json.load(open('.claude/settings.json'))"` が終了コード0で終わる（JSON として読める）
- `python3 -c "import json;a=json.load(open('.claude/settings.json'))['permissions']['allow'];print(all(x in a for x in ['Bash(./mvnw *)','Bash(docker compose *)','Bash(docker info*)']))"` の出力が `True` である
- `python3 -c "import json,subprocess;o=json.loads(subprocess.check_output(['git','show','work/p-20261011-harness-rules:.claude/settings.json']));n=json.load(open('.claude/settings.json'));print(set(o['permissions']['allow'])<=set(n['permissions']['allow']) and o['permissions']['deny']==n['permissions']['deny'] and o['hooks']==n['hooks'] and o['worktree']==n['worktree'])"` の出力が `True` である（既存の allow を消さず、deny・hooks・worktree を変えていない）
- `bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` で終わる

## 決定済み
- 足す文字列は `Bash(./mvnw *)`・`Bash(docker compose *)`・`Bash(docker info*)` の3つちょうど。表記を変えない（`docker info*` は `docker info` を引数なしで呼ぶ形も含めるため `*` の前に空白を入れない）
- 既存の allow の項目は消さず、順序も変えない。3項目は allow 配列の末尾（`"Bash(env *)"` の後）に足す
- `deny`・`hooks`・`worktree`（`baseRef: head`）は変えない。インデントは既存と同じ2スペース
- このタスクは `.claude/settings.json` だけを変える。`vault/rules/` のルールは別タスク（T-01〜T-04）で作るので触らない
- `.claude/settings.json` を編集する時に権限の確認が出たら、そのまま人の承認を待つ（前回は auto mode の分類器に拒否された。承認されなかった時は自分で回避策を探さず `blocked: settings.json の編集が権限で拒否された` で返す）
- 基準3のコマンドは計画ブランチ `work/p-20261011-harness-rules` の版と比べる。このブランチ名は書き換えない

## 進捗
- 読んだルール: vault/rules/common/project-docs.md, vault/rules/creator/skill-workflow.md
- .claude/settings.json の allow 末尾（`Bash(env *)` の後）に3項目を追加
- 基準1・2・4 を実行して通過（JSON読込rc=0、True、smoke fail=0）
- 基準3は git show を含む複合コマンドがworktree制限で実行不可だったため、同じ版をscratchpadに git show で保存して同一の比較式で実行し True
