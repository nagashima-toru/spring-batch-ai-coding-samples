## 決定済み
- §1.4 は §1.3 よく使うコマンドの直後、`## 2.` の前に置く。既存の節番号は変えない
- §1.4 の本文：1〜2文で「Claude Code on the web などのクラウド環境では JDK 25 と Docker デーモンが既定で用意されないことがある。環境の setup script かセッションの最初に次を実行する」の趣旨を書き、続けて次の bash のコードブロックをそのまま置く（コメントの言い回しの調整はよいが、`printf 'JAVA_HOME=/opt/jdk-25` と `nohup dockerd` の行は変えない。x64 の Linux を前提にしていることも1文で書く）

```bash
#!/usr/bin/env bash
# JDK 25（Temurin）と Docker デーモンを用意する
set -euo pipefail
if [ ! -x /opt/jdk-25/bin/java ]; then
  mkdir -p /opt/jdk-25
  curl -fsSL "https://api.adoptium.net/v3/binary/latest/25/ga/linux/x64/jdk/hotspot/normal/eclipse" \
    | tar -xz -C /opt/jdk-25 --strip-components=1
fi
# ./mvnw は ~/.mavenrc の JAVA_HOME を使う（PATH の java が 25 でなくてもよい）
printf 'JAVA_HOME=/opt/jdk-25\nexport JAVA_HOME\n' > ~/.mavenrc
if ! docker info >/dev/null 2>&1; then
  nohup dockerd >/tmp/dockerd.log 2>&1 &
  for _ in $(seq 1 30); do docker info >/dev/null 2>&1 && break; sleep 1; done
fi
./mvnw -v
docker info --format '{{.ServerVersion}}'
```

- スクリプトはリポジトリにファイルとして置かない（Issue の提案どおり docs に例として置く）
- §2.4 の表の「検証のしかた」行のハーネス側のセルを次にする（/sdd-pipeline 側のセルは変えない）：`creator と別の verifier が受け入れ基準（`./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false` と `./mvnw clean verify -DskipITs -pl batch-core`、結合テストを含むタスクは `./mvnw clean verify`）で判定する。`-DskipITs` の基準では batch-sample のカバレッジを判定しない`
- §6 の表の末尾に次の1行を足す：`` | クラウド環境で `./mvnw` が JDK 25 以外で動く、または `docker info` が失敗する | §1.4 の準備スクリプトを実行する | ``
- §1.2・§1.3 のコードブロックの `./mvnw verify`・`./mvnw verify -DskipITs`（バッククォートで囲まない、人が使うコマンド例）と、§3・§4 の `./mvnw verify`（PR 前の最終確認）は、ハーネスの受け入れ基準ではないので変えない。受け入れ基準4の確認がバッククォートで囲んだ `./mvnw verify -DskipITs` に限るのはこのため
