# T-02 JobParametersValidators の Javadoc を実際の動作に合わせ、未知のキーを通す単体テストを足す

## 目的
Issue #42 の提案2の後半。batch-core の `JobParametersValidators` の Javadoc を「未知のキーは拒否しない（WARN のみ）」に直し、その挙動を単体テストで固定する。ORDER-001 の Validator の Javadoc も、基盤部品が拒否すると読める書き方を直す。

## 入力
- `docs/architecture.md` §3.4 ジョブパラメータの検証（T-01 で追加済み）
- `batch-core/src/main/java/com/example/batch/core/execution/JobParametersValidators.java`
- `batch-core/src/test/java/com/example/batch/core/execution/JobParametersValidatorsTest.java`
- `batch-sample/src/main/java/com/example/batch/sample/job_order_daily_sales/OrderDailySalesJobParametersValidator.java`
- `docs/coding-standards.md` §7 テストコード規約

## 成果物
- 主な成果物：`batch-core/src/main/java/com/example/batch/core/execution/JobParametersValidators.java`（Javadoc のみ）
- 付随：`batch-core/src/test/java/com/example/batch/core/execution/JobParametersValidatorsTest.java`（テストメソッド2つの追加）
- 付随：`batch-sample/src/main/java/com/example/batch/sample/job_order_daily_sales/OrderDailySalesJobParametersValidator.java`（クラス Javadoc の1文のみ）

## 受け入れ基準
- `required` と `requiredAndOptional` の Javadoc にそれぞれ「未知のキーは拒否しない」があり、旧記述「未知のキーは許容しない」がリポジトリのコードに無い（`grep -c '未知のキーは拒否しない' batch-core/src/main/java/com/example/batch/core/execution/JobParametersValidators.java` が `2`、`grep -rn '未知のキーは許容しない' batch-core/src batch-sample/src` の出力が空）
- ORDER-001 の Validator の Javadoc から、基盤部品が未知のキーを拒否すると読める旧記述が消えている（`grep -rnF '（未知のキーは拒否）を基盤部品' batch-sample/src` の出力が空）
- 単体テストに、未知のキーがあっても検証を通過することを確かめるメソッドが2つある（`grep -c '未知のキーがある場合＿検証を通過する()' batch-core/src/test/java/com/example/batch/core/execution/JobParametersValidatorsTest.java` が `2`）
- 追加したテストを含む `JobParametersValidatorsTest` の5件が全部通る（`./mvnw test -pl batch-core -Dtest=JobParametersValidatorsTest 2>&1 | grep -c '^\[INFO\] Tests run: 5, Failures: 0, Errors: 0, Skipped: 0$'` が `1`）
- 全モジュールの Checkstyle・SpotBugs・単体テストが通る（`./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false 2>&1 | grep -c '^\[INFO\] BUILD SUCCESS$'` が `1`）
- batch-core のカバレッジ80%を含むビルドが通る（`./mvnw clean verify -DskipITs -pl batch-core 2>&1 | grep -c '^\[INFO\] BUILD SUCCESS$'` が `1`）

## 決定済み
- 実装（メソッド本体）は変えない。Issue #42 は提案2で進める（理由は T-01 の「決定済み」と `docs/architecture.md` §3.4）
- `JobParametersValidators` の Javadoc の直し方
  - `required` のメソッド Javadoc の「（未知のキーは許容しない）」を消し、「未知のキーは拒否しない（Spring Batch 6 の `DefaultJobParametersValidator` は任意キーが空だと未知のキーを検査しない）。」の趣旨を書く
  - `requiredAndOptional` のメソッド Javadoc に「未知のキーは拒否しない（WARN ログを出すだけ）。」の趣旨を書く
  - 「未知のキーは拒否しない」の文字列はこの2つのメソッド Javadoc に1回ずつだけ書く（クラス Javadoc には書かない。受け入れ基準の数が `2` になるように）
  - クラス Javadoc の「拡張ポイント」に、未知のキーの拒否が必要な場合はジョブ側の個別の Validator で行う（方式設計 §3.4）ことを1文足す
- テストメソッドの名前は次の2つにする（コーディング規約の「条件＿期待結果」。区切りは全角の `＿`）
  - `必須キーのみ指定で未知のキーがある場合＿検証を通過する()`：`required("importDate")` に `importDate` と `unknownKey` を渡し、例外が出ないこと
  - `必須と任意を指定し未知のキーがある場合＿検証を通過する()`：`requiredAndOptional({"importDate"}, {"dryRun"})` に `importDate` と `unknownKey` を渡し、例外が出ないこと
  - 既存の3メソッドは名前も中身も変えない。追加後のテストは5件
- `OrderDailySalesJobParametersValidator` のクラス Javadoc の「必須・任意キー（未知のキーは拒否）を基盤部品 {@link JobParametersValidators} に委譲したうえで、」は、「必須・任意キーの検証を基盤部品 {@link JobParametersValidators} に委譲し、基盤部品が拒否しない未知のキーをこのクラスで拒否したうえで、」に直す。コードとコメント（`// Spring Batch 6 の DefaultJobParametersValidator は…`）は変えない
- ビルドの基準は `-DskipITs` の2コマンド（batch-sample のカバレッジは判定しない。`docs/decisions.md` の決定）。結合テストのファイルは成果物に無いので `./mvnw clean verify` は基準にしない
- `-Djacoco.haltOnFailure=false` の実行で batch-sample の `Coverage checks have not been met` の WARNING が出るのは想定どおりで、直さない
