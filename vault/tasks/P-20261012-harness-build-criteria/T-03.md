# T-03 planner ルールのビルド基準を clean 付き・batch-sample カバレッジ非判定の2コマンドに直し、決定を decisions.md に残す

## 目的
Issue #44 の提案1。planner が工程タスクの受け入れ基準に書くビルドのコマンドを、まっさらな worktree でも `target/` の残留データがあっても同じ結果になる形（clean 付き、batch-sample のカバレッジは `-DskipITs` で判定しない）に直し、決定を `docs/decisions.md` に1行残す。

## 入力

- 親 `pom.xml` の `jacoco-maven-plugin` の設定（`coverage-check` はモジュールごとの BUNDLE 判定。参照のみ）

## 成果物

## 決定済み
- コマンドは次の3つに固定する（T-04・T-05 も同じ文字列を使う）
  - `./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false`：全モジュールの Checkstyle・SpotBugs・単体テスト。カバレッジ不足ではビルドを止めない（batch-sample は WARNING `Coverage checks have not been met` が出るだけ）
  - `./mvnw clean verify -DskipITs -pl batch-core`：batch-core のカバレッジ80%まで判定する
  - `./mvnw clean verify`：結合テストを含む。batch-sample のカバレッジ80%はここで判定する
- `-Djacoco.haltOnFailure=false` は JaCoCo の `check` ゴールの標準のプロパティで、pom の設定（閾値・除外）は変えない。`docs/development-guide.md` §5.4 の反則（閾値の変更・除外設定の追加）には当たらない。pom は成果物にしない
- `clean` を付けるのは、JaCoCo の実行データ（`target/jacoco.exec`・`target/jacoco-it.exec`）が `target/` に残っていると結果が変わるため
- `job-task-split.md` の書き換え（ほかの行は変えない）
  - 13行目を次にする：`` - 全タスクの受け入れ基準に、`./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false`（全モジュールの Checkstyle・SpotBugs・単体テスト。カバレッジ不足ではビルドを止めない）と `./mvnw clean verify -DskipITs -pl batch-core`（batch-core のカバレッジ80%）の成功を入れる。`-DskipITs` の基準では batch-sample のカバレッジを判定しない ``
  - 14行目を次にする：`` - 成果物に `*IT.java` を含むタスクだけ `./mvnw clean verify` の成功も入れる（結合テストは Docker が要るため。batch-sample のカバレッジ80%はここで判定する） ``
  - その直後に1行足す：`` - ビルドの確認コマンドは、上のコマンドに `2>&1 | grep -c '^\[INFO\] BUILD SUCCESS$'` をつないだ出力が `1` になる形で書く ``
  - 「確認方法」の2つ目の行を次にする：`` - 各タスク票の受け入れ基準に `./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false` と `./mvnw clean verify -DskipITs -pl batch-core` があり、`*IT.java` を成果物に持つタスクにだけ `./mvnw clean verify` もある ``
  - ルールの中で、clean 無しの `./mvnw verify -DskipITs`・`./mvnw verify` をバッククォートで書かない（受け入れ基準3）
- `docs/decisions.md` の表の末尾に次の1行を足す（既存の行は変えない。1行目・5行目は経緯として残し、この行で具体化する）：`| ハーネスの受け入れ基準のビルドは `clean` 付きで実行する。`-DskipITs` の基準は `./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false`（全モジュールの Checkstyle・SpotBugs・単体テスト）と `./mvnw clean verify -DskipITs -pl batch-core`（batch-core のカバレッジ）の2つにし、結合テストを含むタスクは `./mvnw clean verify` にする | `target/` に残った JaCoCo の実行データで判定がぶれないようにし、batch-sample のカバレッジを判定しないことをコマンドで表すため（どのタスクでも同じ扱いにする） | P-20261012-harness-build-criteria（Issue #44） |`
- `docs/decisions.md` の旧記述（1行目の `./mvnw verify -DskipITs`）は決定の経緯なので、旧形式が残っていないことの確認範囲から外す。`.claude/skills/` の工程 Skill と `.github/` の PR テンプレートは sdd-pipeline 側・人の最終確認の記述で、ハーネスの受け入れ基準ではないので本計画の範囲外（計画票の「次フェーズの候補」）
- `vault/rules/` のほかのファイル（verifier・creator）は T-04 で直す。このタスクの確認範囲は自分の成果物に限る
- 受け入れ基準5のビルドは、ルールに書いたコマンドが通ることの確認（docs だけのタスクでも実行する）
