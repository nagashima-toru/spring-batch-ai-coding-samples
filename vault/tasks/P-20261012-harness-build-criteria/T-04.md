# T-04 verifier・creator ルールのビルド実行を clean 付きの2コマンドに直す

## 目的
Issue #44 の提案2。verifier と creator が実行するビルドを clean 付きの2コマンド（と結合テストを含むタスクの `./mvnw clean verify`）にし、実行の順や `target/` の残留データで判定がぶれないようにする。`-DskipITs` の結果では batch-sample のカバレッジを判定しないことも verifier ルールに書く。

## 入力
- `vault/rules/planner/job-task-split.md`（T-03 で直したコマンドの書き方）
- `docs/decisions.md` の末尾の行（T-03 で追加）
- `vault/rules/verifier/build-verification.md`
- `vault/rules/creator/skill-workflow.md`

## 成果物
- 主な成果物：`vault/rules/verifier/build-verification.md`
- 付随：`vault/rules/creator/skill-workflow.md`（ビルドのコマンドを書いた2行のみ）

## 受け入れ基準
- verifier ルールが、工程タスクの判定で clean 付きの2コマンドを毎回実行させている（`grep -c '^- 工程タスクの判定では毎回自分で `\./mvnw clean verify -DskipITs -Djacoco\.haltOnFailure=false` と `\./mvnw clean verify -DskipITs -pl batch-core` を実行する' vault/rules/verifier/build-verification.md` が `1`）
- verifier ルールの結合テストの行が clean 付きになっている（`grep -c '^- 成果物に `\*IT\.java` を含むタスクでは `\./mvnw clean verify` も実行する' vault/rules/verifier/build-verification.md` が `1`）
- verifier ルールに、`-DskipITs` の結果では batch-sample のカバレッジを判定しない行がある（`grep -c '^- `-DskipITs` の結果では batch-sample のカバレッジを判定しない' vault/rules/verifier/build-verification.md` が `1`）
- creator ルールの review-code の行が、受け入れ基準のビルドコマンドを通す書き方になっている（`grep -c '^- review-code のタスクは .*受け入れ基準のビルドコマンドを通す' vault/rules/creator/skill-workflow.md` が `1`）
- `vault/rules/` 全体に clean 無しの旧コマンドが残っていない（`grep -rnE '`\./mvnw verify( -DskipITs)?`' vault/rules` の出力が空）

## 決定済み
- コマンドは T-03 と同じ3つ：`./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false`・`./mvnw clean verify -DskipITs -pl batch-core`・`./mvnw clean verify`（意味は T-03 の「決定済み」と `docs/decisions.md` の末尾の行）
- `build-verification.md` の書き換え（「目的」「確認方法」と、§5.1・§5.4・§12 を参照する行は変えない）
  - 7行目を次にする：`` - 工程タスクの判定では毎回自分で `./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false` と `./mvnw clean verify -DskipITs -pl batch-core` を実行する（`clean` を付けるのは、`target/` に残った JaCoCo の実行データで結果が変わらないようにするため）。それぞれの終了コードと末尾の `BUILD SUCCESS`／`BUILD FAILURE` を note に書く。creator の進捗や報告を根拠にしない ``
  - その直後に1行足す：`` - `-DskipITs` の結果では batch-sample のカバレッジを判定しない。`Coverage checks have not been met` の WARNING が出ても、それだけを FAIL の根拠にしない（batch-sample のカバレッジは `./mvnw clean verify` で判定する。`docs/decisions.md`） ``
  - 8行目を次にする：`` - 成果物に `*IT.java` を含むタスクでは `./mvnw clean verify` も実行する ``
  - Docker の行（9行目）の `./mvnw verify` を `./mvnw clean verify` に直す（ほかの文言は変えない）
- `skill-workflow.md` の書き換え（この2行だけ）
  - 11行目を次にする：`` - review-code のタスクは `/review-code` の手順でレビューし、[Must]/[Should] を自分で修正したうえで、受け入れ基準のビルドコマンドを通す。[Ask] が残ったら blocked にする ``
  - 20行目（確認方法）を次にする：`` - 完了報告の前に、受け入れ基準のビルドコマンド（`./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false` など）を自分で実行して通す ``
- 確認範囲を `vault/rules` 全体にするのはゴールの範囲（ハーネスのルール）だから。`docs/decisions.md` の旧行・`.claude/skills/`・`.github/` を外す理由は T-03 の「決定済み」のとおり。`docs/development-guide.md` は T-05 で確かめる
- このタスクはルール（md）だけの変更なのでビルドは基準にしない（コマンドが通ることは T-03 で確かめている）
