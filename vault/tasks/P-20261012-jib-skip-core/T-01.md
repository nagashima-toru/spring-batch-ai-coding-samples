# T-01 batch-core の pom.xml に jib.skip=true を設定し CD の jib を batch-core でスキップさせる

## 目的
CD（`.github/workflows/cd.yml`）の `-pl batch-sample -am ... package jib:build` で、依存先の batch-core でも jib が走り「Main class was not found」で失敗する問題（Issue #55）を、batch-core で jib をスキップさせて解消する。

## 入力
- `batch-core/pom.xml`（変更対象）
- `pom.xml`（親 POM。`jib-maven-plugin` のバージョンを pluginManagement で管理している。変更しない）
- `batch-sample/pom.xml`（jib の設定がある唯一のモジュール。変更しない）
- `.github/workflows/cd.yml`（イメージビルドのコマンド。変更しない）
- `CLAUDE.md` の「禁止事項」（依存バージョンの各モジュール個別指定禁止）

## 成果物
- `batch-core/pom.xml`（1ファイル。`<properties>` に `jib.skip` を追加する）

## 受け入れ基準
- `batch-core/pom.xml` の `<properties>` に `<jib.skip>true</jib.skip>` がちょうど1つある。確認：`grep -c 'jib.skip.true./jib.skip' batch-core/pom.xml` の出力が `1`
- batch-core 単体で jib を呼ぶとスキップされ成功する（JDK・ネットワーク非依存）。確認：`./mvnw -B -ntp -pl batch-core jib:buildTar 2>&1 | grep -c 'Skipping containerization because jib-maven-plugin: skip = true'` の出力が `1`、かつ `./mvnw -B -ntp -pl batch-core jib:buildTar 2>&1 | grep -c 'INFO. BUILD SUCCESS'` の出力が `1`
- CD と同じ `-pl batch-sample -am` の reactor 実行で batch-core の jib がスキップされる（JDK・ネットワーク非依存）。確認：`./mvnw -B -ntp -pl batch-sample -am jib:buildTar 2>&1 | grep -c 'Skipping containerization because jib-maven-plugin: skip = true'` の出力が `1`（batch-core の分だけ。親 POM は `packaging is 'pom'` という別の文言でスキップされ、batch-sample はスキップされない）
- Issue の再現コマンド（push しない）に Docker Hub の回数制限を避けるミラーのベースイメージ指定を付けて成功し、batch-sample のイメージ tar が作られる（JDK 25 とベースイメージ取得が要る。pom・CD は変えない）。確認：`./mvnw -B -ntp -pl batch-sample -am -DskipTests -Dcheckstyle.skip -Dspotbugs.skip -Djacoco.skip -Djib.from.image=mirror.gcr.io/library/eclipse-temurin:25-jre package jib:buildTar > /tmp/T-01-c4.log 2>&1` を実行した後、`grep -c 'INFO. BUILD SUCCESS' /tmp/T-01-c4.log` の出力が `1`、かつ `ls batch-sample/target/jib-image.tar` が終了コード0
- batch-core のビルド（Checkstyle・SpotBugs・単体テスト・カバレッジ80%）が通る。確認：`./mvnw clean verify -DskipITs -pl batch-core 2>&1 | grep -c 'INFO. BUILD SUCCESS'` の出力が `1`
- 計画ブランチとの分岐点からの差分に `batch-core/pom.xml` が含まれる。確認：`git diff --merge-base work/p-20261012-jib-skip-core --name-only` の出力に `batch-core/pom.xml` の行がある

## 決定済み
- 追加する場所：`batch-core/pom.xml` の `<description>` の直後に `<properties>` 要素を新設し、その中に `<jib.skip>true</jib.skip>` を1行書く（現状 batch-core に `<properties>` は無い）。直前に日本語の XML コメントで理由を書く（例：`<!-- ライブラリのためコンテナイメージは作らない。CD の -am で jib が走っても batch-core はスキップする（Issue #55） -->`）。
- `jib.skip` はバージョン指定ではないので、「依存バージョンの各モジュール個別指定禁止」には当たらない。jib-maven-plugin の `<plugin>` 宣言を batch-core に足したり、バージョンを書いたりはしない。
- 親 `pom.xml`・`batch-sample/pom.xml`・`.github/workflows/cd.yml` は変えない。batch-sample の親は batch-core ではなくルートの親 POM なので、batch-core のプロパティは batch-sample に継承されず、batch-sample のイメージビルドには影響しない。
- 親 POM（packaging が pom）は jib 側で `Skipping containerization because packaging is 'pom'` として自動でスキップされるので、親 POM に `jib.skip` は足さない。
- docs（`docs/architecture.md`・`docs/aws-setup.md` 等）には jib のモジュール別の挙動の記述が無いので、docs は変えない。
- 確認はレジストリへ push しない `jib:buildTar` で行う。`jib:build`（push）は実行しない。
- 「CD と同じ reactor 実行」の基準は `package` を付けずに実行するため、batch-sample の段は失敗してよい（BUILD FAILURE でもよい）。この基準で見るのは batch-core のスキップのログ行が1行出ることだけ。修正前は batch-core が `Main class was not found` で失敗し、スキップのログは0行になる（計画作成時に確認済み）。
- JDK 25 が要る基準（再現コマンドの BUILD SUCCESS とイメージ tar、`./mvnw clean verify -DskipITs -pl batch-core`）は JDK 25（Temurin）の環境で実行する。実行環境に JDK 25 が無く `release version 25 not supported` で失敗する場合、またはベースイメージ `eclipse-temurin:25-jre` の取得がネットワークの理由で失敗する場合は、成果物の誤りではないので基準を読み替えず `blocked` にし、question にその旨（失敗したコマンドとエラー行）を書く。
- 実行環境の JDK：この環境には apt で JDK 25（`/usr/lib/jvm/java-25-openjdk-amd64`）を入れ、`~/.mavenrc` で `./mvnw` の `JAVA_HOME` を JDK 25 にしてある（`./mvnw -v` で `Java version: 25` を確かめられる）。基準のコマンドは書いてあるとおりに実行する（人の回答）。
- `batch-sample/target/jib-image.tar` は jib:buildTar の既定の出力先（`${project.build.directory}/jib-image.tar`）。コミットしない（`target/` は対象外）。
