# T-04 GitHub 設定・CI の確認結果を含む公開手順チェックリストを docs に作る

## 目的
public 化に伴って見直すべき GitHub の設定（Actions の権限・fork からの PR・Environments・OIDC・シークレット・セキュリティ機能・ブランチ保護）と、可視性の切り替えまでの手順を、リポジトリ所有者が上から順に実施できるチェックリストにする。

- `docs/public-release-inventory.md`（T-01 の棚卸し結果。「人への報告事項」と残存ブランチ）

- チェックリストに4つの見出しがそろっている。確認：`grep -cE '^## (現状の確認結果|公開前に人が行う設定|可視性の切り替え（人が行う）|公開後の確認)$' docs/public-release-checklist.md` の出力が `4`
- 決めた9項目がチェックボックスの行として1行ずつある。確認：`grep -cE '^- \[ \] \*\*(Workflow permissions|fork PR の承認|production 環境の保護|OIDC の信頼ポリシー|Secret scanning|Dependabot alerts|ブランチ保護|残存ブランチ|可視性の切り替え)\*\*' docs/public-release-checklist.md` の出力が `9`
- 可視性の切り替えの項目が、人が Settings の Danger Zone で行う操作として書かれている。確認：`grep -cE '^- \[ \] \*\*可視性の切り替え\*\*.*Danger Zone.*Change visibility' docs/public-release-checklist.md` の出力が `1`

## 決定済み
- 見出しは `## 現状の確認結果`・`## 公開前に人が行う設定`・`## 可視性の切り替え（人が行う）`・`## 公開後の確認` の4つをこの順で書く（`# ` のタイトルは「public 化の手順チェックリスト」）
- `## 現状の確認結果` は、ワークフロー等を読んで確かめた事実を箇条書き（チェックボックスにしない）で書く。最低限：ci.yml は `permissions: contents: read` で `pull_request` を契機に動き、シークレットを使わない／cd.yml は `v*` タグの push だけを契機に `environment: production` で動き、`id-token: write` で OIDC を使い、値は Environments の Variables（`vars.`）から読む／`pull_request_target` は使っていない／Dependabot は maven と github-actions を週次で更新
- チェックボックスの行は `- [ ] **<項目名>**：<やること>` の形で、項目名は次の9つ（この文字列のまま、各1行。1行に複数の項目名を書かない）。`## 公開前に人が行う設定` に1〜8、`## 可視性の切り替え（人が行う）` に9を置く
  1. `Workflow permissions`：Settings > Actions > General の Workflow permissions を「Read repository contents and packages permissions」にし、「Allow GitHub Actions to create and approve pull requests」を外す
  2. `fork PR の承認`：Settings > Actions > General の fork からの PR のワークフロー実行に承認を必須にする（外部のコントリビューター全員に承認を求める設定を選ぶ）
  3. `production 環境の保護`：Settings > Environments > production の Deployment branches and tags を `v*` タグに限定し、Required reviewers に所有者を入れる
  4. `OIDC の信頼ポリシー`：AWS の IAM ロールの信頼ポリシーの `sub` が `repo:nagashima-toru/spring-batch-ai-coding-samples:environment:production` に限定されていることを確かめる（`docs/aws-setup.md` の手順どおりか）
  5. `Secret scanning`：Settings > Code security で Secret scanning と Push protection を有効にする
  6. `Dependabot alerts`：Dependabot alerts と Dependabot security updates を有効にする
  7. `ブランチ保護`：main にブランチ保護（またはルールセット）を設定し、PR 必須・CI の成功必須・force push 禁止にする
  8. `残存ブランチ`：`docs/public-release-inventory.md` の「人への報告事項」を読み、不要なリモートブランチを人が削除する（PR の ref は GitHub 側で消せないことも書く）
  9. `可視性の切り替え`：Settings > General の Danger Zone の Change visibility で Public にする（不可逆に近い外部操作のため人が行う。エージェントは行わない）
- `## 公開後の確認` には、リポジトリのトップでライセンスが MIT と表示されること、CI が main で成功すること、Actions のシークレット・Variables が fork の PR から参照できないこと、を箇条書きで書く（チェックボックス可。ただし上の9つの項目名は使わない）
- このタスクではワークフロー・`dependabot.yml`・`docs/aws-setup.md`・GitHub の Settings を変えない。確認の結果、変更が要ると判断したものはチェックリストに人の作業として書く。受け入れ基準の `pull_request_target`・`secrets.`・`permissions:` の確認が満たせない時（ワークフローの修正が要る時）は `blocked` にする
- GitHub の画面の項目名は英語表記（2024年以降の UI の表記）で書き、正確な表記が分からないものは「〜の設定」と説明で書いてよい（受け入れ基準が見るのは項目名の太字と Danger Zone・Change visibility の語だけ）
