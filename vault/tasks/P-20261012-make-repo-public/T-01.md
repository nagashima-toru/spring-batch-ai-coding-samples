# T-01 機密・個人・内部情報の棚卸しレポート（作業ツリーと git 履歴・リモートの ref）

## 目的
リポジトリを public にした時に誰でも見られるようになる情報（作業ツリー・git 履歴・リモートのブランチと PR の ref）から、シークレット・個人情報・内部情報を洗い出し、公開してよいかを人が判断できるレポートにする。

## 入力
- リポジトリ全体（`git ls-files` の全ファイル）と `git log --all` の全コミット（内容・メッセージ・作成者）
- `git ls-remote origin` で見えるリモートの ref（`refs/heads/*`・`refs/pull/*/head`）
- `docs/aws-setup.md`（AWS アカウント ID・ARN の例示）、`docker/compose.yaml`・`batch-sample/src/main/resources/application-local.yml`（ローカル用の固定パスワード）
- 計画票 `vault/plans/P-20261012-make-repo-public.md` の「人への質問」4（事前の調べで見つかっている項目）

## 成果物
- `docs/public-release-inventory.md`（1ファイル。棚卸しの結果レポート）

## 受け入れ基準
- レポートに4つの見出しがそろっている。確認：`grep -cE '^## (対象と方法|作業ツリーの結果|git 履歴の結果|人への報告事項)$' docs/public-release-inventory.md` の出力が `4`
- 既知の7か所がそれぞれ結果表の1行になっている。確認：`grep -cE '^\| [^|]+ \| (docs/aws-setup\.md|docker/compose\.yaml|batch-sample/src/main/resources/application-local\.yml|vault/designs/D-20261011-spring-batch-adapt\.md|コミットの作成者|コミットメッセージ|リモートのブランチと PR の ref) \|' docs/public-release-inventory.md` の出力が `7`
- レポートに個人のメールアドレスと Claude-Session の URL の値そのものを書き写していない。確認：`grep -cE '@gmail\.com|claude\.ai/code/session_' docs/public-release-inventory.md` の出力が `0`
- 作業ツリー全体に、代表的なシークレットの形（AWS アクセスキー・秘密鍵・GitHub トークン・Slack トークン）が無い。確認：`git grep -nE 'AKIA[0-9A-Z]{16}|-----BEGIN [A-Z ]*PRIVATE KEY-----|gh[pousr]_[A-Za-z0-9]{36}|xox[baprs]-[A-Za-z0-9-]{10,}'` の出力が空
- 全ブランチ・取得済みの PR の ref を含む履歴に、同じシークレットの形を追加・削除したコミットが無い。確認：`git log --all --format=%H -G 'AKIA[0-9A-Z]{16}|-----BEGIN [A-Z ]*PRIVATE KEY-----|gh[pousr]_[A-Za-z0-9]{36}|xox[baprs]-[A-Za-z0-9-]{10,}'` の出力が空
- PR の ref を走査に含めた。確認：`git for-each-ref --count=1 refs/remotes/origin/pr/` の出力が空でない

## 決定済み
- 履歴の扱い（人の回答）：機微な情報が無ければ履歴は書き換えずに公開してよい。機微な情報（実在のシークレット・キー・トークン、実在の AWS アカウント ID・ARN、内部ホスト名・社内 URL、顧客名・社外秘の案件情報など）が作業ツリーまたは履歴に1件でも見つかった時は、レポートにその場所と種別（値は書かない）を書いたうえで `blocked` にし、question 列に「履歴の書き換え等の対応要否」を書く。メールアドレス・Claude-Session の URL・削除済み設計文書・PR の ref は、中身に上記の機微な情報が無ければ機微な情報とはみなさない（人への報告にとどめる）
- レポートの見出しは `## 対象と方法`・`## 作業ツリーの結果`・`## git 履歴の結果`・`## 人への報告事項` の4つをこの順で書く（`# ` のタイトルは「公開前の棚卸し結果」）。`## 作業ツリーの結果` と `## git 履歴の結果` には結果表を置く
- 結果表の列は `| 種別 | 場所 | 判断 | 対応 |` の4列。「場所」はバッククォートで囲まず、ファイルはリポジトリ相対パスをそのまま書く。同じ場所の所見は1行にまとめる（同じ場所で2行に分けない）
- 次の7か所は必ず1行ずつ書く（「場所」の列はこの文字列と完全に一致させる）。判断・対応の案も付ける
  - `docs/aws-setup.md`：AWS アカウント ID `123456789012` と ARN は AWS 公式ドキュメントの例示値（ダミー値）。OIDC の信頼ポリシーの `sub` にリポジトリ名が入るのは公開情報で問題なし → 対応なし
  - `docker/compose.yaml`・`batch-sample/src/main/resources/application-local.yml`：パスワード `batch_admin` はローカル専用の固定値（コメントで明示済み）→ 対応なし（2行に分けて書く）
  - `vault/designs/D-20261011-spring-batch-adapt.md`：作業ツリーからは削除済みだが履歴に残る設計文書。中身を読み、内部情報の有無を判断に書く（`## git 履歴の結果` の表に置く）
  - `コミットの作成者`：作成者のメールアドレスが公開される（値は書かず「個人のメールアドレス」と書く）。履歴は書き換えない → 人への報告
  - `コミットメッセージ`：Claude-Session の URL が残っている（件数だけ書き、URL は書かない）→ 人への報告
  - `リモートのブランチと PR の ref`：squash マージ前のコミット（計画ブランチの vault の作業ログなど）を保持する。残存ブランチ名と PR の ref の件数を書く → 人への報告（ブランチの削除は人が行う。PR の ref は GitHub 側で消せない旨も書く）
- PR の ref は、走査の前に `git fetch origin '+refs/pull/*/head:refs/remotes/origin/pr/*'` で取得する（ローカルの ref を足すだけで非破壊）。リモートのブランチも `git fetch origin` で取得してから `git log --all` で走査する
- 上の7か所以外にも、作業ツリーと履歴（内容・コミットメッセージ）を次の観点で調べ、見つかれば行を足す：シークレット（キー・トークン・パスワード）、AWS アカウント ID・ARN（例示値 `123456789012` 以外）、内部ホスト名・社内 URL・IP アドレス、メールアドレス（`example.com` のテスト用は対象外として「対象と方法」に除外理由を書く）、案件名・顧客名など社外秘になりうる語
- 除外する範囲：`target/` などビルド生成物（`.gitignore` 対象で git に入らないため）。`git ls-files` と `git log --all` に出るものだけが公開対象であることを「対象と方法」に書く
- 本物のシークレット・個人情報が見つかった場合：値はレポートに書かない（場所とコミットのハッシュの先頭7桁だけ書く）。履歴の書き換え・ファイルの削除・ブランチの削除は行わず、`blocked` にして question に「どこで何が見つかったか（値は伏せる）」を書く
- `## 人への報告事項` には、履歴を書き換えない前提で公開した時に見られるもの（作成者のメールアドレス・Claude-Session の URL・PR の ref・残存ブランチ）と、取りうる対応（例：今後のコミットに GitHub の noreply アドレスを使う、残存ブランチを削除する）を箇条書きにする。どれを行うかは決めない
- レポートは日本語で書く。gitleaks などの外部ツールは導入しない（`git grep` と `git log -G` で調べる）
