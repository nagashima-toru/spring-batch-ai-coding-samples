# T-03 docs/development-guide.md §1.2・§1.3 のコマンドをそろえ、全体に残りが無いことを確かめる

## 目的
docs/development-guide.md の §1.2 初回セットアップと §1.3 よく使うコマンドに残る clean の無い `./mvnw verify` を、`vault/rules/verifier/build-verification.md` と同じ3コマンドの使い分けにそろえ、リポジトリ全体の Markdown に clean の無い `./mvnw verify` が残っていないことを確かめる（Issue #52）。

## 入力
- `docs/development-guide.md`（§1.2 の29行目、§1.3 の35〜36行目のコードブロック。§2.4 の表・§4 の手順にある既存の `./mvnw clean verify` の書き方）
- `vault/rules/verifier/build-verification.md`（3コマンドの使い分けと clean を付ける理由）
- `docs/decisions.md`（11行目。`-DskipITs` では batch-sample のカバレッジを判定しない決定と理由）
- T-01・T-02 で変更済みの `README.md`・`CLAUDE.md`（書きぶりをそろえる参考。変更はしない）

## 成果物
- `docs/development-guide.md`（1ファイル。§1.2・§1.3 のコードブロック内の mvnw の行だけを変える）

## 受け入れ基準
- リポジトリ全体（`vault/`・`docs/decisions.md`・`.claude/worktrees/` を除く）の Markdown に clean の無い `./mvnw verify` が残っていない（`grep -rln --include='*.md' --exclude-dir=vault --exclude-dir=worktrees --exclude=decisions.md 'mvnw verify' .` の出力が空）
- §1.2 の初回ビルドの行が、コメントの無い `./mvnw clean verify` の1行になっている（`grep -cx './mvnw clean verify' docs/development-guide.md` が `1`）
- §1.3 に、結合テストを除外しカバレッジ不足で止めないコマンドの行がちょうど1行ある（`grep -c '^./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false *#' docs/development-guide.md` が `1`）
- §1.3 に、batch-core のカバレッジを判定するコマンドの行がちょうど1行ある（`grep -c '^./mvnw clean verify -DskipITs -pl batch-core *#' docs/development-guide.md` が `1`）
- §1.3 に、結合テストを含む全体のコマンドの行がちょうど1行あり、そのコメントに `batch-sample` が書かれている（`grep -c '^./mvnw clean verify *#.*batch-sample' docs/development-guide.md` が `1`）
- 見出しの構成が変わっていない（`git diff --merge-base work/p-20261012-readme-build-cmd-clean -- docs/development-guide.md | grep -c '^[+-]#'` が `0`）
- 変更したのが docs/development-guide.md である（`git diff --merge-base work/p-20261012-readme-build-cmd-clean --name-only` の出力に `docs/development-guide.md` が含まれる）

## 決定済み
- §1.2 の初回セットアップの `./mvnw verify` は、コメントを付けずに `./mvnw clean verify` の1行にする（直前のコメント行「# ビルド＋全テスト（初回は依存ダウンロードで数分かかる）」はそのまま残す）
- §1.3 のコードブロック内の mvnw の verify の行は次の3行にする（並び順もこのとおり。コメントの文言は趣旨を保てば調整してよい）
  - `./mvnw clean verify` … コメントに「ビルド＋単体＋結合（Docker 必須）＋静的解析」と「batch-sample のカバレッジ80%はここで判定」の趣旨を書く。`batch-sample` の語を必ず書く
  - `./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false` … コメントは「結合テストを除外（Docker 不要）。カバレッジ不足では止めない」の趣旨
  - `./mvnw clean verify -DskipITs -pl batch-core` … コメントは「batch-core のカバレッジ80%を判定」の趣旨
- 3行とも、コマンドの後に1つ以上の空白を置いてから `#` のコメントを続ける（受け入れ基準の grep がこの形を前提にする）
- `./mvnw test -pl batch-core`・`./mvnw checkstyle:check`・`./mvnw spring-boot:run ...` の行は変えない
- 必要なら §1.3 のコードブロックの直後に、`./mvnw verify -DskipITs` が batch-sample のカバレッジで失敗する理由と clean を付ける理由を1〜2文で足してよい（任意。足す時は根拠として `docs/decisions.md` を参照する）。ただしその文に clean の無い `./mvnw verify` を書かない（全体検査の基準に当たるため。「`-DskipITs` だけを付けた形」のように言い換える）
- §1 以外の節（§2〜§5 など）は変えない。既に clean 付きにそろっている（前計画 P-20261012-build-cmd-clean で対応済み）
- 全体検査の除外範囲とその理由：`vault/`（計画・ルール・ログ・判定の記録で、run が管理する）、`docs/decisions.md`（過去の決定の記録で、当時のコマンドをそのまま残す）、`.claude/worktrees/`（ハーネスが作る作業用 worktree で、リポジトリの文書ではない）。`.github/workflows/` は Markdown ではないので `--include='*.md'` で既に対象外（CI はクリーンなチェックアウトで動くので clean は不要）
- 全体検査で T-01・T-02 の対象（README.md・CLAUDE.md）に残りが見つかった時は、このタスクの成果物外なので直さず `blocked` にして question に書く
- ビルド（`./mvnw ...`）の成功は受け入れ基準にしない。文書の変更だけで、3コマンドは前計画 P-20261012-build-cmd-clean と `vault/rules/verifier/build-verification.md` で使われ動作が確かめられているため
- docs/development-guide.md は smoke の `(ref-1)` の対象文書ではないので、`(ref-1)` の基準は入れない
- 行頭が `#` の行（見出しとコードブロック内のコメント行）は追加・変更・削除しない（見出し構成の基準 `grep -c '^[+-]#'` がコードブロック内のコメント行の変更にも当たるため）
