# T-02 CLAUDE.md の「ビルド・実行コマンド」を3コマンドの使い分けにそろえる

## 目的
CLAUDE.md の「ビルド・実行コマンド」にある clean の無い `./mvnw verify` と `./mvnw verify -DskipITs` を、`vault/rules/verifier/build-verification.md` と同じ3コマンドの使い分けにそろえる（Issue #52）。`./mvnw verify -DskipITs` はまっさらな環境で batch-sample のカバレッジ判定により必ず失敗するため。

## 入力
- `CLAUDE.md`（「## ビルド・実行コマンド」節のコードブロック。30〜31行目）
- `vault/rules/verifier/build-verification.md`（3コマンドの使い分け）
- `docs/decisions.md`（11行目。`-DskipITs` では batch-sample のカバレッジを判定しない決定と理由）

## 成果物
- `CLAUDE.md`（1ファイル。「ビルド・実行コマンド」節のコードブロック内の mvnw の行だけを変える）

## 受け入れ基準
- CLAUDE.md に clean の無い `./mvnw verify` が残っていない（`grep -c 'mvnw verify' CLAUDE.md` が `0`）
- CLAUDE.md に、結合テストを除外しカバレッジ不足で止めないコマンドの行がちょうど1行ある（`grep -c '^./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false *#' CLAUDE.md` が `1`）
- CLAUDE.md に、batch-core のカバレッジを判定するコマンドの行がちょうど1行ある（`grep -c '^./mvnw clean verify -DskipITs -pl batch-core *#' CLAUDE.md` が `1`）
- CLAUDE.md に、結合テストを含む全体のコマンドの行がちょうど1行あり、そのコメントに `batch-sample` が書かれている（`grep -c '^./mvnw clean verify *#.*batch-sample' CLAUDE.md` が `1`）
- 見出しの構成が変わっていない（`git diff --merge-base work/p-20261012-readme-build-cmd-clean -- CLAUDE.md | grep -c '^[+-]#'` が `0`）
- 変更したのが CLAUDE.md である（`git diff --merge-base work/p-20261012-readme-build-cmd-clean --name-only` の出力に `CLAUDE.md` が含まれる）

## 決定済み
- コードブロック内の mvnw の行は次の3行にする（並び順もこのとおり。コメントの文言は趣旨を保てば調整してよいが、短く1行に収める）。CLAUDE.md はセッションのシステムプロンプトに入るので、説明の文や注記の段落は足さない
  - `./mvnw clean verify` … コメントに「全体（単体＋結合(要Docker)＋静的解析）」と「batch-sample のカバレッジ80%はここで判定」の趣旨を書く。`batch-sample` の語を必ず書く
  - `./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false` … コメントは「結合テスト除外（カバレッジ不足では止めない）」の趣旨
  - `./mvnw clean verify -DskipITs -pl batch-core` … コメントは「batch-core のカバレッジ80%」の趣旨
- 3行とも、コマンドの後に1つ以上の空白を置いてから `#` のコメントを続ける（受け入れ基準の grep がこの形を前提にする）
- `docker compose ...` の行とジョブのローカル実行例（`java -jar ...`）は変えない
- 「技術スタック」「禁止事項」「ハマりどころ」「規約サマリ」など、ほかの節は変えない。`.claude/ai-harness.md` も変えない
- `docs/decisions.md` は過去の決定の記録なので変えない。新しい決定も追加しない（Issue #45 の方針の適用漏れの修正のため）
- ビルド（`./mvnw ...`）の成功は受け入れ基準にしない。文書の変更だけで、3コマンドは前計画 P-20261012-build-cmd-clean と `vault/rules/verifier/build-verification.md` で使われ動作が確かめられているため
- CLAUDE.md は smoke の `(ref-1)` の対象文書ではないので、`(ref-1)` の基準は入れない
- 行頭が `#` の行（見出しとコードブロック内のコメント行）は追加・変更・削除しない（見出し構成の基準 `grep -c '^[+-]#'` がコードブロック内のコメント行の変更にも当たるため）

## 進捗
- 読んだルール: common/project-docs.md, creator/skill-workflow.md
- CLAUDE.md のコードブロック内 mvnw 2行を3行（clean verify / clean verify -DskipITs -Djacoco.haltOnFailure=false / clean verify -DskipITs -pl batch-core）に変更
- 受け入れ基準6行の確認コマンドを実行し、期待値どおり（0,1,1,1,0,CLAUDE.md を含む）
