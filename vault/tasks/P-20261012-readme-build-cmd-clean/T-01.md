# T-01 README.md のクイックスタートのビルドコマンドを clean 付きにする

## 目的
README.md のクイックスタートにある clean の無い `./mvnw verify` を `./mvnw clean verify` にし、`target/` に残った JaCoCo の実行データで判定がぶれないようにする（Issue #52）。

## 入力
- `README.md`（「クイックスタート」節のコードブロック。20行目付近）
- `vault/rules/verifier/build-verification.md`（3コマンドの使い分けと clean を付ける理由）
- `docs/decisions.md`（11行目。`-DskipITs` では batch-sample のカバレッジを判定しない決定）

## 成果物
- `README.md`（1ファイル。クイックスタートのビルドコマンドの行だけを変える）

## 受け入れ基準
- README.md に clean の無い `./mvnw verify` が残っていない（`grep -c 'mvnw verify' README.md` が `0`）
- README.md に、行頭が `./mvnw clean verify` で、その後に空白とコメント（`#`）だけが続く行がちょうど1行ある（`grep -c '^./mvnw clean verify *#' README.md` が `1`）
- README.md のクイックスタートのコードブロックに `docker compose -f docker/compose.yaml up -d` と `java -jar batch-sample/target/batch-sample-*.jar` の行が残っている（`grep -c 'docker compose -f docker/compose.yaml up -d' README.md` と `grep -c 'java -jar batch-sample/target/batch-sample-' README.md` がそれぞれ `1` 以上）
- バッククォート内のパスがすべて存在する（`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`）
- 変更したのが README.md である（`git diff --merge-base work/p-20261012-readme-build-cmd-clean --name-only` の出力に `README.md` が含まれる）

## 決定済み
- 置き換える行は1行だけで、`./mvnw clean verify` にする（`-DskipITs` や `-pl` は付けない）。クイックスタートは前提に Docker を挙げ、直前で DB を起動しているので、結合テストを含む全体のビルドのままでよい
- コメントは「ビルド＋全テスト＋静的解析＋カバレッジ」の趣旨を保つ（文言は任意。カラム位置はほかの行に合わせて整えてよい）
- 3コマンドの使い分けの説明は README には足さない（詳しい使い分けは T-03 で `docs/development-guide.md` §1.3 に書く。README からはドキュメント表で案内済み）
- `docs/decisions.md` は過去の決定の記録なので変えない。新しい決定の記録も追加しない（Issue #45・PR #53 の方針の適用漏れの修正であり、新しい決定ではないため）
- `.github/workflows/` は CI がクリーンなチェックアウトで動くため対象外
- ビルド（`./mvnw ...`）の成功は受け入れ基準にしない。文書の変更だけで、3コマンドは前計画 P-20261012-build-cmd-clean と `vault/rules/verifier/build-verification.md` で使われ動作が確かめられているため

## 進捗
- 読んだルール: vault/rules/common/project-docs.md, vault/rules/creator/skill-workflow.md
- README.md 20行目を `./mvnw clean verify` に変更（コメント位置を整えた）
- 受け入れ基準の確認コマンドを全て実行し通過（0 / 1 / 1 / 1 / 1 / README.md を含む）
