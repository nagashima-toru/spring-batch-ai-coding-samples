# T-01 規約レビューのスキルを review-standards に改名し参照を追従させる

## 目的
規約レビューのスキル `review-code` を、組み込みの `code-review` と区別できる `review-standards` に改名し、リポジトリ内の旧名の参照をすべて新しい名前に追従させる。

## 入力
- `.claude/skills/review-code/SKILL.md`・`.claude/skills/review-code/references/code-review-checklist.md`（移す対象）
- 旧名の参照箇所の一覧：`git grep -n 'review-code'` の出力（着手時点で11ファイル・23行）
- `docs/development-guide.md` の見出し（アンカーを壊さないため）

## 成果物
- 主な成果物：`.claude/skills/review-standards/`（`.claude/skills/review-code/` から移したスキル。SKILL.md と references/ 配下）
- `.claude/skills/review-code/`（移動元。削除になる）
- `CLAUDE.md`
- `docs/development-guide.md`
- `docs/coding-standards.md`
- `.github/PULL_REQUEST_TEMPLATE/implementation.md`
- `.claude/skills/sdd-pipeline/SKILL.md`
- `.claude/skills/implementation/SKILL.md`
- `.claude/skills/integration-test/SKILL.md`
- `vault/rules/planner/job-task-split.md`
- `vault/rules/creator/skill-workflow.md`
- `config/checkstyle/checkstyle.xml`

## 受け入れ基準
- 旧名の参照が計画記録を除くリポジトリ全体に残っていない：`git grep -n --untracked 'review-code' -- ':(exclude)vault/plans' ':(exclude)vault/tasks' ':(exclude)vault/log' ':(exclude)vault/verdicts' | wc -l` の出力が `0`
- 旧名を参照していた11ファイルがすべて新しい名前を参照している：`git grep -l --untracked 'review-standards' -- ':(exclude)vault/plans' ':(exclude)vault/tasks' ':(exclude)vault/log' ':(exclude)vault/verdicts' | wc -l` の出力が `11`
- 移したスキルの frontmatter の name が新しい名前である：`grep -cx 'name: review-standards' .claude/skills/review-standards/SKILL.md` の出力が `1`
- チェックリストが中身を変えずに移っている：`git hash-object .claude/skills/review-standards/references/code-review-checklist.md` の出力が `ff696d1d858c22e99b043fc3330f3a05ba18538b`
- 見出し（アンカー）を変えていない：`git diff --merge-base work/p-20261017-review-redesign -- CLAUDE.md docs/development-guide.md docs/coding-standards.md | grep -c '^[+-]#'` の出力が `0`
- ビルドが通る：`./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false 2>&1 | grep -c '^\[INFO\] BUILD SUCCESS$'` の出力が `1`
- smoke が通り `(ref-1)` も ok：`bash scripts/smoke.sh 2>&1 | grep -c -e '^  ok   (ref-1) ' -e '^smoke: pass=[0-9]* fail=0'` の出力が `2`

## 決定済み
- 新しい名前は `review-standards`（人が選択済み）。移動は `git mv .claude/skills/review-code .claude/skills/review-standards` で行い、SKILL.md と `references/code-review-checklist.md` を丸ごと移す。チェックリストの中身は変えない（ファイル名 `code-review-checklist.md` も変えない）
- SKILL.md の frontmatter は `name: review-standards` の行にする。本文の見出し `# コードレビュー Skill` は `# 規約レビュー Skill` に変える。description と「進め方」以下の本文はこのタスクでは変えない（手順4は T-02 で直す）
- 置き換えは旧名 `review-code` を `review-standards` に替えるだけにする（`/review-code` は `/review-standards`、`review-code Skill` は `review-standards Skill`）。組み込みの `/code-review`（`code-review`）は別のものなので変えない
- 工程の呼び名「コードレビュー」は変えない。CLAUDE.md の Skills 表の行は「| `/review-standards` | コードレビュー | 指摘一覧（チェックリスト準拠＋組み込み `/code-review` の両方） |」にする。`docs/development-guide.md` の mermaid のノードは `RC["/review-standards<br>コードレビュー"]`（ノード ID `RC` は変えない）
- 見出し行（`#` で始まる行）は変えない。旧名を含む見出しは無いので、`docs/development-guide.md#24-ハーネスで実装以降を進める場合` などのアンカーはそのまま
- 参照箇所は着手時点で次の11ファイル：`CLAUDE.md`・`docs/development-guide.md`・`docs/coding-standards.md`・`.github/PULL_REQUEST_TEMPLATE/implementation.md`・`.claude/skills/sdd-pipeline/SKILL.md`・`.claude/skills/implementation/SKILL.md`・`.claude/skills/integration-test/SKILL.md`・SKILL.md 自身（frontmatter）・`vault/rules/planner/job-task-split.md`・`vault/rules/creator/skill-workflow.md`・`config/checkstyle/checkstyle.xml`（コメント）。どれも新しい名前を1回以上含む状態にする（11ファイル以外に `review-standards` を書き足さない）
- `vault/plans`・`vault/tasks`・`vault/log`・`vault/verdicts` は計画の記録（この計画のタスク票自身が旧名を書いている）なので、旧名の検査から除く
- `vault/rules/` の2ファイルは名前の置き換えだけにする（ルールの追記は T-04・T-05 で別ファイルに書く）
- ハーネス本体（`.claude/agents/`・`docs/vault-spec.md`・`.claude/hooks/`・`scripts/`）は変えない。batch-sample には触らない
- ビルドには JDK 25 が要る。`./mvnw -v` の Java が 25 でなければ、`docs/development-guide.md` §1.4 の準備（JDK 25 の用意と `~/.mavenrc`）を実行してからビルドする。準備ができない時は blocked にする

- 受け入れ基準7行の確認コマンドを実行し、期待値どおり（0 / 11 / 1 / ff696d1d... / 0 / 1 / 2）
