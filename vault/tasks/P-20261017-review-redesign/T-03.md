# T-03 verifier ルールに /code-review の指摘の区分の対応を書く

## 目的
受け入れ基準の `/code-review` の行を判定する時の、このリポジトリ固有の補足（review-standards の区分 Must/Should/Ask との対応、差分の外の扱い、規約チェックリストとの関係）を verifier ルールに書く。ハーネス本体の判定規則は写さない。

## 入力
- `.claude/agents/verifier.md` の「コードレビューを参照する基準の判定」節（読むだけ。写さない）
- `.claude/skills/review-standards/SKILL.md`（T-02 の後の手順4と、区分の表の下の [Must]/[Should]/[Ask] の定義）
- `vault/templates/rule.md`（見出し：目的 / ルール / 確認方法）
- `vault/rules/verifier/build-verification.md`（書きぶりの参考）

## 成果物
- `vault/rules/verifier/code-review.md`（新規の1ファイル）

## 受け入れ基準
- ルールの雛形の3見出しがそろっている：`grep -cx -e '## 目的' -e '## ルール' -e '## 確認方法' vault/rules/verifier/code-review.md` の出力が `3`
- 受け入れ基準が参照した時だけ効くと書かれている：`grep -c 'を参照している時だけ判定に使う' vault/rules/verifier/code-review.md` の出力が `1`
- 判定の本体をハーネス本体の節に任せると書かれている：`grep -c 'コードレビューを参照する基準の判定」節に従い' vault/rules/verifier/code-review.md` の出力が `1`
- 区分ごとの扱いが書かれている：`grep -c -e '.Must. 相当の指摘' -e '.Ask. 相当の指摘' -e '.Should. 相当の指摘' vault/rules/verifier/code-review.md` の出力が `3`
- 差分の外の指摘を FAIL の根拠にしないと書かれている：`grep -c '差分の外（既存コード）への指摘は、.Must. 相当でも FAIL の根拠にせず' vault/rules/verifier/code-review.md` の出力が `1`
- 規約チェックリストの指摘を `/code-review` の行に混ぜないと書かれている：`grep -c '.code-review. の行の判定には混ぜない' vault/rules/verifier/code-review.md` の出力が `1`

## 決定済み
- ファイル名は `vault/rules/verifier/code-review.md`。見出しは `# verifier ルール：/code-review の行を review-standards の区分に合わせて判定する` の後に `## 目的`・`## ルール`・`## 確認方法` の3つ（雛形 `vault/templates/rule.md` のとおり）
- 「## ルール」には次の箇条を、文言をこのとおりに書く（各項目は別の行）
  - 「このルールは、受け入れ基準の行がこのファイル（`vault/rules/verifier/code-review.md`）を参照している時だけ判定に使う」
  - 「範囲・呼び方・接頭辞などの判定の本体は `.claude/agents/verifier.md` の「コードレビューを参照する基準の判定」節に従い、ここには写さない」
  - 「[Must] 相当の指摘（差分で変えた行へのクラッシュ・データ破損・誤った結果）が残っていれば、その行を `ok: false` にする」
  - 「[Ask] 相当の指摘（直すのに設計・仕様の改訂が要る）は、その行を `ok: true` のまま、`人の判断が必要: ` で始まる要素を reasons に書く」
  - 「[Should] 相当の指摘（性能・保守性・テスト不足などの致命的でないもの）は FAIL の根拠にしない」
  - 「差分の外（既存コード）への指摘は、[Must] 相当でも FAIL の根拠にせず、`対象外（既存コード）: ` で始まる要素を note と reasons に書く」
  - 「規約（`.claude/skills/review-standards/references/code-review-checklist.md`）の指摘は、受け入れ基準の行がチェックリストを参照している時だけ判定に使い、`/code-review` の行の判定には混ぜない」
  - 「review-standards のタスクでも、`/code-review` の行の範囲はそのタスクの差分（計画ブランチとの分岐点から）で、review-standards の手順4の範囲（ジョブで変えた差分）に広げない」
  - 「区分の定義は `.claude/skills/review-standards/SKILL.md` の区分の表の下の [Must]・[Should]・[Ask] に従う」
- 「## 目的」は1〜2行で、「受け入れ基準の `/code-review` の行を、規約レビューの区分（Must/Should/Ask）と同じ物差しで判定する」旨を書く
- 「## 確認方法」には「verdict の `/code-review` の行の note に、実行した範囲と区分ごとの件数が書かれている」を書く
- 上の文言の「を参照している時だけ判定に使う」「.Should. 相当の指摘」「review-standards のタスクでも」などの句は、ファイルの中でそれぞれ1回だけ使う（ほかの箇条で同じ句を繰り返さない）
- `.claude/agents/verifier.md` の箇条（範囲のコマンド・呼べなかった時の扱いなど）は写さない。ハーネス本体のファイルは変えない
- 100行以内にする
