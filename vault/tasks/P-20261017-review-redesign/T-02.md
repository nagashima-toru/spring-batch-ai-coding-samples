# T-02 review-standards の手順4をハーネスの差分の扱いと整合させる

## 目的
規約レビューのスキル review-standards の手順4（組み込み `/code-review` の実行）に、レビューの範囲・指摘の区分（Must/Ask）・差分の外の指摘の扱いを、ハーネスの規則（`.claude/agents/verifier.md` の「コードレビューを参照する基準の判定」節）と食い違わない形で書く。

## 入力
- `.claude/skills/review-standards/SKILL.md`（T-01 で移したもの。「進め方」の手順4）
- `.claude/agents/verifier.md` の「コードレビューを参照する基準の判定」節・`.claude/agents/creator.md` の「コードレビューを参照する基準がある時」節（読むだけ）
- `docs/vault-spec.md` 11節「コードレビューを参照する受け入れ基準」（読むだけ）

## 成果物
- `.claude/skills/review-standards/SKILL.md`（1ファイル。「進め方」の手順4だけを変える）

## 受け入れ基準
- 手順4の1行目が残っている：`grep -c '^4. 同じ差分に対して、Claude Code 組み込みの' .claude/skills/review-standards/SKILL.md` の出力が `1`
- レビューの範囲がベースブランチとの分岐点からの差分として書かれている：`grep -c 'diff --merge-base main' .claude/skills/review-standards/SKILL.md` の出力が `1`
- 受け入れ基準の `/code-review` の行の範囲（タスクの差分）が区別して書かれている：`grep -c 'diff --merge-base work/' .claude/skills/review-standards/SKILL.md` の出力が `1`
- 差分内の致命的な指摘を [Must] にすると書かれている：`grep -c 'クラッシュ・データ破損・誤った結果の指摘は .Must. にする' .claude/skills/review-standards/SKILL.md` の出力が `1`
- 設計・仕様の改訂が要る指摘を [Ask] にすると書かれている：`grep -c '設計・仕様の改訂が要る指摘は .Ask. にする' .claude/skills/review-standards/SKILL.md` の出力が `1`
- 差分の外の指摘を直さず対象外として残すと書かれている：`grep -c '一覧の最後に .対象外（既存コード）: ' .claude/skills/review-standards/SKILL.md` の出力が `1`
- smoke が通り `(ref-1)` も ok：`bash scripts/smoke.sh 2>&1 | grep -c -e '^  ok   (ref-1) ' -e '^smoke: pass=[0-9]* fail=0'` の出力が `2`

## 決定済み
- 変えるのは「進め方」の手順4（`4. 同じ差分に対して、…` の行とその下の字下げした箇条）だけ。手順1〜3・5、区分の表と [Must]/[Should]/[Ask] の定義、「例外（パイプライン実行時）」、「最重要観点」は変えない
- 手順4の1行目（`4. 同じ差分に対して、Claude Code 組み込みの `/code-review`（Skill ツールの `code-review`）を必ず実行する。`）と、その次の「手順1〜3はチェックリスト（規約）の確認で、…両方を通す」の2行は今のまま残す
- 手順4の字下げした箇条は、次の内容に置き換える（文言はこのとおりに書く。各項目は別の行にする）
  - 「範囲は、レビュー対象のジョブで変えた差分（ベースブランチとの分岐点から。既定は main で、ベースブランチが main でなければその名前に読み替える）で、`git diff --merge-base main` の差分をレビューする。ハーネスのタスクでは、対象の worktree の絶対パスを引数で明示して渡し、その worktree で同じ差分をレビューする（明示しないと呼び出し元の作業ディレクトリをレビューする）」
  - 「この範囲は、ハーネスの受け入れ基準の `/code-review` の行（「`/code-review` で差分に致命的な指摘が残っていない」）の範囲とは別である。その行の範囲はそのタスクの差分（`git -C <worktree のパス> diff --merge-base work/<計画IDの英小文字>`）で、判定は `.claude/agents/verifier.md`・`.claude/agents/creator.md` に従う」
  - 「`/code-review` の指摘も下表の区分（Must/Should/Ask）に分類し直し、手順1〜3の指摘と1つの一覧にまとめる（出典列に `/code-review` と書く）」（今の文のまま）
  - 「差分で変えた行へのクラッシュ・データ破損・誤った結果の指摘は [Must] にする。設計書・決定事項どおりの実装でも、データの範囲や失敗経路で壊れる指摘は除外しない」
  - 「直すのに設計・仕様の改訂が要る指摘は [Ask] にする（ハーネスのタスクでは creator が直さず blocked にする）」
  - 「差分の外（既存コード）への指摘は直さず、一覧の最後に `対象外（既存コード）: <指摘の要約>` の形で除外理由を1行残す（ハーネスでは verifier が同じ接頭辞で verdict の reasons に書き、PR 作成時の取り出しの対象になる）」
  - 「そのほかに除外する指摘（事実誤認など）も、一覧の最後に理由を1行で残す」
- 今の「直すのに設計の改訂が要るものは [Ask] にする」という文と「除外する指摘（事実誤認・対象外）は、一覧の最後に理由を1行で残す」という文は、上の箇条に置き換わるので残さない
- 範囲を「ジョブで変えた差分（ベースブランチとの分岐点から）」にした理由：review-standards のタスクは implementation〜integration-test の後に置かれ、計画ブランチとの分岐点からの差分（そのタスク自身の変更）だけではレビューする対象のコードが入らないため。ハーネスの外（対話・sdd-pipeline）でも feature ブランチの分岐点からの差分で同じコマンドになる。差分の外はベースブランチにある既存コードを指す
- `diff --merge-base main` と `diff --merge-base work/` は手順4の中でそれぞれ1回だけ書く（ほかの箇所に書き足さない）
- `/code-review` の引数（`effort`・`--max-findings` など）の既定値は書かない
- ハーネス本体（`.claude/agents/`・`docs/vault-spec.md`）は変えない
