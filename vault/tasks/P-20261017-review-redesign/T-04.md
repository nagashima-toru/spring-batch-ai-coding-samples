# T-04 creator ルールに /code-review の指摘の区分の対応を書く

## 目的
creator が `/code-review` の指摘を扱う時の、このリポジトリ固有の補足（review-standards の区分 Must/Should/Ask との対応、規約チェックリストとの関係、差分の外の扱い、「進捗」への記録）を creator ルールに書く。ハーネス本体の手順は写さない。

## 入力
- `.claude/agents/creator.md` の「コードレビューを参照する基準がある時」節（読むだけ。写さない）
- `.claude/skills/review-standards/SKILL.md`（T-02 の後の手順4と、区分の表の下の [Must]/[Should]/[Ask] の定義）
- `vault/rules/creator/skill-workflow.md`（T-01 の後。review-standards のタスクの箇条。読むだけ）
- `vault/templates/rule.md`（見出し：目的 / ルール / 確認方法）

## 成果物
- `vault/rules/creator/code-review.md`（新規の1ファイル）

- ルールの雛形の3見出しがそろっている：`grep -cx -e '## 目的' -e '## ルール' -e '## 確認方法' vault/rules/creator/code-review.md` の出力が `3`
- 手順の本体をハーネス本体の節に任せると書かれている：`grep -c 'コードレビューを参照する基準がある時」節に従い' vault/rules/creator/code-review.md` の出力が `1`
- review-standards のタスクで規約と不具合の両方を通すと書かれている：`grep -c 'チェックリスト（規約）と手順4の' vault/rules/creator/code-review.md` の出力が `1`
- 手順4と受け入れ基準の行で範囲が違うことへの対処が書かれている：`grep -c 'タスクの差分でも実行する' vault/rules/creator/code-review.md` の出力が `1`
- 区分ごとの扱いが書かれている：`grep -c -e '.Must. 相当の指摘' -e '.Ask. 相当の指摘' -e '.Should. 相当の指摘' vault/rules/creator/code-review.md` の出力が `3`

## 決定済み
- ファイル名は `vault/rules/creator/code-review.md`。見出しは `# creator ルール：/code-review の指摘を review-standards の区分で扱う` の後に `## 目的`・`## ルール`・`## 確認方法` の3つ（雛形 `vault/templates/rule.md` のとおり）
- 「## ルール」には次の箇条を、文言をこのとおりに書く（各項目は別の行）
  - 「範囲・呼び方・回数などの手順の本体は `.claude/agents/creator.md` の「コードレビューを参照する基準がある時」節に従い、ここには写さない」
  - 「review-standards のタスクでは、手順1〜3のチェックリスト（規約）と手順4の `/code-review`（不具合）の両方を通す（PR #70 で、チェックリストだけでは不具合を拾えなかったため）」
  - 「review-standards の手順4の範囲（ジョブで変えた差分）と、受け入れ基準の `/code-review` の行の範囲（そのタスクの差分）は違う。受け入れ基準に `/code-review` の行がある時は、手順4で直した後に、タスクの差分でも実行する」
  - 「[Must] 相当の指摘（差分で変えた行へのクラッシュ・データ破損・誤った結果）は直す」
  - 「[Ask] 相当の指摘（直すのに設計・仕様の改訂が要る）は直さず、「進捗」に理由を書いて完了報告を `blocked: <質問文>` にする」
  - 「[Should] 相当の指摘は、review-standards のタスクでは直し、それ以外のタスクでは直さない」
  - 「差分の外（既存コード）への指摘は直さず、「進捗」に `対象外（既存コード）: <指摘の要約>` として残す」
  - 「「進捗」には、チェックリストと `/code-review` の指摘件数を出典ごとに分けて書く」
- 「## 目的」は1〜2行で、「`/code-review` の指摘を、規約レビューの区分（Must/Should/Ask）に合わせて直す・残す・人に渡すに振り分ける」旨を書く
- 「## 確認方法」には「「進捗」に、出典ごとの指摘件数と、対象外として残した指摘（あれば）が書かれている」を書く
- 上の文言の「チェックリスト（規約）と手順4の」「タスクの差分でも実行する」「.Must. 相当の指摘」などの句は、ファイルの中でそれぞれ1回だけ使う
- `vault/rules/creator/skill-workflow.md` は変えない（review-standards のタスクの箇条はそのまま。食い違いは無い：差分の外の指摘は手順4で区分に入らず除外されるので、[Must]/[Should] を直すという箇条と両立する）
- `.claude/agents/creator.md` の箇条（範囲のコマンド・もう1回だけ実行するなど）は写さない。ハーネス本体のファイルは変えない
- 100行以内にする
