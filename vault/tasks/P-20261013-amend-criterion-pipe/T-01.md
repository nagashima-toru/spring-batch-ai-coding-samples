# T-01 amend_task.py の --replace-criterion で基準文のパイプ記号を置き換えないようにし smoke で確かめる

## 目的
`--replace-criterion` で差し替えた受け入れ基準の `|` が `／` に置き換わり、確認コマンドのパイプが壊れる不具合（Issue #57）を直す。改行の除去だけを残す。

## 入力
- `scripts/amend_task.py`（216行付近の `lines[i] = "- %s%s" % (transition.clean_text(text), eol)`、冒頭の docstring の「やること」2）
- `scripts/transition.py` の `clean_text`（171行付近。参照のみ。変えない）
- `scripts/smoke.sh` の amend-task の節（2765行付近〜 `(amend-task) 06` まで。`am_run`・`am_task`・`tw_setup` の使い方）
- `docs/vault-spec.md` 75行目（`scripts/amend_task.py` の説明）
- `.claude/skills/plan/SKILL.md` 34〜35行目（参照のみ。変えない）

## 成果物
- `scripts/amend_task.py`（主な成果物。`--replace-criterion` の基準文の整形）
- `scripts/smoke.sh`（amend-task の節に確認を2つ追加）
- `docs/vault-spec.md`（2節の amend_task.py の説明に整形の仕方を補足）

## 受け入れ基準
- smoke が全件 OK で終わる：`bash scripts/smoke.sh 2>&1 | grep -c '^smoke: pass=[0-9]* fail=0'` が `1`
- smoke に追加した `|` をそのまま書く確認が OK になる：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (amend-task) 07 '` が `1`
- smoke に追加した改行を空白にして1行に収める確認が OK になる：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (amend-task) 08 '` が `1`
- `scripts/amend_task.py` が基準文の整形に `transition.clean_text` を使っていない：`grep -c 'clean_text(text)' scripts/amend_task.py` が `0`
- `docs/vault-spec.md` の amend_task.py の説明に整形の仕方が書かれている：`grep -c 'の改行は空白にし、' docs/vault-spec.md` が `1`
- 参照切れの検査が OK のまま：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`
- 成果物の3ファイルが変更されている：`git diff --merge-base work/p-20261013-amend-criterion-pipe --name-only -- scripts/amend_task.py scripts/smoke.sh docs/vault-spec.md` の出力が `docs/vault-spec.md`・`scripts/amend_task.py`・`scripts/smoke.sh` の3行

## 決定済み
- 整形の仕方：基準文 `text` は改行（`\r\n`・`\r`・`\n`）を半角空白1つに置き換えて前後の空白を除く（`transition.clean_text` から `|` の置き換えだけを外した挙動）。`|` を含むほかの文字はそのまま書く。実装は `amend_task.py` の中に小さな関数（名前は任意、例：`clean_criterion`）を作るか、その場で `re.sub(r"\r\n|\r|\n", " ", text).strip()` と書く。どちらでもよいが、`clean_text(text)` という文字列は `amend_task.py` に残さない
- `scripts/transition.py` は変えない（`clean_text` は計画票のタスク表の question セル用で、`|` の置き換えが要る）。差分ゲートで成果物外として差し戻される
- `--note`（`args.note_text = transition.clean_text(args.note) ...` の行。log 行に入る）と `--add-deliverable` の扱いは変えない
- `amend_task.py` 冒頭の docstring「やること」2 の `` `- <文>` の1行に置き換える `` の後ろに、「（<文> の改行は空白にし、`|` はそのまま書く）」の旨を足す（文言は任意）
- `docs/vault-spec.md` 75行目の「`--replace-criterion` は <番号> 番目の行を `- <文>` の1行に置き換え、」の直後に「<文> の改行は空白にし、`|` はそのまま書く（タスク表のセルではないので `／` に置き換えない）。」の文を足す。`の改行は空白にし、` の語はこのとおり書くこと（基準で grep する）。75行目以外は変えない
- smoke の追加位置：`(amend-task) 06` の `expect_eq` の直後、`# --- 主な文書の参照切れの検査 ---` の前。既存の 01〜06 は変えない
- smoke の追加内容：`tw_setup blocked 1` で作り直した状態に対して2つ確かめる
  - `(amend-task) 07`：`am_run P-TEST T-01 --replace-criterion 1 '<パイプを含む文>'`（例：`'bash scripts/x.sh 2>&1 | grep -c ok が 1'`）の後、終了コードが 0 で、受け入れ基準節の1行目が `- ` に続けて渡した文字列そのまま（`|` が残り `／` が無い）であることを `expect_eq` で確かめる。ラベルは `(amend-task) 07 --replace-criterion で | を含む基準がそのまま書かれる` とする
  - `(amend-task) 08`：改行を含む文（例：`$'前半\n後半'`）で `--replace-criterion 1` を実行し、終了コードが 0、1行目が `- 前半 後半`、受け入れ基準節の `- ` で始まる行数が差し替え前と同じであることを確かめる。ラベルは `(amend-task) 08 --replace-criterion で改行は空白になり基準の行数が変わらない` とする
  - 受け入れ基準節の1行目の取り出しは既存の 03 と同じ `sed -n '/^## 受け入れ基準/,/^## 決定済み/p' "$(am_task)" | grep -m1 '^- '` の形を使ってよい。期待値の比較は `grep -F`／`expect_eq` で行い、`|` が正規表現に解釈されないようにする
- `.claude/harness-manifest.json` は変えない（このリポジトリは導入先で、マニフェストは install で配った内容の記録。書き換えると次の `install.sh --update` で修正が黙って上書きされる）
- `(ref-1)` はこのリポジトリでは導入先として検査を省くため常に ok になるが、基準としては残す
- smoke は全体で1分ほどかかる。受け入れ基準の確認では毎回 smoke を実行してよい
