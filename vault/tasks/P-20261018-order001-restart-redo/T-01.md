## 決定済み
- 実装は詳細設計書 1.4 版を正とする。設計書と異なる実装が要ると判断したら、直さずに blocked にして question に書く（`docs/development-guide.md` §5.5）
- スキーマ・Flyway（`db/migration/`）・batch-core は変更しない
- `OrderDailySalesJobConfig`：
  - Step 1〜4 の各 `StepBuilder` に `.allowStartIfComplete(true)` を1回ずつ書く（ヘルパーにまとめない）。Step 5 には付けない。文字列 `allowStartIfComplete(true)` はこの4か所以外（Javadoc・コメント）に書かない
  - Step 4 の Reader は `CsvItemReaderFactory.createWithLineNumber(...)` の戻り値をローカル変数 `reader` に受け、`reader.setSaveState(false);` を呼んでから返す。理由のコメントは `Sample03JobConfig` に倣う（例：リスタート時もファイルの先頭から読み直す）。文字列 `setSaveState(false)` はこの1か所以外に書かない
  - `orderDailySalesClearWorkTasklet` を `@StepScope` にし、他の `@StepScope` の Bean と同じくジョブパラメータ4つ（`scheduledTime`・`targetDate`・`inputFile`・`errorFile`）と `SampleProperties`、`OrderDetailWorkMapper` を受け取り、`new OrderDetailWorkClearTasklet(runParameters(...).errorFile(), orderDetailWorkMapper)` を返す。戻り値の型は具象クラス `OrderDetailWorkClearTasklet`。結果として `@StepScope` の注釈は7個になる。`@StepScope` という文字列は注釈以外（Javadoc・コメント）に書かない
  - Step 4 の `processorListener`（`StepExecutionListener` への代入と `.listener(processorListener)`）を削除し、`StepExecutionListener` の import も消す
  - `orderDailySalesProcessor` の Bean メソッドから `OrderDetailWorkMapper` の引数を外し、`new OrderItemProcessor(validator, runParameters(...).targetDate())` にする
  - クラスの Javadoc の「行番号付き CSV 読取による重複検出（リスタート対応）」を、1.4 版の方式（リスタートは Step 1〜4 を最初からやり直す）に合う記述に直す。Step 3 の Javadoc は「エラーファイルを削除し、ワークテーブルを空にする」にする
- `OrderDetailWorkClearTasklet`：
  - `public class`（final にしない）。コンストラクタは `OrderDetailWorkClearTasklet(Path errorFile, OrderDetailWorkMapper orderDetailWorkMapper)` の順
  - `execute` の順：(1) `boolean deleted = Files.deleteIfExists(errorFile)`。`IOException` は `new SystemException("エラーファイルを削除できません: " + errorFile, e)` に包んで送出する（`SystemException` は `com.example.batch.core.exception.SystemException`）。削除に失敗した時は truncate を呼ばない (2) `orderDetailWorkMapper.truncate()`（Mapper の例外は包み直さない） (3) `log.info("受注明細ワークを初期化しました: errorFile={} 削除={}", errorFile, deleted)` (4) `RepeatStatus.FINISHED` を返す
  - ログのメッセージは `受注明細ワークを初期化しました: errorFile={} 削除={}` をそのまま書く。`Files.deleteIfExists` の呼び出しは1か所だけ
  - クラスの Javadoc を 1.4 版の処理（エラーファイルの削除→TRUNCATE。削除は Tx の外の操作で戻らないが、リスタートで作り直すため問題ない）に直す
- `OrderItemProcessor`：`implements StepExecutionListener`・`beforeStep`・`OrderDetailWorkMapper` のフィールドとコンストラクタ引数を削除する。コンストラクタは `OrderItemProcessor(Validator validator, LocalDate targetDate)`。既出キーの `Map<String, Integer>` はフィールド初期化で空から作る。クラスの Javadoc の「Step 開始時にワークテーブルから対応を復元する」記述を「`@StepScope` のため Step 実行ごとに空の対応から作る」趣旨に直す。重複判定（行番号が違えば重複、同じなら再処理）は変えない
- 削除：`OrderKey.java`（`git rm` 相当でファイルごと消す）、`OrderDetailWorkMapper#selectKeys` と不要になった `ResultHandler` の import、`OrderDetailWorkMapper.xml` の `selectKeys` の `<select>` とその直前のコメント
- テストの最小修正（新しい観点はT-02で足すので、ここでは足さない）：
  - `OrderItemProcessorTest.java`：コンストラクタを2引数にし、`// ---- beforeStep ----` 以降の beforeStep 関連のテスト・`stubKeys`・Mapper のモックと不要になった import を削除する。残りのテストは変えない
  - `OrderDetailWorkClearTaskletTest.java`：既存の3テストを新しいコンストラクタで動くようにする（エラーファイルには JUnit の `@TempDir` 配下の存在しないパスを渡す）。ログのテストは新しいメッセージ（`削除=false`）に合わせて期待値を直す。テストメソッド名は変えない
- 結合テスト（`OrderDailySalesJobIT`）は変えない。そのリスタートのテストは 1.4 版の動作で失敗するが、T-03 で書き直す（この基準は `-DskipITs` で結合テストを実行しない）
- ビルドには JDK 25 が要る。`./mvnw -v` が Java 25 でない時は `docs/development-guide.md` §1.4 の手順で用意する
