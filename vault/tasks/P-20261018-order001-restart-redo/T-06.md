## 決定済み
- レビューの範囲は、ベースブランチ（`HARNESS_BASE_BRANCH`、前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）とする
- 計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない
- 致命的な指摘が無ければ成果物を変えず、「進捗」への記録（実行した範囲と指摘の要約）だけでよい（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）
- 差分の外（既存コード）への指摘・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは、`.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節に従う。差分の外への指摘を直すタスクは起こさない
- `/code-review` には `effort`・`--max-findings` などの引数を付けない
- スキーマ・Flyway・batch-core は変更しない（詳細設計書 1.4 版の改訂範囲外）。直すのに設計書の改訂が要る指摘は直さず、blocked にして question に書く
- ビルドには JDK 25 と Docker が要る。無い時は `docs/development-guide.md` §1.4 の手順で用意する

## 進捗
- 読んだルール: vault/rules/common/project-docs.md, vault/rules/creator/code-review.md, vault/rules/creator/skill-workflow.md
- `/code-review` を1回実行（範囲: `git diff --merge-base main`、計画一式4種を除く。引数なし）。指摘6件。Must 0件・Ask 0件・Should 5件・対象外 1件。成果物は変更していない（再実行も不要）
- Should（直さない）: Tasklet のエラーファイル削除が毎回走る（詳細設計書 1.4 版 §Step 3 の仕様どおり）／Step 5 に targetDate 整合ガードが無い（現状の Step 1〜4 再実行で成立、将来の変更への懸念）／IT の startWithFailTrigger の try 範囲／ClearTaskletTest の配列キャプチャ／ST の env.sh の ST_BASE
- 対象外（既存コード）: ORDER-001.md の Step 4 行（75行目）の「Step 3 から作り直す」と 79行目・290-294行目の記述の食い違い（今回の差分に含まれない既存の記述）
- 確認結果: 基準2 `-DskipITs -Djacoco.haltOnFailure=false` の BUILD SUCCESS 数=1／基準3 batch-core=1／基準4 全体 verify=1／基準5 OrderDailySalesJobIT の `Failures: 0, Errors: 0, Skipped: 0` 数=1
