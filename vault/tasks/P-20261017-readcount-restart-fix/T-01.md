# T-01 sample05 解説の取得件数の数え方を Reader の読込位置基準に改訂する

## 目的
SSoT に従い、コードより先に解説 `batch-sample/docs/sample05-api-import.md` の取得件数の数え方を、StepExecution の読込件数の足し込みから、Reader が確定させた読込位置に基づく方式へ改訂する（Issue #79）。

## 受け入れ基準
- 新方式の説明がある：`grep -c 'Reader が確定させた読込位置（Step の ExecutionContext の .sample05UserReader.read.count.。.inputFile. 指定時は .sample05UserJsonReader.read.count.）' batch-sample/docs/sample05-api-import.md` が `1`
- COMPLETED 時に終端の読込1件を引くことの説明がある：`grep -c 'null が返る読込）も読込位置に1件として数えられるため、1を引く' batch-sample/docs/sample05-api-import.md` が `1`
- readCount を使わない理由の説明がある：`grep -c 'StepExecution の読込件数（readCount）は使わない' batch-sample/docs/sample05-api-import.md` が `1`
- Skip した件を取得件数に含める仕様が維持されている：`grep -c '読込位置は、入力チェックで Skip した件と読込時の例外で Skip した件も含む' batch-sample/docs/sample05-api-import.md` が `1`、かつ `grep -c '入力チェックで Skip した件も「取得した件」として数える' batch-sample/docs/sample05-api-import.md` が `1`
- 旧方式の記述が残っていない：`grep -c '読込件数＋読込 Skip 件数' batch-sample/docs/sample05-api-import.md` が `0`、かつ `grep -c '今回の件数を足して全体の取得件数にする' batch-sample/docs/sample05-api-import.md` が `0`

## 決定済み
- 改訂するのは「処理の流れ」節の `sample05.01ImportStep` の箇条のうち、今の「Step の終了時に、取得件数（読込件数＋読込 Skip 件数）を Job の ExecutionContext の `apiUserReadCount` に足し込む。取込 Step の途中失敗からリスタートすると Reader は続きから読むため、前回の実行で取得した件数に今回の件数を足して全体の取得件数にする」の2行。この2行を消し、同じ箇条の中（インデント2空白の継続行、または入れ子の箇条）に次の文をこの文言のまま書く（バッククォートも含めて一字一句同じにする。各文は文書中に1回だけ書く）
  - 「Step の終了時に、取得件数を Job の ExecutionContext の `apiUserReadCount` に保存する（前回の値は上書きする）。」
  - 「取得件数は、取込 Step の Reader が確定させた読込位置（Step の ExecutionContext の `sample05UserReader.read.count`。`inputFile` 指定時は `sample05UserJsonReader.read.count`）から求める。」
  - 「読込位置はチャンクのコミット時に保存されるため、途中で失敗した実行ではコミット済みの件数と一致する（最初のチャンクで失敗した時は読込位置が無く、0件とする）。リスタートでは前回の読込位置が引き継がれて続きから数えるため、前回の件数に足し込まない。」
  - 「Step が COMPLETED の時は、データの終端を確かめる最後の読込（null が返る読込）も読込位置に1件として数えられるため、1を引く。」
  - 「読込位置は、入力チェックで Skip した件と読込時の例外で Skip した件も含む（どちらも Reader から読んだ件として数えられる）。」
  - 「StepExecution の読込件数（readCount）は使わない。Spring Batch 6 では、失敗した実行の readCount にロールバックしたチャンクの読込件数も入ることがあり、リスタート後の合計が水増しされて件数の突き合わせが失敗するため（Issue #79）。」
- `sample05.02CountCheckStep` の箇条にある既存の文「入力チェックで Skip した件も「取得した件」として数える（Skip は終了コード2で別途知らせる）。」は変えずに残す
- 上記以外の節・箇条（デモする機能・設定・実行方法・リトライ方針など）は変えない
- 読込位置のキーの実際の名前は計画の作成時に確かめた（`AbstractItemCountingItemStreamItemReader` が Reader 名に `.read.count` を付けたキーで保存する。Reader 名は `Sample05JobConfig` の `sample05UserReader`・`sample05UserJsonReader`）。キーの名前を変える判断はしない
- 旧方式の記述の確認範囲は、このタスクでは解説1ファイル。リスナーの Javadoc に残る旧方式の記述は T-02 で直し、T-02 がリポジトリの `batch-sample`・`docs` 全体で確かめる（`vault/` は計画票・タスク票が旧方式の文言を引用しているため対象外）
- ビルドは不要（文書だけの変更）
