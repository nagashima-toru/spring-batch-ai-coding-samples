# T-05 計画の差分が `/code-review` を通過する

## 目的
計画全体（T-01〜T-04）の差分を `/code-review` で確かめ、致命的な指摘を直したうえで、計画全体の動作（ビルド・結合テスト・古い記述が残っていないこと）を壊していないことを確かめる。

## 入力
- 計画全体の差分：`git -C <worktree のパス> diff --merge-base <ベースブランチ>`
- `vault/rules/verifier/code-review.md`（判定の区分）
- `.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節

## 成果物
- 計画の差分への修正（主な成果物）。直してよいのは先行タスクで宣言した次のファイルだけ
- `batch-sample/docs/sample05-api-import.md`
- `batch-sample/docs/README.md`
- `.claude/skills/implementation/SKILL.md`
- `batch-core/src/main/java/com/example/batch/core/item/CountingItemStreamReader.java`
- `batch-core/src/test/java/com/example/batch/core/item/CountingItemStreamReaderTest.java`
- `batch-sample/src/main/java/com/example/batch/sample/job05_api_import/ApiUserReadCountListener.java`
- `batch-sample/src/main/java/com/example/batch/sample/job05_api_import/Sample05JobConfig.java`
- `batch-sample/src/test/java/com/example/batch/sample/job05_api_import/ApiUserReadCountListenerTest.java`
- `batch-sample/src/test/java/com/example/batch/sample/job05_api_import/Sample05ApiImportJobIT.java`

## 受け入れ基準
- `/code-review` で計画の差分に致命的な指摘が残っていない（`vault/rules/verifier/code-review.md` に従って判定する）
- 結合テストと batch-sample のカバレッジ80%を含む全体のビルドが成功する：`./mvnw clean verify 2>&1 | grep -c 'INFO. BUILD SUCCESS'` の出力が `1`
- batch-core のカバレッジ80%を含むビルドが成功する：`./mvnw clean verify -DskipITs -pl batch-core 2>&1 | grep -c 'INFO. BUILD SUCCESS'` の出力が `1`
- 全モジュールの静的解析と単体テストが成功する：`./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false 2>&1 | grep -c 'INFO. BUILD SUCCESS'` の出力が `1`
- 終端の読込を差し引く記述が batch-sample・docs に残っていない：`grep -rn --include='*.java' --include='*.md' -e '1を引' -e '1件を引' batch-sample docs` の出力が空
- smoke の参照検査が通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`

## 決定済み
- レビューの範囲は、ベースブランチ（`HARNESS_BASE_BRANCH`、前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）とする
- 計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない
- 致命的な指摘が無ければ成果物を変えず、「進捗」への記録だけでよい（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）
- 差分の外（既存コード）への指摘・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは、`.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節に従う。差分の外への指摘を直すタスクは起こさない（`vault/rules/planner/code-review-criterion.md`）
- 直す時も、取得件数の数え方（`CountingItemStreamReader` が Reader の返した null 以外の件数をコミットごとに `<名前>.item.count` へ保存し、`ApiUserReadCountListener` が状態を問わずそのまま `apiUserReadCount` に上書きする）と、解説（`batch-sample/docs/sample05-api-import.md`）の記述は変えない。変える必要がある指摘は設計の変更なので、上の節に従って扱う
- 範囲外：#82 の「書込 Skip 後のリスタートで未書込の件を取りこぼす」問題は、指摘されても直さない（計画票の分割方針）
- `./mvnw clean verify` には Docker と JDK 25 が要る（`docs/development-guide.md` §1.4）
