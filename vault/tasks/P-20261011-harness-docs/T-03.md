## 成果物

## 受け入れ基準
- `docs/decisions.md` があり、見出し行 `# 決定事項` と表のヘッダ行 `| 決めたこと | なぜ | 出典 |` がある（`grep -c -x -F '# 決定事項' docs/decisions.md` が `1`、`grep -c -x -F '| 決めたこと | なぜ | 出典 |' docs/decisions.md` が `1`）
- 出典が D-20261011-spring-batch-adapt のデータ行がちょうど4行ある（`grep -c '| D-20261011-spring-batch-adapt |$' docs/decisions.md` が `4`）
- 決定済みの4件がそれぞれ1行ずつ載っている（`grep -c -F './mvnw verify -DskipITs' docs/decisions.md`・`grep -c -F 'vault/rules/' docs/decisions.md`・`grep -c -F 'permissions.allow' docs/decisions.md`・`grep -c -F '[Ask]' docs/decisions.md` がいずれも `1`）
- 削除される設計文書のパスを書いていない（`grep -c 'vault/designs/' docs/decisions.md` が `0`）

## 決定済み
- ファイルの構成：1行目 `# 決定事項`、続けて「このリポジトリで決めたことのうち docs の本文に無いものを1件1行で残す。新しい決定は表の末尾に追記する」旨の1〜2文、その後に表（ヘッダ `| 決めたこと | なぜ | 出典 |`、区切り行 `|---|---|---|`）
- 表のデータ行は次の4件だけ（設計文書の「決定事項」表の該当行の「決めたこと」「なぜ」を要約して書く）。出典列はどの行も `D-20261011-spring-batch-adapt` と書き、行末を `| D-20261011-spring-batch-adapt |` で終える
  1. 全タスクの受け入れ基準に `./mvnw verify -DskipITs` の成功を入れ、結合テスト（`*IT.java`）を成果物に含むタスクだけ `./mvnw verify` の成功も入れる（この行に `./mvnw verify -DskipITs` の語を書く）
  2. `vault/rules/` は docs を正本にした薄いルールにし、どの docs を読むかと要点だけを書く（この行に `vault/rules/` の語を書く）
  3. `.claude/settings.json` の `permissions.allow` に `Bash(./mvnw *)`・`Bash(docker compose *)`・`Bash(docker info*)` を足す（この行に `permissions.allow` の語を書く）
  4. creator が Skill のユーザー確認の手順に当たった時は `sdd-pipeline` の読み替え表に従い、`[Ask]` に当たるものは独断せず blocked にする（この行に `[Ask]` の語を書く）
- 上の4語（`./mvnw verify -DskipITs`・`vault/rules/`・`permissions.allow`・`[Ask]`）は、それぞれ該当する1行にだけ書き、表の外の文や他の行には書かない（確認コマンドが各1を期待するため）
- 載せない決定事項と理由：「要件定義〜設計レビューはハーネスに載せない」「implementation〜system-test を creator・verifier が担う」「`sdd-pipeline` を残して併存させる」「モデル昇格はハーネスでは使わない」は T-01 が `docs/development-guide.md` に書くので載せない。「`docs/decisions.md` を新規作成する」はこのファイル自体の存在で表されるので載せない
- 設計文書は T-04 で削除されるので、`vault/designs/` で始まるパスを書かない。出典は ID（`D-20261011-spring-batch-adapt`）だけで示す
- 文章は日本語で書く
