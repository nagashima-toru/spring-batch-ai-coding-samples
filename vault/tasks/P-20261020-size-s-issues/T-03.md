# T-03 #73 ByteLengthLineAggregator・Tokenizer が表せない文字で BusinessException を投げる

## 目的
Issue #73 を解決する。`ByteLengthLineAggregator` が `String.getBytes(charset)` で、文字コードで表せない文字を黙って `?` に置き換えて固定長ファイルに出す問題を直し、表せない文字があれば項目と値の分かる `BusinessException` にする。読込側の `ByteLengthLineTokenizer` も同じ方針にそろえる。

## 決定済み
- 書込側（`ByteLengthLineAggregator#aggregate`）：各フィールド値を `value.getBytes(charset)` ではなく、`charset.newEncoder()` に `onMalformedInput(CodingErrorAction.REPORT)` と `onUnmappableCharacter(CodingErrorAction.REPORT)` を設定したエンコーダで `CharBuffer.wrap(value)` をエンコードしてバイト列にする。エンコーダはスレッドセーフでないので、フィールド（または aggregate の呼び出し）ごとに `newEncoder()` で作り、フィールドに持たない
- `CharacterCodingException` が出たら、原因の例外を cause に付けて `BusinessException` を投げる。メッセージは `"出力文字コード %s で表せない文字を含むフィールド値です: index=%d value=%s".formatted(charset.name(), i, value)`（`i` は0始まりのフィールドの位置。このクラスはフィールド名を持たないので位置で示す）。表せるかの検査はバイト長超過の検査より先に行う。バイト長超過のメッセージ・`pad` の拡張ポイントは変えない
- 読込側（`ByteLengthLineTokenizer#tokenize`）も同じ方針にする：行全体の `line.getBytes(charset)` を、書込側と同じ REPORT のエンコーダでのエンコードに替え、`CharacterCodingException` なら cause を付けて `BusinessException`（メッセージ `"入力文字コード %s で表せない文字を含む行です: line=%s".formatted(charset.name(), line)`）を投げる。理由：Reader は文字コードとして不正なバイト列を U+FFFD に置き換えて渡し、`getBytes` はそれを黙って `?` にするため、壊れた行がバイト長の検査をすり抜けうる。`BusinessException` なので Skip 対象として扱える。フィールド境界の検査（デコード→再エンコードの比較）とバイト長の検査は今のまま
- 共通のユーティリティクラスは作らない（各クラスの private メソッドで足りる。新しいファイルを増やさない）
- 両クラスのクラス Javadoc に、表せない文字は `BusinessException` になる旨を1文足す
