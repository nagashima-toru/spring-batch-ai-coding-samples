# T-05 計画の差分が `/code-review` を通過する

## 目的
計画単位のレビュータスク。T-01〜T-04（Issue #77・#75・#73・#63）の変更をまとめた計画全体の差分を `/code-review` で確かめ、致命的な指摘を直し、修正で計画全体の動作を壊していないことを確かめる。

## 入力
- 計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）
- `vault/tasks/P-20261020-size-s-issues/T-01.md`〜`T-04.md` の「決定済み」（指摘が設計どおりかの判断に使う）
- `.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節
- `vault/rules/verifier/code-review.md`

## 受け入れ基準
- `/code-review` で計画の差分に致命的な指摘が残っていない（`vault/rules/verifier/code-review.md` に従って判定する）
- `./mvnw clean verify 2>&1 | grep -c 'BUILD SUCCESS'` の出力が `1`（全モジュールの単体テスト・結合テスト・静的解析・batch-sample のカバレッジ80%。Docker が要る）
- `./mvnw clean verify -DskipITs -pl batch-core 2>&1 | grep -c 'BUILD SUCCESS'` の出力が `1`（batch-core のカバレッジ80%）
- `./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false 2>&1 | grep -c 'BUILD SUCCESS'` の出力が `1`
- 古い記述が残っていない：`git grep -n 'Bean にしない' -- batch-sample docs` の出力が空、かつ `git grep -n '一致しないため不一致になる' -- batch-core batch-sample docs` の出力が空、かつ `git grep -n 'に置き換える' -- batch-core/src batch-sample/docs batch-sample/src/main/java/com/example/batch/sample/job03_file_export` の出力が空

## 決定済み
- レビューの範囲は、ベースブランチ（環境変数 `HARNESS_BASE_BRANCH`。前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）とする
- 計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない
- 致命的な指摘が無ければ成果物を変えず、「進捗」への記録だけでよい（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）
- 差分の外（既存コード）への指摘・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは、`.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節に従う。差分の外への指摘を直すタスクは起こさない
- 指摘を直す時も、T-01〜T-04 の「決定済み」で決めた方針（BOM は1行目の先頭の1文字だけ取り除く・読込側の `CsvItemReaderFactory` は変えない・ログの文言とロガー名を変えない・表せない文字は `BusinessException`・本体コードを変えずにテストを足す、など）は変えない。方針そのものを変える必要がある指摘は人に渡す（blocked）
- ビルドの3つの確認は、`/code-review` の修正を入れた後の状態で実行する。`./mvnw clean verify` は Docker が要る（`vault/rules/verifier/build-verification.md`）
