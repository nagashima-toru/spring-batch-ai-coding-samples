# T-02 #75 ORDER-001 の実行時パラメータを @JobScope Bean で1回だけ解決する

## 目的
Issue #75 を解決する。`OrderDailySalesJobConfig` の Step スコープの Bean 7つがそれぞれ同じジョブパラメータを受け取って `runParameters(...)` を呼び、既定値の解決と「実行時パラメータを確定しました」の INFO ログが1回の実行で何度も出る問題を直し、解決とログを1回の JobExecution につき1回にする。

## 決定済み
- 新規クラス `OrderDailySalesRunParametersHolder`（パッケージ `com.example.batch.sample.job_order_daily_sales`）：public で final にしないクラス。`private final OrderDailySalesRunParameters value` を持ち、コンストラクタ `OrderDailySalesRunParametersHolder(OrderDailySalesRunParameters value)` と、final にしないメソッド `public OrderDailySalesRunParameters get()` だけを持つ。record は final でスコーププロキシ（クラスを継承して作る）を作れないため、record を包むこのクラスを `@JobScope` の Bean にする。Javadoc（日本語）にこの理由を書く
- `OrderDailySalesJobConfig` に `@Bean @JobScope public OrderDailySalesRunParametersHolder orderDailySalesRunParameters(...)` を足す。引数は今の Step スコープの Bean と同じ4つのジョブパラメータ（`@Value("#{jobParameters['scheduledTime']}") String`・`['targetDate']` の `LocalDate`・`['inputFile']` の `String`・`['errorFile']` の `String`）と `SampleProperties`。中で `OrderDailySalesRunParameters.resolve(...)` を1回呼び、今と同じ文言・同じロガー（`OrderDailySalesJobConfig` の `log`）で `log.info("実行時パラメータを確定しました: targetDate={} inputFile={} errorFile={}", ...)` を1回出してから holder を返す（`docs/projects/order-daily-sales/system-test/scenarios.md` がこのログの文言とロガー名を参照しているため変えない）
- `@JobScope` は `org.springframework.batch.core.configuration.annotation.JobScope`（Spring Batch 6.0.5 で確認済み）を使う
- private static メソッド `runParameters(...)` は削除する。Step スコープの Bean メソッド7つ（`orderDailySalesFileCheckTasklet`・`orderDailySalesHeaderCheckTasklet`・`orderDailySalesClearWorkTasklet`・`orderDailySalesReader`・`orderDailySalesProcessor`・`orderDailySalesErrorRecordSkipListener`・`orderDailySalesReplaceTasklet`）から4つのジョブパラメータと、パラメータの解決にだけ使っていた `SampleProperties` の引数を外し、代わりに `OrderDailySalesRunParametersHolder orderDailySalesRunParameters` を受け取って `orderDailySalesRunParameters.get()` の値を使う。7つの Bean のスコープ（`@StepScope`）・Bean 名・生成する部品・それ以外の引数（`Validator`・Mapper など）は変えない
- `#{jobParameters['scheduledTime']}` は `OrderDailySalesJobConfig` の中で `orderDailySalesRunParameters` の引数の1か所にだけ書く（Javadoc・コメントにも書かない。クラス Javadoc の実行方法の例の `scheduledTime=...` は形が違うので残してよい）
- リスタート（新しい JobExecution）では `@JobScope` の Bean が作り直されるので、解決とログは JobExecution ごとに1回になる。これで正しい（日付は `scheduledTime` から導くのでリスタートでも値は変わらない）
- `OrderDailySalesRunParameters` の Javadoc の「record は final クラスでスコーププロキシを作れないため Bean にしない。値が必要な Bean メソッドは resolve を呼んで使う」の趣旨の文を、「record は final クラスでスコーププロキシを作れないため、`OrderDailySalesRunParametersHolder` に包んで `@JobScope` の Bean にする」の趣旨に直す。補完規則を resolve だけに置く点は残す。「Bean にしない」の語は batch-sample・docs のどこにも書かない
- 結合テスト：`OrderDailySalesJobIT` にテストメソッド `正常に実行した場合＿実行時パラメータ確定のログは1回だけ出力される` を1つ足す。Spring Boot の `OutputCaptureExtension`（`org.springframework.boot.test.system`）を `@ExtendWith` で付け、引数の `CapturedOutput` で、既存の正常系テストと同じ手順の入力ファイルでジョブを1回実行した後の出力に「実行時パラメータを確定しました」がちょうど1回含まれることを確かめる（終了状態が COMPLETED であることも確かめる）。既存のテストメソッドは変えない
- 詳細設計書 `ORDER-001.md` を改訂する（実装より先に設計を直すのが規約。同じタスクの中で両方を直す）：
  - §1.1 の「実行時パラメータの確定」：「この record は Bean にしない」以下の2つの箇条を、「record を包む `OrderDailySalesRunParametersHolder` を `@JobScope` の Bean `orderDailySalesRunParameters` にし、ジョブパラメータ4つと `SampleProperties` を受け取って resolve を1回呼び、補完した3つの値を INFO ログに1回出す。値が必要な `@StepScope` の Bean メソッドはこの Bean を受け取る」の趣旨に直す
  - Bean 一覧の表に `orderDailySalesRunParameters`（型 `OrderDailySalesRunParametersHolder`、スコープ `@JobScope`）の行を足す。「`@StepScope` で生成するクラスは final にしない」の注記に、`@JobScope` の `OrderDailySalesRunParametersHolder` も final にしない旨を足す
