## 決定済み
- 直し方：`readFirstLine()` で読んだ1行目の先頭の1文字が U+FEFF なら、その1文字だけを取り除いてからカンマで分割して比べる。2文字目以降・2列目以降の U+FEFF は取り除かない。トリムなど、ほかの比べ方は今のまま（完全一致）
- 不一致の時の `BusinessException` のメッセージの「実際=」には、BOM を取り除いた後の行を出す。空ファイルの判定（`firstLine == null`）は今のまま
- BOM だけの1行（U+FEFF の1文字だけ）は、取り除くと空文字になり、期待値と一致しないので今のとおり「ヘッダ行が想定と異なります」の `BusinessException` になる（特別扱いしない）
- クラスの Javadoc の「BOM 付きファイルは先頭項目が一致しないため不一致になる。」の文を消し、次の文をそのまま（途中で改行せず1行に）書く：先頭の BOM（U+FEFF）を取り除いてから比べる。続けて、読込側との関係を1〜2文で書く（`CsvItemReaderFactory` は BOM を取り除かないが、ヘッダ行を `linesToSkip=1` で読み飛ばすので BOM の影響を受けない、という内容）
- 読込側（`CsvItemReaderFactory`）は変えない。Spring Batch 6.0.5 の `FlatFileItemReader` は BOM を取り除かないが、このリポジトリで `CsvItemReaderFactory` を使う3ジョブ（sample01・sample06・ORDER-001）はすべて `linesToSkip=1` でヘッダ行を読み飛ばすため、BOM はデータ行に入らない。「読込側とそろえる」は、BOM 付きのファイルがヘッダチェックも読込も通る状態にそろえることとする。ヘッダ行の無い（`linesToSkip=0`）BOM 付きファイルの扱いはこのタスクの対象外（Issue の範囲外のため）
- テスト：既存の `BOM付きファイルの場合＿先頭項目が一致せずBusinessExceptionをスローする` を、`BOM付きファイルの場合＿BOMを除いて比較し一致すればFINISHEDを返す`（BOM＋期待どおりの項目名で `RepeatStatus.FINISHED` が返る）に置き換える。加えて `BOM付きで項目名が異なる場合＿BusinessExceptionをスローする` を足し、`hasMessageContaining("ヘッダ行が想定と異なります")` で確かめる。BOM は Java の文字列リテラルで `﻿` と書く（ソースに不可視文字を直接書かない）
- テストは JUnit 5＋AssertJ、メソッド名は日本語の「条件＿期待結果」、AAA 構造（`docs/coding-standards.md` §7）。既存のヘルパー（`csv(...)`・`tasklet(...)`）を使う

  - §5 のエラー一覧の5行目の「（空ファイル・BOM 付き含む）」を「（空ファイル含む。BOM 付きは BOM を除いて照合する）」に直す（「BOM 付き含む」の語を残さない）
