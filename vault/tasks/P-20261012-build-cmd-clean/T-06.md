# T-06 development-guide の §3・§4 のビルドコマンドを clean 付きにそろえ、ゴール範囲の残存を確かめる

## 目的
PR テンプレートと対になる `docs/development-guide.md` の §3（ブランチ運用・PR）と §4（新しいジョブを追加するときのチェックリスト）の `./mvnw verify` を `./mvnw clean verify` にそろえ、ゴールの範囲（工程 Skill・PR テンプレート）に `./mvnw verify` が残っていないことを確かめる（Issue #45）。

## 入力
- `docs/development-guide.md`（181行目付近の §3 手順3、191行目付近の PR テンプレートの表、210行目付近の mermaid 図、224行目付近の §4 チェックリスト）
- T-01〜T-05 で直した工程 Skill と PR テンプレート（確認のみ）

## 成果物
- `docs/development-guide.md`（1ファイル）

## 受け入れ基準
- `grep -n 'mvnw verify' docs/development-guide.md` の出力が29・35・36行目の3行だけ（§1 の記述。このタスクの対象外）
- `grep -c 'mvnw clean verify' docs/development-guide.md` が `5`（§2.4 の既存1行と、§3 手順3・§3 の表・§3 の mermaid 図・§4 チェックリストの4行）
- `grep -rn 'mvnw verify' .claude/skills .github/pull_request_template.md .github/PULL_REQUEST_TEMPLATE` の出力が空（ゴールの範囲に clean の無い `./mvnw verify` が残っていない）
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`

## 決定済み
- §3 手順3・§3 の PR テンプレートの表（実装 PR の行）・§3 の mermaid 図（`D[./mvnw verify]` のノード）・§4 チェックリストの4か所を `./mvnw clean verify` に置き換える。mermaid のノードは `D[./mvnw clean verify]` にする
- 各か所は1行に `./mvnw clean verify` を1回だけ書き、同じ行に2回書かない（`grep -c` の期待値 `5` を保つ）。`clean` の理由を足す場合は §3 手順3 の行の中に書く
- §1.2・§1.3 の `./mvnw verify`・`./mvnw verify -DskipITs`（29・35・36行目）は変えない。人向けのよく使うコマンド一覧で Issue #45 の範囲外のため（計画票の「次フェーズの候補」に回した）。行番号がずれないよう、§1 より前の行は増減させない
- §2.4 の表（167行目付近）は既に clean 付きなので変えない
- ゴールの範囲の確認から除くもの：`.github/workflows/`（CI は毎回クリーンなチェックアウトで判定がぶれない）、`docs/decisions.md`（過去の決定の記録）、`README.md`・`CLAUDE.md`（人向けのコマンド一覧で範囲外）
- `.claude/skills` 配下や `.github` 配下で `./mvnw verify` が見つかった場合は、このタスクでは直さず `blocked` にして question に該当箇所を書く（成果物外のため）

- 読んだルール: vault/rules/common/project-docs.md, vault/rules/creator/skill-workflow.md
- docs/development-guide.md の181・191・210・224行目を ./mvnw clean verify に置換
- 確認: grep mvnw verify=29/35/36行のみ、clean verify 件数=5、skills/.github の残存=空、smoke ref-1 ok=1
