# T-01 unit-test Skill のビルドコマンドを clean 付き・カバレッジ判定の分離にそろえる

## 目的
unit-test Skill のカバレッジ確認ループ（手順5）と「カバレッジ」節のビルドコマンドを、`clean` 付きで batch-sample のカバレッジを `-DskipITs` で判定しない形にそろえる（Issue #45）。

## 入力
- `.claude/skills/unit-test/SKILL.md`（36行目付近の手順5、54行目付近の「カバレッジ」節）
- `vault/rules/verifier/build-verification.md`（3コマンドの使い分けの正本）
- `docs/decisions.md`（11行目・13行目の決定）

## 成果物
- `.claude/skills/unit-test/SKILL.md`（1ファイル）

## 受け入れ基準
- `grep -n 'mvnw verify' .claude/skills/unit-test/SKILL.md` の出力が空（clean の無い `./mvnw verify` が残っていない）
- `grep -c 'mvnw clean verify -DskipITs -pl batch-core' .claude/skills/unit-test/SKILL.md` が1以上
- `grep -c 'mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false' .claude/skills/unit-test/SKILL.md` が1以上
- `grep -c 'batch-sample のカバレッジ80%は' .claude/skills/unit-test/SKILL.md` が1以上
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`

## 決定済み
- 手順5（検証ループ（カバレッジ））は、対象モジュールで書き分ける。batch-core は `./mvnw clean verify -DskipITs -pl batch-core` で閾値を確認する。batch-sample は `./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false` を実行し、`batch-sample/target/site/jacoco/` で対象ジョブのクラスの未到達箇所を確かめてケースを追加する。未達時の扱い（観点表に基づく意味のあるケースを追加、最大2ラウンド）は今の文のまま残す
- 手順5に「batch-sample のカバレッジ80%は `/integration-test` の `./mvnw clean verify` で判定する」という文を書く（受け入れ基準の grep 対象。「batch-sample のカバレッジ80%は」の文字列をそのまま含める）。理由（モジュール全体で判定し、既存ジョブの多くは結合テストでしか網羅されないため `-DskipITs` では必ず落ちる）を短く添えてよい
- `clean` を付ける理由（`target/` に残った JaCoCo の実行データで結果が変わらないようにするため）を手順5に1文で書く
- 「カバレッジ」節の `./mvnw verify` は `./mvnw clean verify` にする（閾値チェックで強制する、の意味は変えない）
- 手順4の `./mvnw test -pl {module}` は変えない（JaCoCo の閾値チェックは verify フェーズで、test では動かないため）
- 旧コマンドの `-am` は付けない（batch-core は他モジュールに依存せず、batch-sample は全モジュールのビルドで扱うため）
- `{module}` のような波括弧入りの表記は refcheck の対象外なので残してよい。新しいパスをバッククォートで書く時は実在するものだけにする
- `vault/rules/verifier/build-verification.md`・`docs/decisions.md` は変更しない
