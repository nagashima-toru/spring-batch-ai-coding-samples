# T-02 integration-test Skill のビルドコマンドを clean 付き・カバレッジ判定の分離にそろえる

## 目的
integration-test Skill の検証ループ（手順4）と「注意」節のビルドコマンドを、`clean` 付きで、Docker なしの確認では batch-sample のカバレッジを判定しない形にそろえる（Issue #45）。

## 入力
- `.claude/skills/integration-test/SKILL.md`（25行目付近の手順4、58行目付近の「注意」節）
- `vault/rules/verifier/build-verification.md`（3コマンドの使い分けの正本）
- `docs/decisions.md`（11行目・13行目の決定）

## 成果物
- `.claude/skills/integration-test/SKILL.md`（1ファイル）

## 受け入れ基準
- `grep -n 'mvnw verify' .claude/skills/integration-test/SKILL.md` の出力が空（clean の無い `./mvnw verify` が残っていない）
- `grep -c 'mvnw clean verify' .claude/skills/integration-test/SKILL.md` が2以上（手順4と「注意」節）
- `grep -c 'mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false' .claude/skills/integration-test/SKILL.md` が1以上
- `grep -c 'では batch-sample のカバレッジを判定しない' .claude/skills/integration-test/SKILL.md` が1以上
- `bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`

## 決定済み
- 手順4の `./mvnw verify` は `./mvnw clean verify` にする。batch-sample のカバレッジ80%はこの工程の `./mvnw clean verify` で判定することを1文で添える
- 「注意」節の「Docker が必要（`./mvnw verify`。急ぎのビルドは `-DskipITs`）」は、Docker が必要なのは `./mvnw clean verify` であること、Docker なしで確かめる時は `./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false` と `./mvnw clean verify -DskipITs -pl batch-core` を使うこと、「`-DskipITs` では batch-sample のカバレッジを判定しない」ことを書く（受け入れ基準の grep 対象。「では batch-sample のカバレッジを判定しない」の文字列をそのまま含める）
- `clean` を付ける理由（`target/` に残った JaCoCo の実行データで結果が変わらないようにするため）を1文で書く
- 手順4の失敗時の読み先（`{module}/target/failsafe-reports/`）と Docker 起動のエスカレーションの文は変えない
- 新しいパスをバッククォートで書く時は実在するものだけにする
- `vault/rules/verifier/build-verification.md`・`docs/decisions.md` は変更しない

## 進捗
- 読んだルール: vault/rules/common/project-docs.md, vault/rules/creator/skill-workflow.md
- .claude/skills/integration-test/SKILL.md の手順4と「注意」節を clean 付きに修正した
- 受け入れ基準5行の確認コマンドを実行し全て通った（mvnw verify は出力空、clean verify 5行、haltOnFailure=false 1、判定しない文言 1、smoke ref-1 は 1）
