# T-01 sample03 の tempDir の不正なパスを起動時に拒否し空白だけを未指定として扱う

## 目的
sample03 の任意パラメータ `tempDir` に NUL 文字などパスとして解釈できない値を渡した時に `InvalidPathException` のまま出ず `InvalidJobParametersException` で起動を拒否し、空白だけの値を未指定（配置先の親ディレクトリ配下の `tmp/`）として扱う（GitHub Issue #107 の前半2点）。

## 決定済み
- 空白だけの `tempDir` は拒否せず未指定として扱う。sample05 の `inputFile`（`InputSourceDecider.isFileInput` の `isBlank()`）に合わせる。`tempOutputOf` の判定を `tempDir == null || tempDir.isBlank()` にする（`isEmpty()` から置き換える）。前後に空白がある空白だけでない値は、trim せずそのまま `Path.of` に渡す（今回の範囲外）
- `tempOutputOf` の `@param tempDir` の説明は「一時ディレクトリ（null・空文字・空白だけなら配置先の親ディレクトリ配下の tmp/ に同名で置く）」にする（`null・空文字なら` の並びを残さない）。クラス Javadoc に書き足す必要は無い
- パスとして解釈できない値（`Path.of` が投げる `java.nio.file.InvalidPathException`）は、`validateTempOutput` で `SystemException` と同じく捕まえて `InvalidJobParametersException` に変換する。`outputFile` も `tempOutputOf` の中で `Path.of` するので、`outputFile` の不正な値も同じ変換で拒否されてよい（追加の分岐は要らない）
- 変換後のメッセージは `"outputFile または tempDir をパスとして解釈できません: " + e.getReason()` にする。`e.getMessage()` は入力値（NUL 文字を含む）を含むので使わない
- 単体テストから検証を呼べるように、Job の `validator` のラムダの中身を package-private の `static void validateParameters(JobParameters parameters) throws InvalidJobParametersException` に移し、Job は `.validator(Sample03JobConfig::validateParameters)` にする。検証の順（`requiredAndOptional` → `validateFormat` → `validateTempOutput`）は変えない。`JobParameters` は `org.springframework.batch.core.job.parameters.JobParameters`（Batch 6 のパッケージ。5系のパッケージを使わない）
- `Sample03JobConfigTest` に次の2つのテストメソッドを足す（名前はこのとおり。既存のテストは変えない）
  - `一時ディレクトリが空白だけの場合＿親ディレクトリ配下のtmpに同名の一時ファイルパスを返す`：`tempOutputOf(dir.resolve("sales.csv").toString(), "   ").tempFile()` が `dir.toAbsolutePath().resolve("tmp").resolve("sales.csv")` になる
  - `tempDirにNUL文字を含む場合＿InvalidJobParametersExceptionで起動を拒否する`：`outputFile` に正しいパス、`tempDir` に `"work\u0000dir"` を入れた `JobParameters`（`JobParametersBuilder` の `addString`）で `validateParameters` を呼ぶと `InvalidJobParametersException` が出て、メッセージに `パスとして解釈できません` を含む
  - ほかのテスト（空白だけの `tempDir` で `validateParameters` が例外を出さない、など）を足してもよい。足す時もテストメソッド名は日本語の「条件＿期待結果」にする
- 結合テスト（`Sample03FileExportJobIT.java`）は変えない（NUL 文字を含むパラメータを JobRepository に渡す経路を結合テストで扱わない）。そのため受け入れ基準に `./mvnw clean verify`（結合テスト込み）は入れない。計画単位のレビュータスク T-04 で実行する
- `TempOutputFile.java` と `batch-sample/docs/sample03-file-export.md` は変えない（文書は T-03 が変える）
- 識別パラメータの扱いはコードで変えない（`tempDir` は識別パラメータのまま。理由の記述は T-03）
- ビルドのコマンドはシェルの `JAVA_HOME` が JDK 21 を指すため、受け入れ基準のとおり `JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64` を前に付けて実行する
