# T-02 TempOutputFileTest にリスタート時に prepare が一時ファイルを消さないテストを足す

## 目的
空でない `ExecutionContext`（リスタート）の場合に、`TempOutputFile.prepare` が前回の一時ファイルを消さず、`saveState=true` の Writer が保存した位置から一時ファイルに書き継げることを単体テストで示す（GitHub Issue #107 の4点目。`prepare` の Javadoc の「ここで消すとリスタートを壊す」の裏付け）。

## 入力
- GitHub Issue #107（`gh api repos/{owner}/{repo}/issues/107` で読める）
- `batch-core/src/test/java/com/example/batch/core/tasklet/TempOutputFileTest.java`（既存の `前回の一時ファイルが残っている場合＿CsvItemWriterFactoryのWriterが上書きする` が書き方の手本）
- `batch-core/src/main/java/com/example/batch/core/tasklet/TempOutputFile.java`（`prepare` の Javadoc。変えない）
- `batch-core/src/main/java/com/example/batch/core/item/CsvItemWriterFactory.java`（`shouldDeleteIfExists(true)`・`saveState(true)`）
- `docs/coding-standards.md` §7 テストコード規約

## 成果物
- `batch-core/src/test/java/com/example/batch/core/tasklet/TempOutputFileTest.java`（1ファイル。テストメソッドを1つ足す）

## 決定済み
- 足すテストメソッドは1つで、名前は `リスタートで前回の一時ファイルが残っている場合＿prepareは消さずWriterが保存位置から書き継ぐ` にする（既存の16件は変えない。合計17件）
- テストの手順（`TempOutputFile.java` は変えず、テストだけで示す）
  1. `var temp = TempOutputFile.inSubdirectory(dir.resolve("sales.csv"), "tmp");` で作り、`temp.prepare()` の戻り値を `CsvItemWriterFactory.create("tempOutputWriter", new FileSystemResource(...toFile()), Row.class, StandardCharsets.UTF_8, null, null, "code")` に渡す（既存テストと同じ Writer の作り方。ヘッダ・フッタ無し）
  2. 前回の実行：`ExecutionContext executionContext = new ExecutionContext();` で `open` し、`Row("OLD1")`・`Row("OLD2")` を `write` し、`update(executionContext)` で位置を保存してから `close` する
  3. 保存した `ExecutionContext` が空でないこと（`assertThat(executionContext.isEmpty()).isFalse()`）を確かめる。これがリスタートの文脈であることを示す
  4. リスタート：同じ引数で `TempOutputFile` をもう一度作って `prepare()` を呼び、戻り値の一時ファイルが残っていて中身が `OLD1`・`OLD2` のままであること（`Files.readAllLines`）を確かめる
  5. 同じ名前（`tempOutputWriter`）で Writer を作り直し、2の `executionContext` で `open` して `Row("NEW3")` を `write` し `close` する。一時ファイルの行が `OLD1`・`OLD2`・`NEW3` の順（`containsExactly`）になることを確かめる（`shouldDeleteIfExists(true)` でも、リスタートでは保存した位置から書き継ぐ）
- テストメソッドに、リスタートでは `prepare` が消さないことを示すテストである旨の1行コメントを付けてよい
- `TempOutputFile.java`・`CsvItemWriterFactory.java` と batch-sample 側のファイルは変えない（sample03 は `T-01` が変える）
- 受け入れ基準の3・4行目の surefire の報告は、2行目の `-pl batch-core` のビルドが作り直すので、2行目の後に確かめる
- 結合テストは変えないので、受け入れ基準に `./mvnw clean verify`（結合テスト込み）は入れない。計画単位のレビュータスク T-04 で実行する
- ビルドのコマンドはシェルの `JAVA_HOME` が JDK 21 を指すため、受け入れ基準のとおり `JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64` を前に付けて実行する
