# T-02 OrderItemProcessor の Javadoc を ItemProcessor 型の Bean の方針に直す（#98）

## 目的
`OrderItemProcessor` の Javadoc に残る「`@StepScope` で使うため final にしない」の古い記述を、新方針（docs/architecture.md §13・docs/decisions.md：`process()` は final、`@StepScope` の Processor は Bean メソッドの戻り値と注入先を `ItemProcessor<I, O>` 型にする）に合わせて直す（GitHub Issue #98）。

## 決定済み
- 設計書（ORDER-001）は改訂しない。§1 Bean 一覧の注記は「`@StepScope` で生成するクラスは final にしない」「`ValidatingItemProcessorBase` を継承した Processor は戻り値と注入先の型を `ItemProcessor<OrderCsvRecord, OrderDetailWork>` にする」「`ValidatingItemProcessorBase#process` は例外で final」で、新方針と食い違っていない。食い違いがあるのは Javadoc だけ
- クラスの Javadoc の最後の段落「<p>{@code @StepScope} で使うため final にしない。</p>」を、次の段落に置き換える（文言はこのとおりに書く）：
  「<p>{@code @StepScope} の Bean にする時は、Bean メソッドの戻り値と注入先の型を {@code ItemProcessor<OrderCsvRecord, OrderDetailWork>} にする（docs/architecture.md §13）。{@code process()} は継承元で final のため、具象型で宣言するとスコーププロキシが未初期化のまま {@code process()} を実行して NullPointerException になる。クラスは final にしない（ORDER-001 詳細設計 §1 Bean 一覧の注記）。{@code process()} 以外の public メソッドは足さない（インタフェース型の Bean からは呼べないため）。</p>」
- コードは変えない（`OrderDailySalesJobConfig` の Bean メソッドは既に `ItemProcessor<OrderCsvRecord, OrderDetailWork>` 型）
- `CsvHeaderCheckTasklet`・`OrderDailySalesReplaceTasklet` の同じ文言はクラスのスコーププロキシで使うクラスなので正しく、変えない（受け入れ基準の3行目はこの2つが残ることを前提にしている）
- `OrderItemProcessor` 以外の `ValidatingItemProcessorBase` 派生（`NotifyCandidateItemProcessor` など）には同じ古い記述が無いので変えない
- 人の回答（/plan unblock）：JDK 25 を apt でインストール済み（`java`・`javac` の既定を 25 に切り替え済み）。受け入れ基準のビルドは JDK 21 の代替ではなく元のコマンドで確認する
