# T-01 読込時の Skip の WARN ログに行の内容を出さず行番号を出す（#97・#99(d)）

## 目的
読込時の Skip で `ErrorRecordSkipListener` が出す WARN ログに、行の内容（`FlatFileParseException` のメッセージの `input=[<行>]`）が残らないようにし、行番号で位置が分かるようにする（方式設計 §8 の個人情報のログ出力禁止。GitHub Issue #97 と #99(d)）。

## 決定済み
- WARN ログの書式（`レコードをSkipしました。エラーレコードファイルへ退避します: file={} reason={}`）は変えず、`reason` に渡す値だけを変える
- `onSkipInRead` で `t` が `FlatFileParseException` の時の `reason` は `line=<getLineNumber()> cause=<原因>` にする。`<原因>` は、`getCause()` が `BusinessException` ならそのメッセージ（batch-core の部品のメッセージは値を含めない方針のため。PR #95）、それ以外（`null` を含む）なら原因のクラスの単純名（`getSimpleName()`。`null` の時は `FlatFileParseException`）にする。原因のメッセージをそのまま出さないのは、`BindException` などが不正な値をメッセージに含めるため
- `FlatFileParseException` 以外の読込時の Skip と、加工時・書込時の Skip の `reason` は、これまでどおり `t.getMessage()` にする（加工時・書込時は業務のメッセージで、この Issue の範囲外）
- エラーレコードファイルの中身（`元レコード<TAB>エラー理由`）は変えない。方式設計 §5.2 で元レコードを残すファイルであり、ログではないため。既存のテスト `読取時Skipは元の行を退避する` は変えずに通す
- 追加する単体テストのメソッド名は次の2つにする（受け入れ基準が surefire のレポートでこの名前を探す）
  - `読取時Skipの場合＿WARNログに行の内容を含めず行番号を出す`：`new FlatFileParseException("Parsing error at line: 3 in resource=[x], input=[秘密,行]", new BusinessException("固定長レコードのバイト長が不正です: expected=5 actual=11"), "秘密,行", 3)` を `onSkipInRead` に渡し、WARN の `getFormattedMessage()` が `line=3` と原因のメッセージを含み、`秘密` を含まないことを確かめる
  - `読取時Skipで原因がBusinessExceptionでない場合＿原因のクラス名だけを出す`：原因を `new IllegalStateException("値=秘密")` にし、WARN が `line=3` と `IllegalStateException` を含み、`秘密` を含まないことを確かめる
- ログの検証は Logback の `ListAppender` を `ErrorRecordSkipListener` のロガーに付けて行い、テストの後で外す（`OrderDetailWorkClearTaskletTest` と同じ書き方）
- `ErrorRecordSkipListener` のクラスの Javadoc に、読込時の Skip の WARN ログには行の内容を出さず行番号と原因だけを出すこと（行の内容はエラーレコードファイルにだけ残る）を1文で書く
- #99(d) の判断：`ByteLengthLineTokenizer` の例外のメッセージには行番号を足さない。クラスの Javadoc の「例外のメッセージには行の内容を含めず、バイト数・フィールド名・バイト位置を示す。」の直後に、次の文を足す：「行番号は含めない（{@code LineTokenizer} は行番号を受け取らないため）。行番号は {@code FlatFileItemReader} が {@code FlatFileParseException} に持たせ、{@code ErrorRecordSkipListener} が読込時の Skip の WARN ログに出す。」。コードは変えない
- `batch-sample/docs/sample02-fixedlength-import.md` の「実装ポイント」節の末尾に、次の箇条を1行足す：「- 読込時の Skip の WARN ログには行の内容を出さず、行番号（`FlatFileParseException#getLineNumber()`）と原因だけを出す（`ErrorRecordSkipListener`）。行の内容はエラーレコードファイルにだけ残る」
- `batch-sample/docs/` のほかの文書（sample01 など）は WARN ログの中身に触れていないので変えない
