# T-04 formatViolations の書式と値を含めない約束を Javadoc とテストで固定する（#99(c)）

## 目的
`ValidatingItemProcessorBase.formatViolations` の入力チェック違反のメッセージの書式と、違反値・入力レコードの値を含めない約束を Javadoc に明記し、書式を単体テストで固定する（GitHub Issue #99 の (c)。個人情報を含まないことは維持する）。

## 入力
- `batch-core/src/main/java/com/example/batch/core/item/ValidatingItemProcessorBase.java`
- `batch-core/src/test/java/com/example/batch/core/item/ValidatingItemProcessorBaseTest.java`
- `docs/architecture.md` §8
- `docs/projects/order-daily-sales/system-test/scenarios.md`（エラーファイルに出る既存の書式の例）

## 成果物
- 主な成果物：`batch-core/src/main/java/com/example/batch/core/item/ValidatingItemProcessorBase.java`（`formatViolations` の Javadoc）
- 付随して変えるファイル：`batch-core/src/test/java/com/example/batch/core/item/ValidatingItemProcessorBaseTest.java`

## 受け入れ基準
- `./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false 2>&1 | grep -c 'INFO. BUILD SUCCESS'` が `1` を出す
- `./mvnw clean verify -DskipITs -pl batch-core 2>&1 | grep -c 'INFO. BUILD SUCCESS'` が `1` を出す（batch-core のカバレッジ80%）
- 上のビルドの後、`grep -c '違反メッセージの書式＿項目のパス順に項目とメッセージを並べ違反値を含めない' batch-core/target/surefire-reports/TEST-com.example.batch.core.item.ValidatingItemProcessorBaseTest.xml` が `1` を出す
- `grep -c 'と入力レコードの値はメッセージに含めない' batch-core/src/main/java/com/example/batch/core/item/ValidatingItemProcessorBase.java` が `1` を出す

## 決定済み
- 出力の書式（`入力チェックエラー: ` の後に「項目のパス 空白 メッセージ」を項目のパスの文字列順に `, ` でつなぐ）は変えない。システムテストの実施記録（`docs/projects/order-daily-sales/system-test/scenarios.md`）や既存のエラーファイルと食い違わせないため。`formatViolations` の本体のコードは変えない
- `formatViolations` の Javadoc に次の3つを書く
  - 書式：`{@code 入力チェックエラー: 項目のパス メッセージ, 項目のパス メッセージ}`（項目のパスの文字列順）
  - 「違反値（{@link ConstraintViolation#getInvalidValue()}）と入力レコードの値はメッセージに含めない（docs/architecture.md §8）。」の文（この文言のとおりに書く）
  - 上書きする時も値を含めないこと。メッセージテンプレートに `validatedValue` の式を使うと値が入るので使わないこと
- 追加するテストのメソッド名は `違反メッセージの書式＿項目のパス順に項目とメッセージを並べ違反値を含めない` にする（受け入れ基準が surefire のレポートでこの名前を探す）
- テストは JVM のロケールで既定のメッセージが変わらないよう、メッセージを固定した制約を持つテスト専用の record（例：`@NotBlank(message = "必須") String code`・`@Max(value = 150, message = "150以下") int age`）を使い、`code` を空白だけの文字列、`age` を `200` にして、`hasMessage("入力チェックエラー: age 150以下, code 必須")` と `hasMessageNotContaining("200")` で確かめる
- 既存のテストは変えない
- クラスの Javadoc の「拡張ポイント」の段落は変えない
