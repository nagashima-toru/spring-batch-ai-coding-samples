# T-06 計画の差分が `/code-review` を通過する

## 目的
T-01〜T-05 で変えた計画全体の差分を組み込みの `/code-review` で確かめ、致命的な指摘を残さない（計画単位のレビュータスク）。

## 入力
- 計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）
- `.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節
- `vault/rules/verifier/code-review.md`
- T-01〜T-05 のタスク票（`vault/tasks/P-20261022-review-followups-95/`）の「決定済み」

## 成果物
- 主な成果物：計画の差分への修正（致命的な指摘が無ければ変更なし）
- 直してよいファイル（先行タスクの「成果物」に宣言したパス）：
  - `batch-core/src/main/java/com/example/batch/core/exception/ErrorRecordSkipListener.java`
  - `batch-core/src/test/java/com/example/batch/core/exception/ErrorRecordSkipListenerTest.java`
  - `batch-core/src/main/java/com/example/batch/core/item/ByteLengthLineTokenizer.java`
  - `batch-sample/docs/sample02-fixedlength-import.md`
  - `batch-sample/src/main/java/com/example/batch/sample/job_order_daily_sales/OrderItemProcessor.java`
  - `batch-sample/src/test/java/com/example/batch/sample/architecture/StepScopeBeanRuleTest.java`
  - `batch-core/src/main/java/com/example/batch/core/item/ValidatingItemProcessorBase.java`
  - `batch-core/src/test/java/com/example/batch/core/item/ValidatingItemProcessorBaseTest.java`
  - `docs/decisions.md`

## 受け入れ基準
- `/code-review` で計画の差分に致命的な指摘が残っていない（`vault/rules/verifier/code-review.md` に従って判定する）
- `./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false 2>&1 | grep -c 'INFO. BUILD SUCCESS'` が `1` を出す
- `./mvnw clean verify -DskipITs -pl batch-core 2>&1 | grep -c 'INFO. BUILD SUCCESS'` が `1` を出す
- 3行目のビルドの後、`grep -c '読取時Skipの場合＿WARNログに行の内容を含めず行番号を出す' batch-core/target/surefire-reports/TEST-com.example.batch.core.exception.ErrorRecordSkipListenerTest.xml` が `1` を出す
- 2行目のビルドの後、`grep -c 'クラスにStepScopeを付けた派生クラス＿違反として検出される' batch-sample/target/surefire-reports/TEST-com.example.batch.sample.architecture.StepScopeBeanRuleTest.xml` が `1` を出す

## 決定済み
- レビューの範囲は、ベースブランチ（`HARNESS_BASE_BRANCH`、前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）とする
- 計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない
- 致命的な指摘が無ければ成果物を変えず、「進捗」への記録だけでよい（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）
- 差分の外（既存コード）への指摘・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは、`.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節に従う
- 直す時も、各先行タスクの「決定済み」（WARN ログの `reason` の書式、`formatViolations` の出力の書式を変えないこと、ORDER-001 を改訂しないこと、`docs/decisions.md` は1行の追記だけにすることなど）を変えない。変えないと直せない指摘は設計や仕様の変更が要る指摘として扱う
- ビルドは 3行目の `-pl batch-core` を2行目の後に実行するので、4行目は batch-core の、5行目は batch-sample の surefire のレポートを見る（`-pl batch-core` の `clean` は batch-sample の `target/` を消さない）

## 進捗
- 読んだルール: vault/rules/common/project-docs.md, vault/rules/creator/code-review.md, vault/rules/creator/skill-workflow.md
- /code-review を1回実行（範囲: git diff --merge-base main、計画一式4種は除く）。指摘7件、いずれも致命的（クラッシュ・データ破損・誤った結果）に当たらず、成果物は変更しない
- 区分ごとの件数: Must 0 / Should 7 / Ask 0
- Should（直さない）: 書込・加工Skipのログに例外メッセージが残る点、BusinessException cause のメッセージ、ValidatingItemProcessorBase の Javadoc の並び順表現、StepScopeBeanRuleTest の検出範囲とクラスパス依存、ErrorRecordSkipListenerTest のログ捕捉、docs/decisions.md の行の重複
- 対象外（既存コード）: 書込・加工Skip時に t.getMessage() をそのままWARNに出す既存挙動（onSkipInWrite/onSkipInProcess）
- 確認: 2行目ビルド=1、3行目ビルド=1、ErrorRecordSkipListenerTest のテスト名=1、StepScopeBeanRuleTest のテスト名=1
