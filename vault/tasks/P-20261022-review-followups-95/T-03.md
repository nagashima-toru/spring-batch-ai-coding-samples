# T-03 StepScopeBeanRuleTest の検出範囲と空マッチの扱いを明示する（#99(a)(b)）

## 目的
`StepScopeBeanRuleTest`（ArchUnit）が、クラスレベルの `@StepScope` を付けた `ValidatingItemProcessorBase` 派生も検出し、検出の対象外をテストの Javadoc に明記し、検査対象が1件も取り込めなかった時に何も検査せず成功しないことを明示する（GitHub Issue #99 の (a)(b)）。

## 入力
- `batch-sample/src/test/java/com/example/batch/sample/architecture/StepScopeBeanRuleTest.java`
- `batch-core/src/main/java/com/example/batch/core/item/ValidatingItemProcessorBase.java`
- `docs/architecture.md` §13
- ArchUnit 1.5.1（親 POM の `archunit.version`）の `ArchRule#allowEmptyShould`

## 成果物
- `batch-sample/src/test/java/com/example/batch/sample/architecture/StepScopeBeanRuleTest.java`（1ファイル）

## 決定済み
- 既存のルール（`@Bean` かつ `@StepScope` のメソッドの戻り値が派生の具象型なら違反）と既存の3つのテストは残す。既存のルールの定義に `.allowEmptyShould(false)` を足す
- 2つ目のルールを足す：`noClasses().that().areAssignableTo(ValidatingItemProcessorBase.class).should().beAnnotatedWith(StepScope.class)` に `.allowEmptyShould(false)` と `.because(...)` を付ける（クラスレベルの `@StepScope` は既定の `proxyMode` がクラスのプロキシのため、final の `process()` が未初期化のプロキシ本体で実行される）。`that()` を「派生クラス」にするのは、本番のクラスにクラスレベルの `@StepScope` が1つも無く、`that()` を「`@StepScope` のクラス」にすると空マッチで失敗するため
- 追加するテストのメソッド名は次の3つにする（受け入れ基準が surefire のレポートで2つ目と3つ目の名前を探す）
  - `StepScopeのクラスにValidatingItemProcessorBase派生が無い`：本番のクラス（既存のテストと同じ `importPackages("com.example.batch")`・`DO_NOT_INCLUDE_TESTS`）に2つ目のルールを当てて通る
  - `クラスにStepScopeを付けた派生クラス＿違反として検出される`：テスト専用の見本 `@StepScope` 付きの `ValidatingItemProcessorBase` 派生クラスを `importClasses` で取り込み、2つ目のルールが `AssertionError` を投げる
  - `検査対象が取り込めなかった場合＿何も検査せずに成功しない`：`@Bean` メソッドを持たないテスト専用のクラスだけを取り込み、既存のルールが `AssertionError` を投げる（`allowEmptyShould(false)` の効果を示す）
- `allowEmptyShould(false)` の文字列はルールの定義の2か所にだけ書き、Javadoc やコメントには書かない（受け入れ基準が `2` を数えるため）。Javadoc で触れる時は `{@code allowEmptyShould}` と書く
- クラスの Javadoc に、検出するもの（上の2つのルール）と、空マッチで失敗させる意図（パッケージの指定の誤りなどで何も検査せずに成功しないため）を書く。検出の対象外は「次は検出の対象外とする」の文で始めて列挙する：`ValidatingItemProcessorBase` 以外の、final の public メソッドを持つ基底クラス（一般の final メソッドは判定できないため。docs/decisions.md の「`@StepScope` で生成する Bean のクラスは final にせず、継承元の public メソッドも final にしない」で防ぐ）と、XML などアノテーション以外で定義した Bean
- ArchUnit の設定ファイル（`archunit.properties`）は作らない（ルールごとに明示する）
- `batch-core` 側にルールを移さない（`batch-sample` の `pom.xml` にだけ ArchUnit の依存があるため）
