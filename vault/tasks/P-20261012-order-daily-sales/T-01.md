## 決定済み
- 仕様の正本は詳細設計書 ORDER-001.md 1.1 版。クラス名・Bean 名・Step 名・Mapper のメソッド名・SQL・V5 の内容は §1〜§6 の表のとおりにし、名前を変えない。設計書と異なる実装が必要と分かったら設計書を直さず blocked にする（`docs/development-guide.md` §5.5）
- ジョブパッケージに置くクラス：`OrderDailySalesJobConfig`・`OrderDailySalesJobParametersValidator`・`OrderDailySalesRunParameters`・`OrderCsvRecord`・`OrderDetailWork`・`OrderKey`・`OrderItemProcessor`・`OrderDetailWorkClearTasklet`・`OrderDailySalesReplaceTasklet`・`OrderDetailWorkMapper`・`OrderDetailMapper`・`DailyStoreSalesMapper`。これ以外のクラスが要ると判断したら、設計の範囲内（private メソッド・パッケージ内の補助）にとどめる
- Mapper インタフェースはジョブパッケージに置き（Writer の statementId が `com.example.batch.sample.job_order_daily_sales.OrderDetailWorkMapper.insert` のため）、XML は `batch-sample/src/main/resources/mapper/` に置く（`mybatis.mapper-locations: classpath:mapper/*.xml`）。XML の namespace はインタフェースの完全修飾名
- Step 名は `new StepBuilder("orderDailySales.01FileCheckStep", jobRepository)` のように文字列リテラルで書く（既存の `AnnouncementNotifyJobConfig` と同じ書き方。受け入れ基準の grep がこの形を見る）
- Bean メソッドは `public` で、メソッド名を Bean 名にする（既存の `PointExpiryJobConfig` と同じ）。`createWithLineNumber` の宣言は `public static <T> FlatFileItemReader<T> createWithLineNumber(` までを1行に書く（引数は折り返してよい。行長120以内）
- Validator は `JobParametersValidators.requiredAndOptional(...)`（batch-core に既存）に委譲してから書式・型を検証する。未知のキーは拒否される（結合テストで `testRunId` が使えなくなるのは T-03 で扱う）
- `SampleProperties` には `Job05` と同じ形でネストした record `OrderDailySales(String inputDir, String errorDir)` を足し、コンポーネント名は `orderDailySales`（キーは `sample.order-daily-sales.*`）。application.yml の既定は `/data/in`・`/data/error`、application-local.yml は `batch-sample/data/in`・`batch-sample/data/error`（§1.2）
- 追加依存は無い。`pom.xml`・`batch-core/pom.xml`・`batch-sample/pom.xml`・`config/` は変えない。カバレッジの除外設定の追加・閾値の変更はしない（`docs/development-guide.md` §5.4）
- カバレッジ80%（モジュールごと・`-DskipITs` では単体テストだけで計測）に届かずビルドが失敗した時に限り、「成果物」に挙げたテストのパスに単体テストを先に書いてよい。テストメソッド名は日本語の「条件＿期待結果」（`docs/coding-standards.md` §7）。網羅は T-02 が詳細設計書 §7 で行うので、ここでは閾値に届く分だけでよい。書いたテストは「進捗」に列挙する
- 既存の `CsvItemReaderFactory#create` の動作とシグネチャは変えない（追加だけ）
- Javadoc は日本語。batch-core の新規部品は既存部品と同じく用途・使い方・拡張ポイントを書く（`CsvHeaderCheckTasklet` はクォート付きヘッダ非対応を拡張ポイントとして書く。§6.1）
- 受け入れ基準の禁止パターン（`(Object)`・`LocalDate.now`・`java.time.Clock`・5系の `org.springframework.batch.item.`）はコメント・Javadoc にも書かない（説明が要る時は「Object へのキャスト」「現在日付の取得」のように言い換える）
- コミットメッセージは日本語
