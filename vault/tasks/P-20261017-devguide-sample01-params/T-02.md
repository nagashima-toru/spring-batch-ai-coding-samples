# T-02 architecture.md §1.2 のサンプル01実行例を inputFile/errorFile に直す

## 目的
`docs/architecture.md` §1.2「アプリケーション構成」の `java -jar` 実行例を、sample01 の必須パラメータ `inputFile` / `errorFile` を渡す形に直す（Issue #59 と同一原因の誤り）。

## 入力
- `docs/architecture.md` §1.2「アプリケーション構成」（現在33行目の `java -jar batch-sample.jar --spring.batch.job.name=sample01CsvImportJob importDate=2026-07-14,java.time.LocalDate`）
- `docs/architecture.md` §11「命名規約」の表（ジョブパラメータの行。変えない）
- `batch-sample/docs/sample01-csv-import.md` の「実行方法」（正しいパラメータの出典）
- `batch-sample/src/main/java/com/example/batch/sample/job01_csv_import/Sample01JobConfig.java`（`JobParametersValidators.required("inputFile", "errorFile")`）

## 成果物
- `docs/architecture.md`（1ファイル。§1.2 の実行例の1行のみ）

## 受け入れ基準
- 誤った実行例のパラメータが残っていない（`grep -c 'importDate=2026-07-14' docs/architecture.md` の出力が `0`）
- §11 命名規約表のジョブパラメータの例が残っている（`grep -c 'ジョブパラメータ.*importDate' docs/architecture.md` の出力が `1`、かつ `grep -c 'importDate' docs/architecture.md` の出力が `1`）
- 実行例が inputFile と errorFile を渡している（`grep -c 'sample01CsvImportJob inputFile=batch-sample/data/in/customers.csv errorFile=batch-sample/data/error/customers_error.txt' docs/architecture.md` の出力が `1`）

- 成果物が差分に含まれる（`git diff --merge-base work/p-20261017-devguide-sample01-params --name-only | grep -c '^docs/architecture.md'` の出力が `1`）

## 決定済み
- 変えるのは `docs/architecture.md` §1.2 のコードブロック内の次の1行だけ：
  `java -jar batch-sample.jar --spring.batch.job.name=sample01CsvImportJob importDate=2026-07-14,java.time.LocalDate`
- 置き換え後の行は次の1行にする（行の継続 `\` で複数行に割らない。`batch-sample.jar` の表記はそのまま）：
  `java -jar batch-sample.jar --spring.batch.job.name=sample01CsvImportJob inputFile=batch-sample/data/in/customers.csv errorFile=batch-sample/data/error/customers_error.txt`
- §11「命名規約」の表のジョブパラメータの行（`importDate` を camelCase の命名例として挙げている行）は誤りではないので変えない。そのため `importDate` は architecture.md に1件だけ残る
- §1.2 の他の行（箇条書き・コードブロックの囲み）や他の節は変えない。代わりの日付パラメータは足さない（sample01 は日付パラメータを使わない）
- パラメータ値は `batch-sample/docs/sample01-csv-import.md` の実行方法と同じにする。`batch-sample/data/error/` ディレクトリが現時点で存在しないことは気にしない（ディレクトリやファイルは作らない）
- `docs/development-guide.md` は T-01 が扱うので、このタスクでは変えない。README.md・CLAUDE.md・`batch-sample/docs/` 配下・コードも変えない
- architecture.md は SSoT だが、今回は実装と食い違っていた例の訂正であり、設計方針の変更ではない。コードの変更は伴わない
- `docs/architecture.md` は smoke の `(ref-1)` の検査対象外なので、smoke の実行は不要。文書のみの変更なのでビルド（`./mvnw`）も受け入れ基準に含めない
