# T-02 implementation Skill の命名表を §11 と整合させ正本を §11 と明記する

## 目的
implementation Skill の「出力ファイルの格納先・命名規則」を、T-01 で改訂した `docs/architecture.md` §11 と矛盾しない内容にし、命名の正本が §11 であることを明記する。

## 入力
- `.claude/skills/implementation/SKILL.md`（「出力ファイルの格納先・命名規則」節）
- `docs/architecture.md` §11（T-01 で改訂済み。計画ブランチの実ファイルを読む）

## 成果物
- `.claude/skills/implementation/SKILL.md`（1ファイル）

## 受け入れ基準
- 命名の正本が §11 と書かれている（`grep -c '命名の正本は .docs/architecture.md. §11' .claude/skills/implementation/SKILL.md` の出力が `1`）
- 番号付きの命名を新規ジョブに使わないと書かれている（`grep -c '新規の業務ジョブに使わない' .claude/skills/implementation/SKILL.md` の出力が `1`）
- 格納先の表が §11 の業務ジョブの命名と一致している（`grep -o -F -e 'job_{内容}/{Xxx}JobConfig.java' -e '{Xxx}Record.java' -e '{Xxx}ItemProcessor.java' .claude/skills/implementation/SKILL.md` の出力に3つの文字列がすべて現れ、かつ `awk '/^## 11/,/^## 12/' docs/architecture.md | grep -o -F -e '{Xxx}JobConfig' -e '{Xxx}Record' -e '{Xxx}ItemProcessor'` の出力にも3つすべてが現れる）
- 見出し構成が変わっていない（`grep -c '^#' .claude/skills/implementation/SKILL.md` の出力が `7`）
- smoke の参照検査が通る（`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`）
- 成果物が差分に含まれる（`git diff --merge-base work/p-20261017-naming-convention-unify --name-only | grep -c '^.claude/skills/implementation/SKILL.md'` の出力が `1`）

## 決定済み
- 「### 出力ファイルの格納先・命名規則」の見出しの直後（表の前）に、次の趣旨の文を置く。「命名の正本は `docs/architecture.md` §11」と「新規の業務ジョブに使わない」の語句はこのとおりに書く：「命名の正本は `docs/architecture.md` §11（命名規約）。下表は格納先と §11 の業務ジョブの命名の早見で、食い違ったら §11 を正とする。リファレンスサンプルの番号付き命名（`jobNN_{内容}`・`SampleNNJobConfig` など）は新規の業務ジョブに使わない。」
- 表の行（Job設定クラス・入力レコード・Processor・Mapper IF / XML・Flyway）は残し、命名の書式は今の `job_{内容}/{Xxx}JobConfig.java`・`{Xxx}Record.java`・`{Xxx}ItemProcessor.java` のまま変えない（§11 と一致しているため）。ジョブ名・Step 名・Bean 名の書式はこの表に重複して書かず、§11 を参照させる（「ジョブ名・Step 名・Bean 名は §11 に従う」のような1行を表の後に足すのはよい）
- 見出し（`#` で始まる行）の追加・削除・改名はしない
- 「進め方」以降の節は変えない
- バッククォートで書くリポジトリのパスは実在するものだけにする（smoke の `(ref-1)` が検査する）。`docs/architecture.md` は実在する
