# T-05 計画の差分が `/code-review` を通過する

## 目的
計画 P-20261021-code-review-minor-fixes（Issue #92 の7項目）の T-01〜T-04 の変更全体を `/code-review` で確かめ、致命的な指摘が残らないようにする。修正で計画全体の動作（ビルド・単体テスト・結合テスト・BOM と strict エンコードの集約）を壊していないことを確かめる。

## 入力

## 受け入れ基準
- `/code-review` で計画の差分に致命的な指摘が残っていない（`vault/rules/verifier/code-review.md` に従って判定する）
- リポジトリ（`.git`・`target`・`vault` を除く）にリテラルの U+FEFF を含むファイルが無い：`grep -rlP '\xEF\xBB\xBF' --exclude-dir=.git --exclude-dir=target --exclude-dir=vault .` の出力が空
- strict エンコードの処理が1か所にまとまっている：`grep -rl 'CodingErrorAction' batch-core/src/main batch-sample/src/main` の出力が `batch-core/src/main/java/com/example/batch/core/item/StrictCharsetEncoder.java` の1行だけ
- 全モジュールの静的解析と単体テストが通る：`JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 ./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` が `1`
- batch-core のカバレッジ80%を含めて通る：`JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 ./mvnw clean verify -DskipITs -pl batch-core 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` が `1`
- 結合テストと batch-sample のカバレッジ80%を含めて全体が通る（要 Docker）：`JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 ./mvnw clean verify 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` が `1`

## 決定済み
- レビューの範囲は、ベースブランチ（`HARNESS_BASE_BRANCH`。前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）
- 計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない
- 致命的な指摘が無ければ成果物を変えず、「進捗」への記録だけでよい（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）
- 差分の外（既存コード）・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは、`.claude/agents/creator.md` の「コードレビューを参照する基準がある時」の節と `.claude/agents/verifier.md` の「コードレビューを参照する基準の判定」の節に従う
- T-01〜T-04 の「決定済み」にある設計判断（例外のメッセージに値を含めない・解決のタイミングは変えず Validator で起動前に検証する・引数なしコンストラクタを足さない・表せない文字以外の文言は変えない）は、人の回答として扱う。これを覆す指摘は設計や仕様の変更が要る指摘として扱う
- ツールの入力にバックスラッシュ・`u`・4桁の16進を書くと、ツールに渡る前にその1文字に変わることがある（計画作成時に確かめた）。修正で Unicode エスケープを書く時は T-01 の「決定済み」の `perl` の置き換えを使い、受け入れ基準の2行目で確かめる
- ビルドは Java 25 が要る。この環境の既定の `JAVA_HOME` は Java 21 なので、確認コマンドの先頭の `JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64` を付けて実行する。Docker デーモンは起動済み

## 進捗
- 読んだルール: vault/rules/common/project-docs.md, vault/rules/creator/code-review.md, vault/rules/creator/skill-workflow.md
- /code-review を1回実行（範囲: git diff --merge-base main、計画一式4種は除く。HARNESS_BASE_BRANCH は空なので main）。指摘6件、Must 0件、Should 6件、Ask 0件。成果物は変更していない（2回目の実行は不要）
- Should（直さない）: 長さ超過例外・Tokenizer の行長不一致例外が値・行を含む（既存コードの文言で、T-01〜T-04 の決定済み「表せない文字以外の文言は変えない」の範囲）／StrictCharsetEncoder.message() が文字ごとにエンコーダを作る（性能）／Tokenizer の Javadoc の `</p>`（Checkstyle・ビルドは通過済み）／Validator と resolve の Path.of の重複（設計判断は T-03 の決定済み）／IT のログ件数テストがログ書式に依存（テスト保守性）
- 確認結果: U+FEFF の grep は出力空／CodingErrorAction の grep は StrictCharsetEncoder.java の1行のみ／`clean verify -DskipITs -Djacoco.haltOnFailure=false` の BUILD SUCCESS 件数=1／`-DskipITs -pl batch-core` =1／`clean verify`（全体・IT含む）=1
