# T-01 開発ガイド §1.4 の JDK 25 導入を apt の OpenJDK 25 へフォールバックする形にする

## 目的
クラウド環境で api.adoptium.net が 403 などで拒否されても、§1.4 の準備スクリプトだけで `./mvnw clean verify -DskipITs` を通せるようにする（Issue #66・#84）。

## 入力
- `docs/development-guide.md` の §1.4「クラウド環境での準備」（スクリプトと前置きの文）と §6「トラブルシューティング」の表
- `CLAUDE.md` の「技術スタック（固定バージョン）」（Java 25 は Temurin 固定）
- Issue #66・#84 の本文（要旨は「決定済み」に写した。Issue を読みに行かなくてよい）

## 成果物
- `docs/development-guide.md`（1ファイル。§1.4 のスクリプトと説明文の改訂、§6 の表への1行追加）

## 受け入れ基準
- §1.4 のスクリプト（`#!/usr/bin/env bash` の行から `docker info --format` の行まで）に apt でのインストール行がある：`awk '/^#!.usr.bin.env bash/,/^docker info --format/' docs/development-guide.md | grep -c 'DEBIAN_FRONTEND=noninteractive apt-get install -y openjdk-25-jdk-headless'` が `1`
- 同じスクリプトでフォールバック時の JAVA_HOME を apt の OpenJDK 25 のパスにしている：`awk '/^#!.usr.bin.env bash/,/^docker info --format/' docs/development-guide.md | grep -c 'JAVA_HOME_25=/usr/lib/jvm/java-25-openjdk-amd64'` が `1`
- `~/.mavenrc` への書き込みは選んだ JAVA_HOME を使う1か所だけで、`/opt/jdk-25` を無条件に書く旧行が無い：`grep -c 'printf .JAVA_HOME=' docs/development-guide.md` が `1`、かつ `grep -c 'printf .JAVA_HOME=%s' docs/development-guide.md` が `1`
- §1.4 のスクリプトが bash の構文として正しい：`awk '/^#!.usr.bin.env bash/,/^docker info --format/' docs/development-guide.md | bash -n` が終了コード 0 で、何も出力しない
- §1.4 にフォールバックである旨とローカル検証の扱いが書かれている：`grep -c 'Temurin を取得できない時のフォールバック' docs/development-guide.md` が `1`、かつ `grep -c 'ローカル検証は OpenJDK 25 でよい（CI は Temurin で検証する）' docs/development-guide.md` が `1`
- §1.4 に Network access で api.adoptium.net を許可する案内がある：`grep -c 'Network access で .api.adoptium.net. を許可' docs/development-guide.md` が `1`
- §6 の表に 403 で JDK を取得できない時の行がある：`grep -c 'JDK 取得が 403 で失敗する' docs/development-guide.md` が `1`

## 決定済み
- §1.4 のスクリプトは次の内容に置き換える（コードブロックの中身。2文字の字下げは外して書く。言語指定は今までどおり `bash`）。Temurin を優先し、`/opt/jdk-25/bin/java` が無いままなら apt の OpenJDK 25 を入れる。apt 版が既に入っていれば `apt-get` は実行しない。

  ```bash
  #!/usr/bin/env bash
  # JDK 25 と Docker デーモンを用意する（Temurin を優先し、取得できなければ apt の OpenJDK 25 にフォールバックする）
  set -euo pipefail
  if [ ! -x /opt/jdk-25/bin/java ]; then
    mkdir -p /opt/jdk-25
    curl -fsSL "https://api.adoptium.net/v3/binary/latest/25/ga/linux/x64/jdk/hotspot/normal/eclipse" \
      | tar -xz -C /opt/jdk-25 --strip-components=1 \
      || echo "Temurin を取得できなかったため apt の OpenJDK 25 にフォールバックする" >&2
  fi
  if [ -x /opt/jdk-25/bin/java ]; then
    JAVA_HOME_25=/opt/jdk-25
  else
    JAVA_HOME_25=/usr/lib/jvm/java-25-openjdk-amd64
    if [ ! -x "$JAVA_HOME_25/bin/java" ]; then
      apt-get update
      DEBIAN_FRONTEND=noninteractive apt-get install -y openjdk-25-jdk-headless
    fi
  fi
  # ./mvnw は ~/.mavenrc の JAVA_HOME を使う（PATH の java が 25 でなくてもよい）
  printf 'JAVA_HOME=%s\nexport JAVA_HOME\n' "$JAVA_HOME_25" > ~/.mavenrc
  if ! docker info >/dev/null 2>&1; then
    nohup dockerd >/tmp/dockerd.log 2>&1 &
    for _ in $(seq 1 30); do docker info >/dev/null 2>&1 && break; sleep 1; done
  fi
  ./mvnw -v
  docker info --format '{{.ServerVersion}}'
  ```

- §1.4 の前置きの文（「Claude Code on the web などの…」の段落）は残し、スクリプトの直後に次の2文を段落として足す（文言はこのとおり。表記を変えない）。
  - 「技術スタックは Temurin 固定であり、apt の OpenJDK 25（`openjdk-25-jdk-headless`、JAVA_HOME は `/usr/lib/jvm/java-25-openjdk-amd64`）は Temurin を取得できない時のフォールバックである。ローカル検証は OpenJDK 25 でよい（CI は Temurin で検証する）。」
  - 「Temurin を使いたい時は、環境の Network access で `api.adoptium.net` を許可する（403 で拒否される時はこの許可が無い）。」
- §6「トラブルシューティング」の表は、既存の「クラウド環境で `./mvnw` が JDK 25 以外で動く…」の行を変えずに、その直後に次の1行を足す：`| クラウド環境で api.adoptium.net からの JDK 取得が 403 で失敗する | §1.4 の準備スクリプトが apt の OpenJDK 25 にフォールバックする。Temurin を使う時は §1.4 のとおり環境の設定で許可を足す |`。この行には「Network access」の語を書かない（§1.4 の案内の基準を1件に保つため）。
- §1.1「前提ツール」の表の JDK の行（`25（Temurin）`）は変えない（正はあくまで Temurin で、フォールバックは §1.4 のクラウド環境向けの扱いのため）。
- 旧形式（`/opt/jdk-25` を無条件に `~/.mavenrc` に書く行）が残っていないことの確認はリポジトリ全体で行った結果、`docs/development-guide.md` 以外の該当は `docs/projects/order-daily-sales/system-test/` 配下（`data/env.sh` の `ST_JAVA_HOME` の既定値と `scenarios.md` の実施環境の記録）だけだった。これはシステムテストの実施記録と、環境変数で上書きできる既定値なので、このタスクでは変えない（範囲外）。
- `CLAUDE.md` の技術スタックの記述も変えない（Temurin 固定のまま）。
- 実際に `apt-get` や `curl` を実行してスクリプトを試す必要は無い。構文は受け入れ基準の `bash -n` で確かめる。
