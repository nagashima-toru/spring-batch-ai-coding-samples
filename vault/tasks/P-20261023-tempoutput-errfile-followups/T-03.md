## 決定済み
- 一時ディレクトリは任意のジョブパラメータ `tempDir` で指定する（設定 `SampleProperties` にはしない。実行ごとに選べるようにするため。既存の任意パラメータ `format` と同じ置き方）。必須パラメータは `outputFile` のまま。`JobParametersValidators.requiredAndOptional` の任意キーを `{"format", "tempDir"}` にする
- `tempOutputOf` の形を `static TempOutputFile tempOutputOf(String outputFile, String tempDir)` に変える。`tempDir` が null か空文字なら今どおり `TempOutputFile.inSubdirectory(Path.of(outputFile), TEMP_DIR_NAME)`、それ以外は `TempOutputFile.inDirectory(Path.of(outputFile), Path.of(tempDir))`
- Writer の Bean（`sample03SalesWriter`）と配置の Tasklet の Bean（`sample03FileMoveTasklet`）は、`@Value("#{jobParameters['tempDir']}") String tempDir` を受け取り、`tempOutputOf(outputFile, tempDir)` を使う
- 起動時のパラメータ検証：今の `validateOutputFileName` を、`tempOutputOf(outputFile, tempDir)` を呼んで `SystemException` を `InvalidJobParametersException`（メッセージは `SystemException` のメッセージ）に変えるメソッドに置き換える。ファイル名 `tmp` の拒否もこの中の重なり検査で行われる（既存の結合テスト `outputFileのファイル名がtmpの場合_InvalidJobParametersExceptionで起動を拒否する` はそのまま通る）。同じファイルシステムかどうかはコードで検査しない（一時ディレクトリが起動時にまだ無いことがあるため。文書で前提として書く）
- `Sample03JobConfig` のクラスの Javadoc の「一時出力→配置」に `tempDir` を指定すると `inDirectory` で配置先の外に置くことを1文足し、「実行方法」の例に `tempDir` を付けた1行を足す
- 単体テスト（`Sample03JobConfigTest`）：既存の `配置先ファイルを指定した場合＿親ディレクトリ配下のtmpに同名の一時ファイルパスを返す` は名前を変えずに `tempOutputOf(..., null)` を呼ぶ形にする。次の2件を足す（名前はこのとおり。「一時ディレクトリ」で始まるテストメソッドはこの2件だけ）：
  - `一時ディレクトリを指定した場合＿指定のディレクトリ配下に同名の一時ファイルパスを返す`
  - `一時ディレクトリが空文字の場合＿親ディレクトリ配下のtmpに同名の一時ファイルパスを返す`
- 結合テスト（`Sample03FileExportJobIT`。このファイルの既存の名前に合わせて区切りは半角の `_`）に次の2件を足す（「tempDir」で始まるテストメソッドはこの2件だけ）：
  - `tempDirを指定した場合_一時ファイルを配置先の外に作り配置先へ移動する`：`@TempDir` の下に `work`（一時ディレクトリ）と `out/sales_tempdir.csv`（配置先）を使い、COMPLETED・配置先のファイルがある・`work/sales_tempdir.csv` が無い・`out/tmp` が作られていない、を確かめる
  - `tempDirが配置先の親ディレクトリと同じ場合_InvalidJobParametersExceptionで起動を拒否する`
- 解説（`batch-sample/docs/sample03-file-export.md`）に書くこと：
  - 「一時出力→配置」の節に、任意パラメータ `tempDir` を指定すると `TempOutputFile.inDirectory` で一時ディレクトリを配置先の外に置くこと。今の38行目（配置先を再帰的に監視する仕組みがある場合）の箇条はこのパラメータを指す形に書き直す
  - 一時ディレクトリは配置先と同じファイルシステムに置く前提（別のファイルシステムだと移動がアトミックにならず、コピーと削除になって配置先に書きかけのファイルが見える）。今の記述を残してよい
  - シンボリックリンクの限界：文言「シンボリックリンクは解決しない」をそのまま含む1文（重なりの検査は正規化したパスで行い、シンボリックリンクは解決しないので、実体が同じでも検出できない場合がある）
  - 並行実行の前提：文言「同じ出力ファイル名で並行実行しない」をそのまま含む1文。同じジョブの並行実行は二重起動防止（方式設計 §6.3）で止まるが、別のジョブや別の実行が同じ一時ディレクトリに同じ出力ファイル名で書くと同じ一時ファイルを使うので、そうしない（出力ファイル名か一時ディレクトリを分ける）
  - 残った一時ファイルの方針（T-02）：文言「前回の失敗で残った同名の一時ファイルは消さない」をそのまま含め、Writer（`shouldDeleteIfExists(true)`、sample03 は `saveState=false`）が最初から書き直すので前回の中身は残らないことを書く。今の33行目の「次の実行で上書きされる」はこの説明に合わせて書き直す
  - 「実行方法」の節に、`tempDir` を付けた実行例を1つ足す。引数の行は「outputFile=batch-sample/data/out/sales.csv tempDir=batch-sample/data/work」とし、文字列「tempDir=batch-sample/data/work」は文書の中でこの1か所だけに書く
  - 上の3つの文言（「シンボリックリンクは解決しない」「同じ出力ファイル名で並行実行しない」「前回の失敗で残った同名の一時ファイルは消さない」）は、それぞれ文書の中で1か所だけに書く
- `batch-core` 配下は変えない（T-01・T-02 で済んでいる）。`batch-sample/docs/README.md` は変えない
