# T-05 計画の差分が `/code-review` を通過する

## 目的
計画全体（T-01〜T-04）の差分を `/code-review` で確かめ、致命的な指摘が残っていない状態にする。修正で計画全体の動作を壊していないことをビルドとテストで確かめる。

## 入力
- 計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）
- `vault/tasks/P-20261023-tempoutput-errfile-followups/T-01.md`〜`T-04.md`（各タスクの決定済み）
- `vault/rules/verifier/code-review.md`（判定の区分）

## 成果物
- 主な成果物：計画の差分への修正（致命的な指摘があった時だけ。無ければ成果物を変えない）
- 直してよいファイル（先行タスクの「成果物」の宣言のすべて）：
  - `batch-core/src/main/java/com/example/batch/core/tasklet/TempOutputFile.java`
  - `batch-core/src/test/java/com/example/batch/core/tasklet/TempOutputFileTest.java`
  - `batch-sample/src/main/java/com/example/batch/sample/job03_file_export/Sample03JobConfig.java`
  - `batch-sample/src/test/java/com/example/batch/sample/job03_file_export/Sample03JobConfigTest.java`
  - `batch-sample/src/test/java/com/example/batch/sample/job03_file_export/Sample03FileExportJobIT.java`
  - `batch-sample/docs/sample03-file-export.md`
  - `batch-core/src/main/java/com/example/batch/core/exception/ErrorRecordSkipListener.java`
  - `batch-core/src/test/java/com/example/batch/core/exception/ErrorRecordSkipListenerTest.java`
  - `docs/architecture.md`

## 受け入れ基準
- `/code-review` で計画の差分に致命的な指摘が残っていない（`vault/rules/verifier/code-review.md` に従って判定する）
- 結合テストを含む全体のビルドが成功する（Docker が要る）：`JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 ./mvnw clean verify 2>&1 | grep -c 'BUILD SUCCESS'` の出力が `1`
- batch-core のカバレッジ80%を含むビルドが成功する：`JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 ./mvnw clean verify -DskipITs -pl batch-core 2>&1 | grep -c 'BUILD SUCCESS'` の出力が `1`
- `TempOutputFile` の検証の単体テストが残っている：上のビルドの後、`grep -c 'testcase name=.dirName' batch-core/target/surefire-reports/TEST-com.example.batch.core.tasklet.TempOutputFileTest.xml` の出力が `4`
- エラー理由の置き換えの単体テストが残っている：`grep -c 'に置き換えて1行で退避する' batch-core/target/surefire-reports/TEST-com.example.batch.core.exception.ErrorRecordSkipListenerTest.xml` の出力が `2`
- sample03 の `tempDir` の結合テストが残っている：`grep -c 'testcase name=.tempDir' batch-sample/target/failsafe-reports/TEST-com.example.batch.sample.job03_file_export.Sample03FileExportJobIT.xml` の出力が `2`

## 決定済み
- レビューの範囲は、ベースブランチ（`HARNESS_BASE_BRANCH`、前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）。対象 worktree のパスを明示して `/code-review` を呼ぶ
- 計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない
- 致命的な指摘が無ければ成果物を変えず、「進捗」への記録だけでよい（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）
- 差分の外（既存コード）への指摘・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは、`.claude/agents/creator.md` の「コードレビューを参照する基準がある時」の節と `.claude/agents/verifier.md` の「コードレビューを参照する基準の判定」の節に従う。差分の外への指摘を直すためのファイル変更はしない
- 計画で決めた方式（`dirName` は単一のディレクトリ名に限る・重なり検査は祖先と子孫を拒否しシンボリックリンクは解決しない・`prepare` は残った一時ファイルを消さず Writer の上書きに任せる・sample03 の一時ディレクトリは任意のジョブパラメータ `tempDir`・エラー理由の CR・LF・タブを半角空白1文字に置き換え元レコードは置き換えない）は決定済みの仕様として扱う。これを変える必要がある指摘は設計・仕様の変更が要る指摘として扱う
- 修正する時も、先行タスクの決定済みにあるテストメソッド名と文書の文言（受け入れ基準の grep の対象）は変えない
- ビルドは `JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64` を付けて実行する（シェルの既定の JAVA_HOME は JDK 21 のため）
