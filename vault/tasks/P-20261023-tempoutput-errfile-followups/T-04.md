# T-04 ErrorRecordSkipListener がエラー理由の改行・タブを空白に置き換えて1行1レコードを保つ（#105）

## 目的
例外メッセージに改行やタブが入っても、エラーレコードファイルの `元レコード<TAB>エラー理由` の1行1レコードの形式が壊れないようにし、その扱いを方式設計 §5.2 に書く。

## 決定済み
- 置き換えるのはエラーレコードファイルに書くエラー理由（今の `t.getMessage()`）だけ。`\r`・`\n`・タブを、それぞれ半角空白1文字に置き換える（CRLF は空白2文字になる）。元レコード（フォーマッタの結果・`FlatFileParseException.getInput()`）は置き換えない（Issue の範囲がエラー理由だけで、元レコードは手動リカバリでそのまま使う値のため）
- メッセージが null の時は今どおり文字列 "null" を書く（`String.valueOf` で今の出力を変えない）
- WARN ログの reason（`cause=...`。#97/#100 の形式）は変えない。エラーレコードファイルに書くエラー理由の中身も、改行・タブ以外は変えない
- 置き換えは private の static メソッドに分けてよい（名前は任意）
- クラスの Javadoc の出力形式の段落に、文言「エラー理由に含まれる改行」をそのまま含む1文を足す（例：エラー理由に含まれる改行（CR・LF）とタブは半角空白に置き換え、1行1レコードを保つ）。この文言は Javadoc の中で1か所だけにする
- `docs/architecture.md` §5.2 の「Skip したレコードは エラーレコードファイル（元レコード＋エラー理由）へ退避し」の箇条の直後に、箇条を1つ足す：エラーレコードファイルは「元レコード<TAB>エラー理由」の1行1レコードで、文言「エラー理由に含まれる改行」をそのまま含めて、改行（CR・LF）とタブを半角空白に置き換えて書くこと、元レコードは置き換えないことを書く。この文言は architecture.md の中で1か所だけにする。§5.2 以外の節は変えない
- 追加する単体テスト（`@Test` の通常のメソッド。名前はこのとおり。「に置き換えて1行で退避する」で終わるテストメソッドはこの2件だけ）：
  - `加工時Skipで理由に改行とタブを含む場合＿空白に置き換えて1行で退避する`：`onSkipInProcess("A001", new BusinessException("1行目\r\n2行目\t3行目"))` の後、`Files.readAllLines` が `"A001\t1行目  2行目 3行目"` の1行だけ（フォーマッタは `r -> r`）
  - `読取時Skipで理由に改行を含む場合＿空白に置き換えて1行で退避する`：`onSkipInRead(new FlatFileParseException("パース\n失敗", "bad,line"))` の後、`Files.readAllLines` が `"bad,line\tパース 失敗"` の1行だけ
- 既存テストのメソッド・期待値は変えない（行の削除・書き換えをしない。追加だけ）
- `TempOutputFile` と sample03 は変えない（T-01〜T-03 の範囲）。`docs/projects/` 配下の設計書は変えない（書式「元レコード<TAB>エラー理由」は変わらないため）
