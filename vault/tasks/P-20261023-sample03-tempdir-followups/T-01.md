# T-01 sample03 の format の空白だけの値を tempDir と揃えて未指定（csv）として扱う

## 目的
sample03 の任意パラメータ `format` の空白だけの値を、`tempDir` と同じく未指定として扱い（CSV で出力する）、起動時に拒否しないようにする（GitHub Issue #110 の2点目）。

- `batch-sample/src/main/java/com/example/batch/sample/job03_file_export/Sample03JobConfig.java`（`validateFormat`・クラス Javadoc の固定長出力の段落・`sample03SalesWriter`）
- `batch-sample/src/test/java/com/example/batch/sample/job03_file_export/Sample03JobConfigTest.java`（既存の `tempDirが空白だけの場合＿起動を拒否しない` の書き方）
- `batch-sample/src/main/java/com/example/batch/sample/job05_api_import/InputSourceDecider.java`（空白だけを未指定とする既存の扱い：`isBlank()`）
- `docs/architecture.md` §3.4 ジョブパラメータの検証、`docs/coding-standards.md` §7 テストコード規約

## 決定済み
- 空白だけの `format` は拒否せず未指定（csv）として扱う。`tempDir`（`tempOutputOf` の `isBlank()`）と sample05 の `inputFile`（`InputSourceDecider.isFileInput` の `isBlank()`）に合わせる
- `validateFormat` の条件は `format != null && !format.isBlank() && !"csv".equals(format) && !"fixed".equals(format)` にする（`!format.isEmpty()` を `!format.isBlank()` に置き換えるだけ）。例外のメッセージは変えない。前後に空白がある `" fixed "` のような空白だけでない値は trim せず、今のまま拒否する（今回の範囲外）
- `sample03SalesWriter` は変えない（`"fixed".equals(format)` 以外は CSV なので、空白だけの値はすでに CSV になる）
- クラス Javadoc の固定長出力の段落の「未指定・空・{@code csv} は CSV、それ以外は起動を拒否する。」を「未指定・空文字・空白だけ・{@code csv} は CSV、それ以外は起動を拒否する。」に書き換える（未指定・空・ の並びを残さない）
- 検証の順（`requiredAndOptional` → `validateFormat` → `validateTempOutput`）と `validateParameters` のシグネチャは変えない
- `Sample03JobConfigTest` にテストメソッドをちょうど1つ足す。名前は `formatが空白だけの場合＿起動を拒否しない`。`outputFile` に `dir.resolve("sales.csv").toString()`（`@TempDir Path dir`）、`format` に `"   "` を入れた `JobParameters`（`JobParametersBuilder` の `addString`）で `Sample03JobConfig.validateParameters` を呼ぶと例外が出ない（`assertThatCode(...).doesNotThrowAnyException()`）。既存の8件のテストは変えず、ほかのテストは足さない（受け入れ基準が件数 `9` を見るため。T-02 が1件足して10件にする）
- `outputFile` の NUL 文字のテストは T-02 が足す。このタスクでは足さない
- 識別パラメータの扱いはコードで変えない（`format`・`tempDir` は識別パラメータのまま。JobParameters の作成時の正規化もしない。理由は計画票の「分割方針」、文書は T-03）
- 結合テスト（`Sample03FileExportJobIT.java`）と `batch-sample/docs/sample03-file-export.md` は変えない（文書は T-03 が変える）。受け入れ基準に `./mvnw clean verify`（結合テスト込み）は入れず、計画単位のレビュータスク T-04 で実行する
- 6行目の除外：`vault/` は計画一式（このタスク票自身が旧い文言を引用している）で、マージ前に除去されるので対象にしない
- ビルドのコマンドはシェルの `JAVA_HOME` が JDK 21 を指すため、受け入れ基準のとおり `JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64` を前に付けて実行する
