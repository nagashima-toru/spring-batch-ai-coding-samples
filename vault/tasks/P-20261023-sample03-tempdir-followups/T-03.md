# T-03 sample03-file-export.md に空白だけの値が別の JobInstance になることと format の空白の扱いを書く

## 目的
sample03 の解説文書に、`tempDir`・`format` の空文字・空白だけの値が、動作は未指定と同じでも未指定とは別の JobInstance になること（解消しない判断とその理由、リスタートのしかた）と、`format` の空白だけの値を `tempDir` と揃えて csv として扱うことを書く（GitHub Issue #110 の1点目・2点目の文書）。

## 決定済み
- 方式：空白だけの値が別の JobInstance になる点は解消せず、文書に明記する（理由は計画票の「分割方針」。下の箇条の文言に要約を入れる）。`format` の空白だけの値は `tempDir` と揃えて未指定（csv）として扱う（コードの変更は T-01）
- 新しい `## ` 見出しは作らない（`### ` も作らない）。書き足すのは既存の節の箇条と表だけ
- 「## 一時出力→配置」節の、`tempDir` を識別パラメータのままにする箇条（「`tempDir` は識別パラメータのままにする。…」）の直後に、次の箇条を1つ足す（文言はこのとおり。前後の説明を少し足すのはよい）
  - 「`tempDir`・`format` の空文字・空白だけの値は、動作は未指定と同じでも、識別パラメータなので未指定とは別の JobInstance になる（コマンドラインから起動すると Spring Boot が値の前後の空白を取り除くので、空白だけの値は空文字になる）。空文字・空白だけの値で起動して失敗した実行をリスタートするには、前回と同じ値で起動する。未指定で起動すると新しい JobInstance として出力 Step から出力し直す（出力ファイルは上書き生成なので冪等。docs/architecture.md §6.2）。JobParameters の作成時に空文字・空白だけの値を取り除く正規化はしない。正規化はコマンドライン引数から JobParameters を作る全ジョブ共通の処理を差し替えることになり、`JobParametersValidator` は値を検査するだけで書き換えられないため（sample05 の `inputFile` も空白だけを未指定として扱うだけで、正規化しない）」
- 「## 出力形式（format パラメータ）」節の表の1行目の「`csv`（既定。省略時も csv）」を「`csv`（既定。未指定・空文字・空白だけも csv）」に書き換える（省略時も csv の並びを残さない）
- 同じ節の表の直後の「上記以外の値は、起動時のパラメータ検証で拒否する（`InvalidJobParametersException`）。」の直前に、次の1文を足す：「`format` の空白だけの値も未指定と同じ csv にする（`tempDir` と同じく空白だけを未指定として扱う）。」
- 「未指定とは別の JobInstance になる」「取り除く正規化はしない」「空白だけの値も未指定と同じ csv」の3語句は、それぞれ文書の中に1回だけ書く（受け入れ基準が出現数 `1` を見るため）。既存の「`tempDir` の空白だけの値は未指定として扱う」の箇条は変えない
- コード（`Sample03JobConfig.java` など）は変えない。動作の実装は T-01 が行う
- `docs/architecture.md` は変えない（全ジョブ共通の方針は変えないため）
- 4行目の範囲は、リポジトリの文書（`batch-sample/`・`docs/`・`README.md`）。`vault/` は計画一式（このタスク票自身が旧い文言を引用している）で、マージ前に除去されるので対象にしない
- この文書は smoke の `(ref-1)` の対象文書ではない（`batch-sample/docs/` 配下）ので、`(ref-1)` の基準は入れない
