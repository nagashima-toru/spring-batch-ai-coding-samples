## 決定済み
- 解説だけを変える。コード・テスト・JSON ファイルは T-04・T-05 で作る（このタスクでは触らない）
- 既存の節（デモする機能・設定・実行方法・選ぶ/選ばない・実装ポイント）は残し、追記・修正する。既存の実行例（`syncDate=2026-07-14,java.time.LocalDate`）は消さない
- 書く内容（T-04・T-05 の実装と同じ決定。解説の正）:
  - 処理の流れ：ジョブの先頭で Decider（`InputSourceDecider`）が `inputFile` の有無を見る。未指定（または空文字）なら `sample05.00UserCountStep` → `sample05.01ImportStep`、指定ありなら `sample05.00UserCountStep` を飛ばして `sample05.01ImportStep` だけを実行する。Step 名はこのまま書く（既存の `sample05.01ImportStep` は改名できないため、前に入る Step を `00` にしたことも書く）
  - `sample05.00UserCountStep` は `AbstractApiCallTasklet` を継承した `ApiUserCountTasklet` で、件数 API `GET {base-url}/users/count`（Bearer トークン付き、レスポンス例 `{"count":3}`）を1回呼び、件数をログに出して Step の ExecutionContext に `apiUserCount` として保存する（取込前の疎通確認を兼ねる）。ページングで大量データを取るのは Chunk＋`RestApiPagingItemReader` の役割で、1回だけの呼出は Tasklet にする（§3.1）
  - 任意パラメータ `inputFile` を指定すると、API の代わりに保存済みの JSON 配列ファイルから `JsonItemReaderFactory` で取り込む（リプレイ用途。API 障害時の再取込や検証）。入力チェック・UPSERT は API 取込と同じ。ファイルが無い時は異常終了（終了コード1）。必須パラメータは `syncDate` のまま
  - 実行例に `inputFile=batch-sample/data/in/api-users.json` を付けた例を1つ足す（既存の実行例と同じ `./mvnw -q spring-boot:run ...` の形）。サンプル入力 `batch-sample/data/in/api-users.json` は T-05 で作るので、このタスクではバッククォートでパスを書くだけでよい
  - リトライ方針の節：HTTP 呼出のリトライは `BatchHttpClient` が `batch.core.http.retry.*`（既定 `max-attempts: 3`、指数バックオフ）で行い、architecture §5.2 に従って「Batch の `retry()` は設定しない」（この語のまま書く）。二重にすると試行回数が掛け算になるため。5xx・接続エラーが続くと `BatchHttpClient` が試行を使い切った後に「`RetryableSystemException` で異常終了（終了コード1）」（この語のまま書く）する。4xx は `SystemException` で即異常終了（既存の記述のまま）。この動作は結合テスト `Sample05ApiImportJobIT` で確かめていることも書く
  - 「デモする機能」に `AbstractApiCallTasklet`（件数取得 Step）・`JsonItemReaderFactory`（inputFile リプレイ）・`RetryableSystemException`（リトライ枯渇で異常終了）を足す
  - 「選ばない」表の `AbstractApiCallTasklet` の行は残してよい（本サンプルの件数取得 Step が実例であることを足してもよい）
- 文言は日本語。見出しの構成・追加位置は任せる
