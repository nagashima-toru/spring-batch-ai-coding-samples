# T-02 sample03 に一時出力→配置の Step と format=fixed の固定長出力を実装する

## 目的
T-01 で改訂した解説どおりに、sample03 を「一時ファイルに出力 → `FileMoveTasklet` で配置先へ移動」の2 Step にし、任意パラメータ `format=fixed` で `FixedLengthItemWriterFactory` による Shift_JIS 固定長を出力できるようにする。結合テストで動作を確かめる。

## 決定済み
- 変えるのは成果物の2ファイルだけ。解説（`batch-sample/docs/sample03-file-export.md`）は T-01 で確定済みなので変えない。解説と食い違う実装が必要になったら blocked にする
- ジョブ名 `sample03FileExportJob`（`JOB_NAME`）・既存の Step 名 `sample03.01ExportStep`・既存の Writer 名 `sample03SalesWriter`・Bean 名 `sample03ExportStep`・`sample03SalesReader`・`sample03FooterCallback` は変えない（メタデータに残るため。architecture §11「既存名の扱い」）
- Step 構成：`.start(sample03ExportStep).next(sample03FileMoveStep)`。新規 Step の名前は `sample03.02FileMoveStep`、Bean 名は `sample03FileMoveStep`。Tasklet の Bean は `@StepScope` の `sample03FileMoveTasklet`（`@Value("#{jobParameters['outputFile']}")` を受け取る）で、`new FileMoveTasklet(<一時ファイル>, <outputFile の親ディレクトリ>, true)` を返す。Step には既存と同じく `loggingStepExecutionListener` を付け、`.tasklet(tasklet, transactionManager)` で組む
- 一時ファイルの場所：`Path.of(outputFile).toAbsolutePath()` の親ディレクトリを P、ファイル名を N として `P/tmp/N`。計算は `Sample03JobConfig` の package-private な static メソッド1つ（例：`static Path tempFileOf(String outputFile)`）にまとめ、Writer と Tasklet の両方から使う。Writer の Bean を作る時に `Files.createDirectories` で `P/tmp` を作る（FlatFileItemWriter が親ディレクトリを作るかどうかに依存しない）
- Writer は既存の `@StepScope` の Bean `sample03SalesWriter`（戻り値の型 `FlatFileItemWriter<SalesTransaction>`）1つの中で `@Value("#{jobParameters['format']}") String format` を見て分岐する。null・空文字・`csv` は今の `CsvItemWriterFactory.create(...)`（Writer 名 `sample03SalesWriter`・ヘッダ・トレーラはそのまま）、`fixed` は `FixedLengthItemWriterFactory.create("sample03SalesFixedWriter", new FileSystemResource(<一時ファイル>), SalesTransaction.class, Charset.forName("Shift_JIS"), null, null, new String[] {"id", "customerCode", "amount", "soldAt"}, new int[] {10, 10, 12, 10})`。リソースはどちらも一時ファイル
- 固定長はヘッダ・トレーラ無し（header・footerCallback に null）。`SummaryFooterCallback` の Step への listener 登録はそのまま残してよい（固定長では使われないだけ）
- パラメータ検証：`JobParametersValidators.requiredAndOptional(new String[] {"outputFile"}, new String[] {"format"})` で必須・任意を検証してから、format が null・空文字・`csv`・`fixed` 以外なら `InvalidJobParametersException` を投げる `JobParametersValidator` のラムダ（または private static メソッド）を `Sample03JobConfig` の中に書き、`.validator(...)` に渡す（`JobParametersValidators` の Javadoc の「ラムダで実装し、必須チェックと組み合わせる」拡張ポイントどおり）。別クラスは作らない。未知のキー（`testRunId` など）は拒否しない
- クラスの Javadoc（デモする機能・実行方法）に、一時出力→配置と `format=fixed` の実行例を足す
- 結合テスト（`Sample03FileExportJobIT` に3メソッド追加。既存2メソッドは変えずに通す）。メソッド名は次のとおり（受け入れ基準が名前で照合する）:
  - `CSV出力の場合_一時ファイルを配置先へ移動し一時ディレクトリに残さない`：`@TempDir` 配下の `outputFile` で起動し、COMPLETED、配置先のファイルがある、`<tempDir>/tmp/<ファイル名>` が無い、実行された Step 名に `sample03.01ExportStep` と `sample03.02FileMoveStep` の両方があることを確かめる
  - `formatにfixedを指定した場合_Shift_JISの固定長ファイルを配置先へ出力する`：明細2件（うち1件は `customerCode` が `顧客A`）を投入して `format=fixed` で起動し、COMPLETED、Shift_JIS で読んだ行数が2（ヘッダ・トレーラ無し）、各行の Shift_JIS のバイト長が42、`顧客A` の行のバイト 10〜19 を Shift_JIS で読んだ値が `顧客A` の後ろに半角スペース5つであることを確かめる
  - `formatに未定義の値を指定した場合_InvalidJobParametersExceptionで起動を拒否する`：`format=xml` で `jobOperator.start` すると `InvalidJobParametersException` が投げられることを `assertThatThrownBy` で確かめる
- テストデータは各テストが自前で投入する（既存の `@BeforeEach` の truncate を使う）。id は採番値なので完全一致では比べない
- Flyway のファイルは追加・変更しない。batch-core は変えない
- `./mvnw clean verify` は Docker と JDK 25 が必要。この環境では使えることをオーケストレーターが確認済み
