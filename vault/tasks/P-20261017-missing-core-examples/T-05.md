# T-05 sample05 に inputFile 指定時の JSON ファイル取込（リプレイ）を実装する

## 目的
T-03 で改訂した解説どおりに、sample05 で任意パラメータ `inputFile` が指定された時は、件数取得 Step を飛ばし、API の代わりに保存済み JSON ファイルから `JsonItemReaderFactory` で取り込めるようにする（リプレイ用途）。サンプル入力の JSON ファイルを追加し、単体・結合テストで確かめる。

## 決定済み
- 解説（`batch-sample/docs/sample05-api-import.md`）は T-03 で確定済みなので変えない。解説と食い違う実装が必要になったら blocked にする
- `InputSourceDecider implements JobExecutionDecider`。定数 `public static final String API = "API"`・`public static final String FILE = "FILE"`。`jobExecution.getJobParameters().getString("inputFile")` が null でも空白だけでもなければ `new FlowExecutionStatus(FILE)`、それ以外は `new FlowExecutionStatus(API)` を返す
- ジョブの Flow：`new JobBuilder(...)...start(decider).on(InputSourceDecider.FILE).to(sample05ImportStep).from(decider).on(InputSourceDecider.API).to(sample05UserCountStep).next(sample05ImportStep).end().build()` の形（Decider のインスタンスは `Sample06JobConfig` と同じくジョブの Bean の中で `new` してよい）。Step 名・ジョブ名・既存の Bean 名は変えない
- パラメータ検証：`JobParametersValidators.requiredAndOptional(new String[] {"syncDate"}, new String[] {"inputFile"})` に替える。未知のキー（`testRunId` など）は拒否しない（architecture §3.4）
- Reader：既存の Bean `sample05UserReader` を `@StepScope` にし、戻り値の型を `ItemStreamReader<ApiUserResponse>` にする。`@Value("#{jobParameters['inputFile']}") String inputFile` が null でも空白だけでもなければ `JsonItemReaderFactory.create("sample05UserJsonReader", new FileSystemResource(inputFile), ApiUserResponse.class)`、それ以外は今の `RestApiPagingItemReader`（Reader 名 `sample05UserReader` のまま）を返す。`sample05ImportStep` の引数の型も合わせて変える。Processor・Writer・Skip の設定は共通のまま
- ファイルが無い時は JsonItemReader の open で失敗して異常終了（終了コード1）でよい（存在チェックの Step は足さない）
- サンプル入力 `batch-sample/data/in/api-users.json`（UTF-8、JSON 配列、3件。キーは `userId`・`userName`・`email`）。内容は次のとおり（1要素1行の整形でよい）：`U101`/`高橋`/`u101@example.com`、`U102`/`田中`/`u102@example.com`、`U103`/`伊藤`/`u103@example.com`
- 単体テスト `InputSourceDeciderTest`（Spring コンテキストを使わない）。メソッドは次の3つ（1つ目の名前は受け入れ基準が照合する）：`inputFileが指定された場合_FILEを返す`・`inputFileが未指定の場合_APIを返す`・`inputFileが空文字の場合_APIを返す`
- 結合テスト `Sample05ApiImportJobIT`（既存のテストは変えずに通す）:
  - スタブの `/users` へのリクエスト数も static な `AtomicInteger`（例：`USERS_REQUESTS`）で数え、`@BeforeEach` で0に戻す
  - `inputFileを指定した場合_APIを呼ばずJSONファイルから取り込む`：テストが `@TempDir` に JSON 配列ファイル（2〜3件。テスト自前のデータ。`batch-sample/data/in/api-users.json` は使わない）を書いて `syncDate` と `inputFile` で起動し、COMPLETED、`app.api_user` の件数がファイルの件数と同じ、`USERS_REQUESTS` と `COUNT_REQUESTS` がどちらも0、実行された Step 名に `sample05.00UserCountStep` が無いことを確かめる
  - `inputFileに存在しないファイルを指定した場合_異常終了する`：存在しないパスで起動し、`BatchStatus.FAILED`、ExitStatus の終了コードが `ExitStatus.FAILED.getExitCode()` であることを確かめる
- クラスの Javadoc（デモする機能・実行方法）に `inputFile` の実行例を足す
- Flyway のファイルは追加・変更しない。batch-core は変えない
- `./mvnw clean verify` は Docker と JDK 25 が必要。この環境では使えることをオーケストレーターが確認済み
