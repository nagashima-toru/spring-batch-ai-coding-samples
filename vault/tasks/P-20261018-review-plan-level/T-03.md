# T-03 review-standards SKILL.md の手順4をハーネスでは計画単位のレビュータスクに任せる形にする

## 目的
ハーネスの review-standards のタスクではチェックリスト（規約）の確認（手順1〜3）だけを行い、組み込みの `/code-review`（手順4）は計画単位のレビュータスクに任せることを SKILL.md に書く。あわせて、範囲を「そのタスクの差分」とする誤った箇条を直す。対話や sdd-pipeline でスキルを使う時は従来どおり手順4を実行する。

## 入力
- `.claude/skills/review-standards/SKILL.md`（現行。「## 進め方」の手順4）
- `.claude/agents/planner.md` の「計画単位のレビュータスク」節、`.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節（写さない）

## 成果物
- `.claude/skills/review-standards/SKILL.md`（1ファイル）

## 受け入れ基準
- ハーネスのタスクでは手順4を行わない箇条がある：`grep -c 'ハーネスのタスクでは手順4を行わず、計画単位のレビュータスクに任せる' .claude/skills/review-standards/SKILL.md` の出力が `1`
- 手順4の範囲が計画単位のレビュータスクの範囲と同じであることが書かれている：`grep -c '計画単位のレビュータスクの範囲（ベースブランチとの分岐点からの計画全体の差分）と同じである' .claude/skills/review-standards/SKILL.md` の出力が `1`
- 手順4の範囲（`git diff --merge-base main`）は残っている：`grep -c 'git diff --merge-base main' .claude/skills/review-standards/SKILL.md` の出力が `1`
- タスクの差分を前提にした記述が残っていない：`grep -c -e 'merge-base work/' -e 'タスクの差分' -e '対象の worktree の絶対パスを引数で明示' .claude/skills/review-standards/SKILL.md` の出力が `0`
- 見出しが変わっていない：`grep -c -x -e '## 入力と出力（工程連鎖）' -e '## 進め方' -e '## 最重要観点（順に確認する）' .claude/skills/review-standards/SKILL.md` の出力が `3`
- smoke の `(ref-1)` が通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` の出力が `1`
- smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- 手順4の1行目（「同じ差分に対して、Claude Code 組み込みの `/code-review`（Skill ツールの `code-review`）を必ず実行する。」）と、その後の理由の2行は変えない
- 手順4の最初の箇条（理由の行の直後、「範囲は、…」の箇条の前）として、次の1行を足す：`` - ハーネスのタスクでは手順4を行わず、計画単位のレビュータスクに任せる（`.claude/agents/planner.md` の「計画単位のレビュータスク」節。review-standards のタスクは手順1〜3だけを行う）。対話や `sdd-pipeline` でこのスキルを使う時は手順4を実行する ``
- 「範囲は、レビュー対象のジョブで変えた差分（…）で、`git diff --merge-base main` の差分をレビューする。」の文は残し、その後ろの「ハーネスのタスクでは、対象の worktree の絶対パスを引数で明示して渡し、…（明示しないと呼び出し元の作業ディレクトリをレビューする）」の文は消す（ハーネスのタスクでは手順4を行わないため）
- 「この範囲は、ハーネスの受け入れ基準の `/code-review` の行（…）の範囲とは別である。その行の範囲はそのタスクの差分（`git -C <worktree のパス> diff --merge-base work/<計画IDの英小文字>`）で、…」の箇条は、次の1行に置き換える：`` - この範囲は、ハーネスの計画単位のレビュータスクの範囲（ベースブランチとの分岐点からの計画全体の差分）と同じである。その判定は `.claude/agents/verifier.md`・`.claude/agents/creator.md` の「コードレビューを参照する基準」の節に従う ``
- [Ask] の箇条の「（ハーネスのタスクでは creator が直さず blocked にする）」と、差分の外の箇条の「（ハーネスでは verifier が同じ接頭辞で verdict の reasons に書き、PR 作成時の取り出しの対象になる）」は変えない（計画単位のレビュータスクでも同じ扱いのため）
- 「例外（パイプライン実行時）」の段落（手順4の `/code-review` 由来を含む）は変えない（sdd-pipeline では手順4を実行するため）
- frontmatter（name・description）と区分の表は変えない
- 書かない語：「タスクの差分」「merge-base work/」
- 新しいファイルへのバッククォート参照は足さない（既存のパスだけを書く）
