# T-06 verifier ルール code-review.md を計画単位のレビュータスクの前提に直す

## 目的
`/code-review` の行を Must/Should/Ask の物差しで判定する verifier ルールを、計画単位のレビュータスク（範囲は計画全体の差分）の前提に直す。範囲を「そのタスクの差分」とする箇条を消す。

## 入力
- `vault/rules/verifier/code-review.md`（現行）
- `.claude/agents/verifier.md` の「コードレビューを参照する基準の判定」節（写さない）
- `vault/rules/planner/code-review-criterion.md`（計画単位のレビュータスクの1行目がこのファイルを参照する。T-01 で書き直す）

## 成果物
- `vault/rules/verifier/code-review.md`（1ファイル）

## 受け入れ基準
- `/code-review` の行を持つのが計画単位のレビュータスクであることが書かれている：`grep -c '..code-review. の行を持つのは計画単位のレビュータスクで' vault/rules/verifier/code-review.md` の出力が `1`
- タスクの差分を前提にした記述が残っていない：`grep -c -e 'タスクの差分' -e 'review-standards のタスクでも' vault/rules/verifier/code-review.md` の出力が `0`
- 参照時だけ使う条件が残っている：`grep -c 'このルールは、受け入れ基準の行がこのファイル' vault/rules/verifier/code-review.md` の出力が `1`
- Must/Should/Ask の対応と差分の外の扱いが残っている：`grep -c -e '^- .Must. 相当の指摘' -e '^- .Ask. 相当の指摘' -e '^- .Should. 相当の指摘' -e '^- 差分の外（既存コード）への指摘は' vault/rules/verifier/code-review.md` の出力が `4`
- 見出しが3つそろっている：`grep -c -x -e '## 目的' -e '## ルール' -e '## 確認方法' vault/rules/verifier/code-review.md` の出力が `3`
- verifier のルールとして列挙され続ける：`bash scripts/rules.sh verifier | grep -c 'verifier/code-review.md'` の出力が `1`

## 決定済み
- 1行目の見出しと「## 目的」は変えない
- 「## ルール」の1つ目（このルールは、受け入れ基準の行がこのファイル（`vault/rules/verifier/code-review.md`）を参照している時だけ判定に使う）と2つ目（範囲・呼び方・接頭辞などは `.claude/agents/verifier.md` の「コードレビューを参照する基準の判定」節に従い、ここには写さない）はそのまま残す
- 最後の箇条「- review-standards のタスクでも、`/code-review` の行の範囲はそのタスクの差分（計画ブランチとの分岐点から）で、review-standards の手順4の範囲（ジョブで変えた差分）に広げない」は消し、2つ目の箇条の直後に次の1行を置く：`` - `/code-review` の行を持つのは計画単位のレビュータスクで（`.claude/agents/planner.md` の「計画単位のレビュータスク」節）、範囲は計画全体の差分（ベースブランチとの分岐点から）とする。通常のタスク（review-standards のタスクを含む）の受け入れ基準には `/code-review` の行は無い ``
- [Must]・[Ask]・[Should]・差分の外・規約（チェックリスト）の各箇条は行頭の形（`- [Must] 相当の指摘` など）を変えずに残す。[Must] の括弧内の「差分で変えた行」は「計画の差分で変えた行」にしてよい
- 「## 確認方法」は変えなくてよい
- 書かない語：「タスクの差分」「review-standards のタスクでも」
