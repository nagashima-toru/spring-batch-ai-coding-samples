# T-02 planner ルール job-task-split.md に計画単位のレビュータスクを足す

## 目的
ジョブ1本の計画で、工程5タスクの後に計画単位のレビュータスク（ハーネス planner の「計画単位のレビュータスク」節）が付くことを planner ルールに反映し、タスク数と確認方法を6タスク前提に合わせる。

## 入力
- `vault/rules/planner/job-task-split.md`（現行）
- `.claude/agents/planner.md` の「計画単位のレビュータスク」節（写さない）

## 成果物
- `vault/rules/planner/job-task-split.md`（1ファイル）

## 受け入れ基準
- 工程5タスクの後に計画単位のレビュータスクを足す箇条がある：`grep -c '工程5タスクの後に、..claude/agents/planner.md. の「計画単位のレビュータスク」節に従って計画単位のレビュータスクを1件足す' vault/rules/planner/job-task-split.md` の出力が `1`
- タスク数の記述が6タスクになっている：`grep -c '計画単位のレビュータスク1件の6タスクで、1計画7タスク以下の上限に収まる' vault/rules/planner/job-task-split.md` の出力が `1`
- 確認方法がタスク表6行の前提になっている：`grep -c 'タスク表が6行で' vault/rules/planner/job-task-split.md` の出力が `1`
- 5タスク前提の記述が残っていない：`grep -c -e 'タスク表が5行' -e '（5タスクで、' vault/rules/planner/job-task-split.md` の出力が `0`
- 見出しが3つそろっている：`grep -c -x -e '## 目的' -e '## ルール' -e '## 確認方法' vault/rules/planner/job-task-split.md` の出力が `3`
- planner のルールとして列挙され続ける：`bash scripts/rules.sh planner | grep -c 'job-task-split.md'` の出力が `1`

## 決定済み
- 「## ルール」9行目の括弧 `（5タスクで、1計画7タスク以下の上限に収まる）` を `（工程5タスクと計画単位のレビュータスク1件の6タスクで、1計画7タスク以下の上限に収まる）` に置き換える
- 「## ルール」の「各タスクは `after` に直前の工程のタスク ID を書く…」の箇条の直後に、次の1行を足す：`` - 工程5タスクの後に、`.claude/agents/planner.md` の「計画単位のレビュータスク」節に従って計画単位のレビュータスクを1件足す（implementation などの工程タスクの成果物にコードが入るため。導入先の補足は `vault/rules/planner/code-review-criterion.md`） ``
- 「## ルール」10行目の「ジョブ1本は implementation → … → system-test の順の5タスクに分ける」と、ビルドの成功を入れる箇条（「全タスクの受け入れ基準に、…」）は変えない（計画単位のレビュータスクは先行タスクのビルドの確認コマンドを再掲するので食い違わない）
- 「## 確認方法」の1行目を `` - 計画票のタスク表が6行で、工程5タスクの `after` が上記の順に1本の鎖になっている（先頭以外の `after` が直前の ID だけ）。6行目の計画単位のレビュータスクが工程5タスクすべてを `after` に持つ `` に置き換える
- 計画単位のレビュータスクの判定・title・受け入れ基準などハーネスの節の中身は写さない
- 書かない語：「タスクの差分」「コードを変えるタスク」

## 進捗
- 読んだルール: vault/rules/common/project-docs.md, vault/rules/creator/code-review.md, vault/rules/creator/skill-workflow.md
- vault/rules/planner/job-task-split.md を「決定済み」どおり3か所編集（9行目の括弧、レビュータスクの箇条追加、確認方法1行目）
- 受け入れ基準6件の確認コマンドを実行し、出力は 1 / 1 / 1 / 0 / 3 / 1 で期待どおり。禁止語（タスクの差分・コードを変えるタスク）は0件
- /code-review 参照の基準は無いので未実行
