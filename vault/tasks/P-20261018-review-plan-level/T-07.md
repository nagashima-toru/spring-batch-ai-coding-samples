# T-07 development-guide.md 2.4 末尾の段落を計画単位のレビュータスク前提に書き直す

## 目的
`docs/development-guide.md` §2.4 末尾の「コードを変えるタスクの受け入れ基準には…」の段落を、計画単位のレビュータスク（コードを変更する計画の最後に付き、計画全体の差分に `/code-review` を実行する）の前提に書き直し、ゴールの範囲にタスクごとの `/code-review` を前提にした記述が残っていないことを確かめる。

## 入力
- `docs/development-guide.md` の「### 2.4 ハーネスで実装以降を進める場合」節（末尾の段落）
- T-01〜T-06 で直した `vault/rules/planner/code-review-criterion.md`・`vault/rules/planner/job-task-split.md`・`.claude/skills/review-standards/SKILL.md`・`vault/rules/creator/code-review.md`・`vault/rules/creator/skill-workflow.md`・`vault/rules/verifier/code-review.md`
- `.claude/agents/planner.md` の「計画単位のレビュータスク」節

## 成果物

- 計画単位のレビュータスクが付くことが書かれている：`grep -c 'コードを変更する計画では、最後に「計画の差分が ..code-review. を通過する」タスク（計画単位のレビュータスク）が付く' docs/development-guide.md` の出力が `1`
- creator・verifier がそのタスクで計画全体の差分に実行することが書かれている：`grep -c 'そのタスクで計画全体の差分（ベースブランチとの分岐点から）に組み込みの ..code-review. を実行する' docs/development-guide.md` の出力が `1`
- 見出しが変わっていない：`git diff --merge-base work/p-20261018-review-plan-level -- docs/development-guide.md | grep -c '^[-+]#'` の出力が `0`、かつ `grep -c -x '### 2.4 ハーネスで実装以降を進める場合' docs/development-guide.md` の出力が `1`
- ゴールの範囲にタスクごとの `/code-review` を前提にした記述が残っていない：`git grep -n -e 'merge-base work/' -e 'タスクの差分' -e 'コードを変えるタスク' -e '手順4の組み込み ..code-review. を含む' -- .claude/skills/ vault/rules/ docs/development-guide.md docs/coding-standards.md CLAUDE.md .github/` の出力が空

- smoke 全体が通る：`bash scripts/smoke.sh 2>&1 | tail -1` の出力が `fail=0` を含む

## 決定済み
- §2.4 の末尾の段落（「コードを変えるタスクの受け入れ基準には「`/code-review` で差分に致命的な指摘が残っていない」の行が入る…人が `/plan unblock` で答える。」の1段落）だけを、次の1段落に置き換える（1行の段落のまま。見出しとほかの段落・表は変えない）：
  `` コードを変更する計画では、最後に「計画の差分が `/code-review` を通過する」タスク（計画単位のレビュータスク）が付く（`.claude/agents/planner.md` の「計画単位のレビュータスク」節。導入先の補足は `vault/rules/planner/code-review-criterion.md`）。通常のタスクの受け入れ基準には `/code-review` の行は入らず、review-standards のタスクも手順4の `/code-review` を行わない。creator は完了報告の前に、verifier は判定の時に、そのタスクで計画全体の差分（ベースブランチとの分岐点から）に組み込みの `/code-review` を実行する。指摘と `/review-standards` の区分（Must/Should/Ask）の対応は `vault/rules/creator/code-review.md`・`vault/rules/verifier/code-review.md` にある。差分の外（既存コード）への指摘は FAIL にせず、PR 本文の「verifier の指摘」に残る。直すのに設計の改訂が要る指摘は blocked になり、人が `/plan unblock` で答える。 ``
- §2.2 の表の `review-standards` の行（「チェックリストの確認と組み込みの `/code-review` の両方を行う」）は変えない（対話や sdd-pipeline で使う時の説明で、手順4は従来どおり実行するため）
- ゴールの範囲の確認（受け入れ基準の4行目）から除外する範囲と理由：`.claude/agents/`・`docs/vault-spec.md`・`scripts/`・`.claude/hooks/` はハーネス本体で、`merge-base work/` を差分確認のコマンドとして正しく使っており、この計画では変えないため対象にしない。`vault/plans/`・`vault/tasks/`・`vault/log/` は計画一式で、旧前提の語を説明のために引用するため対象にしない。batch-sample は触らない
- 4行目で出力が空にならない時は、`docs/development-guide.md` 以外のファイルを直さない（宣言外の変更は差分ゲートで差し戻される）。その時は「進捗」に該当行を書いて完了報告を `blocked: <質問文>` にする
- 書かない語：「タスクの差分」「コードを変えるタスク」
