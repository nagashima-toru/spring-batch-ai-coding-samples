# T-03 job05 の ApiUser・ApiUserMapper を job05_api_import へ移す

## 目的
job05 からしか使われない `ApiUser`・`ApiUserMapper` を `common/` から `job05_api_import` パッケージへ移し、サンプル05を1パッケージで読めるようにする（Issue #64）。

## 入力
- `batch-sample/src/main/java/com/example/batch/sample/common/ApiUser.java`・`ApiUserMapper.java`（移動元）
- `batch-sample/src/main/resources/mapper/ApiUserMapper.xml`
- `batch-sample/src/main/java/com/example/batch/sample/job05_api_import/`（移動先。`Sample05JobConfig.java`・`ApiUserItemProcessor.java`）
- `batch-sample/src/test/java/com/example/batch/sample/job05_api_import/`（`ApiUserItemProcessorTest.java`・`Sample05ApiImportJobIT.java`）
- `docs/architecture.md` §2.1（パッケージ構成）、`CLAUDE.md` の「禁止事項」

## 成果物
- 主な成果物：`batch-sample/src/main/java/com/example/batch/sample/job05_api_import/ApiUserMapper.java`（移動先の Mapper IF）
- 変えるファイル（すべて）
  - `batch-sample/src/main/java/com/example/batch/sample/job05_api_import/ApiUser.java`（新規・移動先）
  - `batch-sample/src/main/java/com/example/batch/sample/job05_api_import/ApiUserMapper.java`（新規・移動先）
  - `batch-sample/src/main/java/com/example/batch/sample/common/ApiUser.java`（削除）
  - `batch-sample/src/main/java/com/example/batch/sample/common/ApiUserMapper.java`（削除）

## 受け入れ基準
- 移動先の2ファイルがある：`ls batch-sample/src/main/java/com/example/batch/sample/job05_api_import/ApiUser.java batch-sample/src/main/java/com/example/batch/sample/job05_api_import/ApiUserMapper.java` が2つのパスを表示し、エラーを出さない
- `common/` に移動元が残っていない：`ls batch-sample/src/main/java/com/example/batch/sample/common/ | grep -c '^ApiUser'` が `0`
- 旧パッケージ名の参照がリポジトリに残っていない：`git grep -l --untracked 'sample.common.ApiUser' -- ':!vault/'` の出力が空
- Mapper XML の namespace が移動先を指す：`grep -c 'sample.job05_api_import.ApiUserMapper' batch-sample/src/main/resources/mapper/ApiUserMapper.xml` が `1`
- 結合テストを含むビルドが通る（Checkstyle・SpotBugs・単体テスト・`Sample05ApiImportJobIT`・batch-sample のカバレッジ80%）：`JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 ./mvnw clean verify 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` が `1`

## 決定済み
- 移動は `git mv` で行い、移動したファイルの `package` 宣言を `package com.example.batch.sample.job05_api_import;` に書き換える。クラス名・メソッド・record の成分・Javadoc の本文は変えない（パッケージ移動だけ）
- 同じパッケージになるため、`ApiUserItemProcessor.java`・`Sample05JobConfig.java`・テスト2本の `import com.example.batch.sample.common.ApiUser;`・`import com.example.batch.sample.common.ApiUserMapper;` は書き換えずに削除する（Checkstyle の `RedundantImport`・`UnusedImports` に当たるため）。`SampleProperties` の import は `common` のまま残す
- `ApiUserMapper.xml` は `src/main/resources/mapper/` に置いたまま動かさない（`application.yml` の `mybatis.mapper-locations: classpath:mapper/*.xml` で読むため。案件ジョブも同じ置き方）。中の `namespace` を `com.example.batch.sample.job05_api_import.ApiUserMapper` に、`parameterType` を `com.example.batch.sample.job05_api_import.ApiUser` に書き換える
- `Sample05JobConfig.java` の `.statementId("com.example.batch.sample.common.ApiUserMapper.upsert")` を `com.example.batch.sample.job05_api_import.ApiUserMapper.upsert` に書き換える（XML の namespace と一致させる。食い違いは結合テストで失敗する）
- Mapper の登録は `@Mapper` の自動スキャン（基底パッケージ `com.example.batch.sample` 配下）なので、`@MapperScan` の追加や設定変更は要らない
- 移動先に同名のクラスは無い（既存は `ApiUserResponse`・`ApiUserCountResponse` など別名）。`docs/` には旧パッケージ名の参照が無いので変えない
- 旧パッケージ名の残りの確認から `vault/` を除くのは、計画票・タスク票がこの旧名を説明として含むため。`target/` は `git grep` の対象外（git 管理外）
- ビルドは結合テスト込みの `./mvnw clean verify` で確かめる（Docker が要る。`docker info` が失敗する時は blocked にして question に書く）
