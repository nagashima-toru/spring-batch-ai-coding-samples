# T-04 job06 の WorkRecord・WorkMapper を job06_flow_job へ移す

## 目的
job06 からしか使われない `WorkRecord`・`WorkMapper` を `common/` から `job06_flow_job` パッケージへ移し、サンプル06を1パッケージで読めるようにする（Issue #64）。

## 入力
- `batch-sample/src/main/java/com/example/batch/sample/common/WorkRecord.java`・`WorkMapper.java`（移動元）
- `batch-sample/src/main/resources/mapper/WorkMapper.xml`
- `batch-sample/src/main/java/com/example/batch/sample/job06_flow_job/`（移動先。`Sample06JobConfig.java`・`WorkItemProcessor.java`・`WorkSummaryTasklet.java`）
- `batch-sample/src/test/java/com/example/batch/sample/job06_flow_job/`（`WorkItemProcessorTest.java`・`Sample06FlowJobIT.java`）
- `docs/architecture.md` §2.1（パッケージ構成）、`CLAUDE.md` の「禁止事項」

## 受け入れ基準
- 移動先の2ファイルがある：`ls batch-sample/src/main/java/com/example/batch/sample/job06_flow_job/WorkRecord.java batch-sample/src/main/java/com/example/batch/sample/job06_flow_job/WorkMapper.java` が2つのパスを表示し、エラーを出さない
- `common/` に移動元が残っていない：`ls batch-sample/src/main/java/com/example/batch/sample/common/ | grep -c '^Work'` が `0`
- 旧パッケージ名の参照がリポジトリに残っていない：`git grep -l --untracked 'sample.common.Work' -- ':!vault/'` の出力が空
- Mapper XML の namespace が移動先を指す：`grep -c 'sample.job06_flow_job.WorkMapper' batch-sample/src/main/resources/mapper/WorkMapper.xml` が `1`
- 結合テストを含むビルドが通る（Checkstyle・SpotBugs・単体テスト・`Sample06FlowJobIT`・batch-sample のカバレッジ80%）：`JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 ./mvnw clean verify 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` が `1`

## 決定済み
- 移動は `git mv` で行い、移動したファイルの `package` 宣言を `package com.example.batch.sample.job06_flow_job;` に書き換える。クラス名・メソッド・record の成分・Javadoc の本文は変えない（パッケージ移動だけ）
- 同じパッケージになるため、`Sample06JobConfig.java`・`WorkItemProcessor.java`・`WorkSummaryTasklet.java`・テスト2本の `import com.example.batch.sample.common.WorkRecord;`・`import com.example.batch.sample.common.WorkMapper;` は書き換えずに削除する（Checkstyle の `RedundantImport`・`UnusedImports` に当たるため）
- `WorkMapper.xml` は `src/main/resources/mapper/` に置いたまま動かさない（`application.yml` の `mybatis.mapper-locations: classpath:mapper/*.xml` で読むため。案件ジョブも同じ置き方）。中の `namespace` を `com.example.batch.sample.job06_flow_job.WorkMapper` に、`parameterType` を `com.example.batch.sample.job06_flow_job.WorkRecord` に書き換える
- `Sample06JobConfig.java` の `.statementId("com.example.batch.sample.common.WorkMapper.upsert")` を `com.example.batch.sample.job06_flow_job.WorkMapper.upsert` に書き換える（XML の namespace と一致させる。食い違いは結合テストで失敗する）
- Mapper の登録は `@Mapper` の自動スキャン（基底パッケージ `com.example.batch.sample` 配下）なので、`@MapperScan` の追加や設定変更は要らない
- 移動先に同名のクラスは無い（既存は `WorkCsvRecord`・`WorkItemProcessor` など別名）。`docs/` には旧パッケージ名の参照が無いので変えない
- 旧パッケージ名の残りの確認から `vault/` を除くのは、計画票・タスク票がこの旧名を説明として含むため。`target/` は `git grep` の対象外（git 管理外）
- ビルドは結合テスト込みの `./mvnw clean verify` で確かめる（Docker が要る。`docker info` が失敗する時は blocked にして question に書く）
