## 受け入れ基準
- `/code-review` で計画の差分に致命的な指摘が残っていない（`vault/rules/verifier/code-review.md` に従って判定する）
- 結合テストを含むビルドが通る（全モジュールの Checkstyle・SpotBugs・単体テスト・結合テスト・batch-sample のカバレッジ80%）：`JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 ./mvnw clean verify 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` が `1`
- `common/` に共有のものだけが残っている：`ls batch-sample/src/main/java/com/example/batch/sample/common/` の出力が `SalesMapper.java`・`SalesTransaction.java`・`SampleProperties.java` の3つだけ
- smoke の参照検査が通る：`bash scripts/smoke.sh 2>&1 | grep -c '^  ok   (ref-1) '` が `1`

## 決定済み
- レビューの範囲は、ベースブランチ（`HARNESS_BASE_BRANCH`、前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）とする
- 計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない
- 致命的な指摘が無ければ成果物を変えず、「進捗」への記録だけでよい（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）
- 差分の外（既存コード）・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは、`.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節に従う
- この計画はパッケージの移動だけなので、クラス名・メソッド・SQL・Javadoc の本文を変える指摘は設計や仕様の変更が要る指摘として扱い、ここでは直さない
- `SalesTransaction`・`SalesMapper`（job03・job04 で共有）と `SampleProperties`（複数ジョブで参照）は `common/` に残すのが計画の決定であり、移す指摘は直さない
- ビルドは結合テスト込みの `./mvnw clean verify` で確かめる（Docker が要る。`docker info` が失敗する時は blocked にして question に書く）

## 進捗
- 読んだルール: vault/rules/common/project-docs.md, vault/rules/creator/code-review.md, vault/rules/creator/skill-workflow.md
- `/code-review` 実行 1 回（範囲: `git diff --merge-base main`、vault 除く）。Must 0 件・Ask 0 件・Should 3 件。致命的な指摘（クラッシュ・データ破損・誤った結果）は 0 件のため成果物は変更なし
  - Should: WorkSummaryTasklet.java の import 削除後の空行重複（直さない）
  - Should: docs/architecture.md §2.1 に配置規則が未記載（成果物に宣言されていないファイルのため直さない）
  - Should: MyBatis の FQCN 文字列は手書き（指摘どおり結合テスト込みビルドで確認済み）
- 受け入れ基準の確認: `./mvnw clean verify`（JAVA_HOME=JDK25）の BUILD SUCCESS 件数 = 1、common/ は SalesMapper.java・SalesTransaction.java・SampleProperties.java の3つのみ、smoke (ref-1) ok 件数 = 1
