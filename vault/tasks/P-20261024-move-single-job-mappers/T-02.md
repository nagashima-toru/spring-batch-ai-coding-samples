# T-02 job02 の Product・ProductMapper を job02_fixedlength_import へ移す

## 目的
job02 からしか使われない `Product`・`ProductMapper` を `common/` から `job02_fixedlength_import` パッケージへ移し、サンプル02を1パッケージで読めるようにする（Issue #64）。

## 入力
- `batch-sample/src/main/java/com/example/batch/sample/common/Product.java`・`ProductMapper.java`（移動元）
- `batch-sample/src/main/resources/mapper/ProductMapper.xml`
- `batch-sample/src/main/java/com/example/batch/sample/job02_fixedlength_import/`（移動先。`Sample02JobConfig.java`・`ProductItemProcessor.java`）
- `batch-sample/src/test/java/com/example/batch/sample/job02_fixedlength_import/`（`ProductItemProcessorTest.java`・`Sample02FixedLengthImportJobIT.java`）
- `docs/architecture.md` §2.1（パッケージ構成）、`CLAUDE.md` の「禁止事項」

## 成果物
- 主な成果物：`batch-sample/src/main/java/com/example/batch/sample/job02_fixedlength_import/ProductMapper.java`（移動先の Mapper IF）
- 変えるファイル（すべて）
  - `batch-sample/src/main/java/com/example/batch/sample/job02_fixedlength_import/Product.java`（新規・移動先）
  - `batch-sample/src/main/java/com/example/batch/sample/job02_fixedlength_import/ProductMapper.java`（新規・移動先）
  - `batch-sample/src/main/java/com/example/batch/sample/common/Product.java`（削除）
  - `batch-sample/src/main/java/com/example/batch/sample/common/ProductMapper.java`（削除）
  - `batch-sample/src/main/java/com/example/batch/sample/job02_fixedlength_import/ProductItemProcessor.java`
  - `batch-sample/src/main/java/com/example/batch/sample/job02_fixedlength_import/Sample02JobConfig.java`
  - `batch-sample/src/main/resources/mapper/ProductMapper.xml`
  - `batch-sample/src/test/java/com/example/batch/sample/job02_fixedlength_import/ProductItemProcessorTest.java`
  - `batch-sample/src/test/java/com/example/batch/sample/job02_fixedlength_import/Sample02FixedLengthImportJobIT.java`

## 受け入れ基準
- 移動先の2ファイルがある：`ls batch-sample/src/main/java/com/example/batch/sample/job02_fixedlength_import/Product.java batch-sample/src/main/java/com/example/batch/sample/job02_fixedlength_import/ProductMapper.java` が2つのパスを表示し、エラーを出さない
- `common/` に移動元が残っていない：`ls batch-sample/src/main/java/com/example/batch/sample/common/ | grep -c '^Product'` が `0`
- 旧パッケージ名の参照がリポジトリに残っていない：`git grep -l --untracked 'sample.common.Product' -- ':!vault/'` の出力が空
- Mapper XML の namespace が移動先を指す：`grep -c 'sample.job02_fixedlength_import.ProductMapper' batch-sample/src/main/resources/mapper/ProductMapper.xml` が `1`
- 結合テストを含むビルドが通る（Checkstyle・SpotBugs・単体テスト・`Sample02FixedLengthImportJobIT`・batch-sample のカバレッジ80%）：`JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 ./mvnw clean verify 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` が `1`

## 決定済み
- 移動は `git mv` で行い、移動したファイルの `package` 宣言を `package com.example.batch.sample.job02_fixedlength_import;` に書き換える。クラス名・メソッド・record の成分・Javadoc の本文は変えない（パッケージ移動だけ）
- 同じパッケージになるため、`ProductItemProcessor.java`・`Sample02JobConfig.java`・テスト2本の `import com.example.batch.sample.common.Product;`・`import com.example.batch.sample.common.ProductMapper;` は書き換えずに削除する（Checkstyle の `RedundantImport`・`UnusedImports` に当たるため）。`SampleProperties` の import は `common` のまま残す
- `ProductMapper.xml` は `src/main/resources/mapper/` に置いたまま動かさない（`application.yml` の `mybatis.mapper-locations: classpath:mapper/*.xml` で読むため。案件ジョブも同じ置き方）。中の `namespace` を `com.example.batch.sample.job02_fixedlength_import.ProductMapper` に、`parameterType` を `com.example.batch.sample.job02_fixedlength_import.Product` に書き換える
- `Sample02JobConfig.java` の `.statementId("com.example.batch.sample.common.ProductMapper.upsert")` を `com.example.batch.sample.job02_fixedlength_import.ProductMapper.upsert` に書き換える（XML の namespace と一致させる。食い違いは結合テストで失敗する）
- Mapper の登録は `@Mapper` の自動スキャン（基底パッケージ `com.example.batch.sample` 配下）なので、`@MapperScan` の追加や設定変更は要らない
- `batch-core` のテストにある `Product` は batch-core 内の別クラス（テスト用）で、このタスクと関係ないので変えない。`docs/` には旧パッケージ名の参照が無いので変えない
- 旧パッケージ名の残りの確認から `vault/` を除くのは、計画票・タスク票がこの旧名を説明として含むため。`target/` は `git grep` の対象外（git 管理外）
- ビルドは結合テスト込みの `./mvnw clean verify` で確かめる（Docker が要る。`docker info` が失敗する時は blocked にして question に書く）
