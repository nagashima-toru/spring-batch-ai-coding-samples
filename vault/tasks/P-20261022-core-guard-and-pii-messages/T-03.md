# T-03 `ByteLengthLineTokenizer` の例外メッセージから行の内容を除く

## 目的
Issue #93 の対応として、`ByteLengthLineTokenizer` が送出する `BusinessException` のメッセージに入力の行をそのまま入れないようにし、バイト数・フィールド名・バイト位置だけを示す（方式設計 §8 の個人情報のログ出力禁止）。

## 入力
- `batch-core/src/main/java/com/example/batch/core/item/ByteLengthLineTokenizer.java`
- `batch-core/src/test/java/com/example/batch/core/item/ByteLengthLineTokenizerTest.java`
- `batch-core/src/main/java/com/example/batch/core/item/StrictCharsetEncoder.java`（値を含めないメッセージの先例。変更しない）
- `docs/architecture.md` §8 ロギング・監視方針

## 成果物
- 主な成果物：`batch-core/src/main/java/com/example/batch/core/item/ByteLengthLineTokenizer.java`（例外メッセージ2つの書式）
- 付随して変えるファイル：`batch-core/src/test/java/com/example/batch/core/item/ByteLengthLineTokenizerTest.java`

## 受け入れ基準
- 行をそのまま出す書式がリポジトリの Java に残っていない：`grep -rn --include=*.java 'line=%s' batch-core/src batch-sample/src` の出力が空
- 境界分断のメッセージがバイト位置を示す書式になっている：`grep -c 'offset=%d length=%d' batch-core/src/main/java/com/example/batch/core/item/ByteLengthLineTokenizer.java` の出力が `1`
- バイト長不一致のテストがメッセージ全体と行を含まないことを検証している：`grep -c 'expected=5 actual=11' batch-core/src/test/java/com/example/batch/core/item/ByteLengthLineTokenizerTest.java` と `grep -c 'hasMessageNotContaining(.TOOLONGLINE.)' batch-core/src/test/java/com/example/batch/core/item/ByteLengthLineTokenizerTest.java` の出力がどちらも `1`
- 境界分断のテストがメッセージ全体と行を含まないことを検証している：`grep -c 'field=a offset=0 length=3' batch-core/src/test/java/com/example/batch/core/item/ByteLengthLineTokenizerTest.java` と `grep -c 'hasMessageNotContaining(.あああ.)' batch-core/src/test/java/com/example/batch/core/item/ByteLengthLineTokenizerTest.java` の出力がどちらも `1`
- 全モジュールの静的解析・単体テストが通る：`./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` の出力が `1`
- batch-core のカバレッジ80%を満たす：`./mvnw clean verify -DskipITs -pl batch-core 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` の出力が `1`

## 決定済み
- バイト長不一致のメッセージは、書式を `"固定長レコードのバイト長が不正です: expected=%d actual=%d"`（`totalBytes`・`bytes.length`）にする。行（`line`）は渡さない
- 境界分断のメッセージは、書式を `"フィールド境界がマルチバイト文字を分断しています: field=%s offset=%d length=%d"` にする。`field` はフィールド名（`names[i]`。レイアウトの項目名で個人情報ではない）、`offset` はそのフィールドの先頭の0始まりのバイト位置（ループ内の `offset`）、`length` はそのフィールドのバイト長（`byteLengths[i]`）。行（`line`）は渡さない
- 書式の文字列は1つの文字列リテラルに書き、`+` で分けない（`offset=%d length=%d` が1行に並ぶようにする）
- クラスの Javadoc の「行のバイト長が定義合計と一致しない場合・フィールド境界がマルチバイト文字の途中にかかる場合は BusinessException を送出する」の段落の末尾に、「例外のメッセージには行の内容を含めず、バイト数・フィールド名・バイト位置を示す。」を足す
- 単体テスト（既存の2件を直す。メソッド名は変えない）：
  - `バイト長が不一致の行はBusinessExceptionをスローする`：`.hasMessageContaining("バイト長が不正")` を `.hasMessage("固定長レコードのバイト長が不正です: expected=5 actual=11")` に替え、`.hasMessageNotContaining("TOOLONGLINE")` を足す
  - `フィールド境界がマルチバイト文字を分断する場合はBusinessExceptionをスローする`：`.hasMessageContaining("分断")` を `.hasMessage("フィールド境界がマルチバイト文字を分断しています: field=a offset=0 length=3")` に替え、`.hasMessageNotContaining("あああ")` を足す
- `StrictCharsetEncoder`・`ErrorRecordSkipListener`・`FixedLengthItemReaderFactory` は変えない。読込時の Skip で `FlatFileParseException` のメッセージ（`input=[<行>]`）が WARN ログに出る件は #93 の範囲外（計画票の「次フェーズの候補」）
- `batch-sample/docs/sample02-fixedlength-import.md` はメッセージの文言を書いていないので変えない
- 古い書式の確認（`line=%s`）は `batch-core/src`・`batch-sample/src` の Java を対象にする（`OrderDailySalesJobConfig` の `"line=" +` はエラーファイルの行番号の書式で、`line=%s` には当たらない）
