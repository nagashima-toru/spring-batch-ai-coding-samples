## 決定済み
- 方式：`ValidatingItemProcessorBase#process` は final に戻す（コードの変更は T-02）。`@StepScope` のスコーププロキシは、Bean の型がインタフェースなら JDK 動的プロキシで作られ（Spring の `ScopedProxyFactoryBean` は対象型がインタフェースの時にインタフェースのプロキシを作る）、final メソッドを継承で上書きする必要が無い。このタスクでは設計書だけを変え、Java は変えない
- `docs/architecture.md` §13 の箇条書きの末尾に、次の1項目をそのまま足す（他の項目は変えない）：
  - `ValidatingItemProcessorBase` を継承した Processor を `@StepScope` の Bean にする時は、Bean メソッドの戻り値の型と注入先の引数の型を `ItemProcessor<入力型, 出力型>` にする（スコーププロキシがインタフェースの JDK 動的プロキシになり、final の `process()` を横取りできる。具象クラスの型にするとクラスを継承したプロキシになり、final の `process()` が未初期化のプロキシ本体で実行されて NullPointerException になる。結合テストでしか見つからない）
- `docs/decisions.md` の12行目（`@StepScope` で生成する Bean のクラスは final にせず…の行）は、「決めたこと」の列の `（`ValidatingItemProcessorBase#process` も final を外した）` を `（`ValidatingItemProcessorBase#process` は例外。Issue #76 で final に戻した。末尾の行を見る）` に置き換える。その行の他の列と、他の行は変えない
- `docs/decisions.md` の表の末尾に、次の1行をそのまま足す：
  - `| `ValidatingItemProcessorBase#process` を final に戻し、継承した Processor を `@StepScope` の Bean にする時は Bean メソッドの戻り値と注入先の型を `ItemProcessor<I, O>` にする（docs/architecture.md §13） | サブクラスが `process()` を上書きして super を呼ばないと入力チェックが黙って飛ばされるため。インタフェース型の Bean ならスコーププロキシが JDK 動的プロキシになり、final のままでも横取りできる | P-20261022-core-guard-and-pii-messages（Issue #76） |`
- ORDER-001 の §1 Bean 一覧の `orderDailySalesProcessor` の行は、型の列を次のようにする（スコープ・備考の列は変えない）：
  - `| `orderDailySalesProcessor` | `ItemProcessor<OrderCsvRecord, OrderDetailWork>`（実体は `OrderItemProcessor`） | `@StepScope` | …（備考は今のまま） |`
- ORDER-001 の §1 の `@StepScope` の注記（107〜112行目）は次のように直す：
  - 「Bean メソッドの戻り値の型は具象クラスにする（…）」の行の直後に、`ただし `ValidatingItemProcessorBase` を継承した Processor（`orderDailySalesProcessor`）は、戻り値と注入先の型を `ItemProcessor<OrderCsvRecord, OrderDetailWork>` にする（docs/architecture.md §13）` という内容の行を足す
  - 「継承元の public メソッド（`ValidatingItemProcessorBase#process` など）も final にしない（final だとプロキシが上書きできず、プロキシ経由の呼び出しで target の状態が使われない）」は、`（`ValidatingItemProcessorBase#process` など）` を削って「継承元の public メソッドも final にしない（…）。`ValidatingItemProcessorBase#process` は例外で final にし、上のとおりインタフェース型の Bean にする（Issue #76）」にする
  - 「`@StepScope` で生成するクラスは final にしない」の行と、`OrderItemProcessor` のクラス自体を final にしない扱いは変えない
- ORDER-001 の §8 変更履歴の末尾に、日付 `2026-10-22`・版 `1.8` で、変更内容が `Issue #76: ` で始まる1行を足す。変更内容は「Issue #76: `ValidatingItemProcessorBase#process` を final に戻した。§1 Bean 一覧の `orderDailySalesProcessor` の型を `ItemProcessor<OrderCsvRecord, OrderDetailWork>` にし、`@StepScope` の注記を直す」とする。ORDER-001 の冒頭の「ステータス」は変えない
