## 決定済み
- 長さ超過のメッセージは、書式を `"フィールド値が固定長 %dバイト を超えています: index=%d actual=%d"` にする。引数は順に `byteLengths[i]`（幅）・`i`（0始まりのフィールドの添字。`StrictCharsetEncoder` に渡す `index=` と同じ数え方）・`bytes.length`（値のバイト数）。値（`value`）は渡さない
- 書式の文字列は1つの文字列リテラルに書き、`+` で分けない
- クラスの Javadoc の「フィールド値が指定バイト長を超える場合は BusinessException を送出する（切り捨てによるデータ破損を防ぐため）。」の直後に、「例外のメッセージには値を含めず、フィールドの添字（0始まり）・固定長のバイト数・値のバイト数を示す。」を足す
- `pad(byte[], int, String)` の引数 `value` は拡張ポイントの互換のため残す（変えない）
- 単体テスト `バイト長を超えるフィールド値はBusinessExceptionをスローする`（メソッド名は変えない）：`.hasMessageContaining("超えています")` を `.hasMessage("フィールド値が固定長 2バイト を超えています: index=0 actual=7")` に替え、`.hasMessageNotContaining("TOOLONG")` を足す（`aggregator(2, 4, 3)` に `new Product("TOOLONG", "x", "1")` を渡すので、添字0・幅2バイト・値7バイト）
- `batch-sample/docs/sample03-file-export.md` の「固定長のレイアウト（1行63バイト）」節の箇条書き「各項目の幅は、…値が幅を超えると `BusinessException` で失敗する」の行の末尾に、次の1文をそのまま足す：「例外のメッセージには値を含めず、フィールドの添字・幅・値のバイト数を示す」。句点の扱いは前後の文に合わせる。他の行は変えない
- `StrictCharsetEncoder`・`FixedLengthItemWriterFactory`・sample03 のジョブのコードは変えない
- 古い書式の確認（`value=%s`）は `batch-core/src`・`batch-sample/src` の Java を対象にする
