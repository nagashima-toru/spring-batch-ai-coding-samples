# T-02 `ValidatingItemProcessorBase.process()` を final に戻し、`orderDailySalesProcessor` をインタフェース型の Bean にする

## 目的
Issue #76 の対応として、`ValidatingItemProcessorBase.process()` を final に戻し、サブクラスが入力チェック（Bean Validation）を飛ばせないようにする。`@StepScope` の `orderDailySalesProcessor` は T-01 で改訂した方式設計 §13 どおりインタフェース型の Bean にし、結合テストで動くことを確かめる。

## 入力

- `docs/projects/order-daily-sales/detail-design/ORDER-001.md` §1 Bean 一覧（T-01 で改訂済み）
- `batch-core/src/main/java/com/example/batch/core/item/ValidatingItemProcessorBase.java`
- `batch-core/src/test/java/com/example/batch/core/item/ValidatingItemProcessorBaseTest.java`

- `batch-sample/src/test/java/com/example/batch/sample/job_order_daily_sales/OrderDailySalesJobIT.java`（変更しない。プロキシの動作を確かめる結合テスト）

- `ValidatingItemProcessorBase.java` から「final にしない」の記述が消えている：`grep -c 'final にしない' batch-core/src/main/java/com/example/batch/core/item/ValidatingItemProcessorBase.java` の出力が `0`
- final を確かめる単体テストがある：`grep -c 'void processメソッドの修飾子＿finalである' batch-core/src/test/java/com/example/batch/core/item/ValidatingItemProcessorBaseTest.java` の出力が `1`
- `orderDailySalesProcessor` の Bean メソッドの戻り値と注入先の型がインタフェース型：`grep -c 'public ItemProcessor.OrderCsvRecord, OrderDetailWork. orderDailySalesProcessor(' batch-sample/src/main/java/com/example/batch/sample/job_order_daily_sales/OrderDailySalesJobConfig.java` と `grep -c 'ItemProcessor.OrderCsvRecord, OrderDetailWork. orderDailySalesProcessor,' batch-sample/src/main/java/com/example/batch/sample/job_order_daily_sales/OrderDailySalesJobConfig.java` の出力がどちらも `1`
- 全モジュールの静的解析・単体テストが通る：`./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` の出力が `1`
- batch-core のカバレッジ80%を満たす：`./mvnw clean verify -DskipITs -pl batch-core 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` の出力が `1`
- 結合テスト（`OrderDailySalesJobIT` の `@StepScope` のプロキシ経由の実行を含む）が通る：`./mvnw clean verify 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` の出力が `1`

## 決定済み
- `ValidatingItemProcessorBase.process()` のシグネチャは `public final O process(I item) throws Exception` にする（本体は変えない）
- `process()` の Javadoc の「`@StepScope` の Bean として使えるよう…final にしない。サブクラスでのオーバーライドは想定しない。」の段落は、次の内容に置き換える：「入力チェックを必ず `doProcess` の前に実行するため final にする。`@StepScope` の Bean にする時は、Bean メソッドの戻り値と注入先の型を `ItemProcessor<I, O>` にする（スコーププロキシがインタフェースの JDK 動的プロキシになる。docs/architecture.md §13）。」。「final にしない」の語は残さない
- 単体テストは `ValidatingItemProcessorBaseTest` に `void processメソッドの修飾子＿finalである()` を1件足す。中身は `ValidatingItemProcessorBase.class.getMethod("process", Object.class)` の修飾子が `java.lang.reflect.Modifier.isFinal` で真であることを AssertJ で確かめる（final を再び外す変更を単体テストで止めるため）。既存のテストは変えない
- `OrderDailySalesJobConfig.java`：
  - `orderDailySalesProcessor` の Bean メソッドは `public ItemProcessor<OrderCsvRecord, OrderDetailWork> orderDailySalesProcessor(Validator validator,` とし、本体（`new OrderItemProcessor(...)` を返す）・`@Bean`・`@StepScope` は変えない
  - `orderDailySalesImportStep` の引数 `OrderItemProcessor orderDailySalesProcessor,` を `ItemProcessor<OrderCsvRecord, OrderDetailWork> orderDailySalesProcessor,` にする
  - `ItemProcessor` は `org.springframework.batch.infrastructure.item.ItemProcessor` を import する（Batch 6 のパッケージ。5系の `org.springframework.batch.item` は使わない）。使わなくなった import は消す（Checkstyle）
- `OrderItemProcessor.java` は変えない（クラスを final にしない Javadoc の注記もそのままにする。ORDER-001 §1 の「`@StepScope` で生成するクラスは final にしない」に従う）。他のジョブの Processor は `@StepScope` でないので変えない
- ArchUnit などの依存は足さない（final にすればコンパイラが上書きを止めるため）
- `./mvnw clean verify` は Docker が要る。Docker が使えずに結合テストを実行できない時は、基準を満たせないので blocked にし、question にその旨を書く
- 結合テストで、インタフェース型にしても `@StepScope` の Bean の生成・注入に失敗する時（NullPointerException や型の不一致）は、方式を勝手に変えず（final を外す・ArchUnit に切り替えるなど）blocked にし、question に失敗したテストと例外の要点を書く
