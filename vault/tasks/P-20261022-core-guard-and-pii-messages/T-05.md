# T-05 計画の差分が `/code-review` を通過する

計画全体（T-01〜T-04）の差分を組み込みの `/code-review` で確かめ、致命的な指摘が残っていない状態にする。修正で計画全体の動作（ビルド・単体テスト・結合テスト）と Issue #76・#93 の達成を壊していないことを確かめる。

## 入力

## 受け入れ基準
- `/code-review` で計画の差分に致命的な指摘が残っていない（`vault/rules/verifier/code-review.md` に従って判定する）
- 全モジュールの静的解析・単体テストが通る：`./mvnw clean verify -DskipITs -Djacoco.haltOnFailure=false 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` の出力が `1`
- batch-core のカバレッジ80%を満たす：`./mvnw clean verify -DskipITs -pl batch-core 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` の出力が `1`
- 結合テストを含む全体のビルド（batch-sample のカバレッジ80%を含む）が通る：`./mvnw clean verify 2>&1 | grep -c '^.INFO. BUILD SUCCESS'` の出力が `1`
- `process()` が final のまま：`grep -c 'public final O process(I item)' batch-core/src/main/java/com/example/batch/core/item/ValidatingItemProcessorBase.java` の出力が `1`
- 行をそのまま出す書式が残っていない：`grep -rn --include=*.java 'line=%s' batch-core/src batch-sample/src` の出力が空
- 値をそのまま出す書式が残っていない：`grep -rn --include=*.java 'value=%s' batch-core/src batch-sample/src` の出力が空

## 決定済み
- レビューの範囲は、ベースブランチ（`HARNESS_BASE_BRANCH`、前後の空白を除いて空なら `main`）との分岐点からの計画全体の差分（`git -C <worktree のパス> diff --merge-base <ベースブランチ>`）とする
- 計画一式4種（`vault/plans/`・`vault/tasks/`・`vault/verdicts/`・`vault/log/`）はレビューの対象にしない
- 致命的な指摘が無ければ成果物を変えず、「進捗」への記録だけでよい（「進捗」の追記が収集コミットになるので、新規コミット無しの blocked にはならない）
- 差分の外（既存コード）・致命的でない指摘・設計や仕様の変更が要る指摘の扱いは、`.claude/agents/creator.md`・`.claude/agents/verifier.md` の「コードレビューを参照する基準」の節に従う
- 読込時の Skip で `FlatFileParseException` のメッセージ（`input=[<行>]`）が `ErrorRecordSkipListener` の WARN ログに出る件は差分の外（既存コード）で、計画票の「次フェーズの候補」に挙げてある。このタスクでは直さない
- #76 の方式（`process()` を final に戻し、`@StepScope` の Processor をインタフェース型の Bean にする）を変える指摘は、設計の変更が要る指摘として扱い、独断で直さない
- `./mvnw clean verify` は Docker が要る。Docker が使えずに実行できない時は blocked にし、question にその旨を書く
- 人の回答（B）：具象型の `@StepScope` の Bean を検出する ArchUnit のテストを足す。T-06 で足すので、T-05 は T-06 の完了後に再実行する。T-06 の成果物（`pom.xml`・`batch-sample/pom.xml`・`StepScopeBeanRuleTest.java`・`docs/architecture.md`・`docs/decisions.md`）も計画の差分としてレビューする
