# システムテスト Skill

業務シナリオ・運用観点（スケジュール実行・リラン・異常終了時の運用）でジョブ群を検証する。
結合テストが「ジョブ単体の仕様どおりの動作」を保証するのに対し、システムテストは
「業務・運用の流れの中で使えること」を確認する。

## 入力と出力（工程連鎖）

| | 内容 |
|---|---|
| 入力 | `docs/projects/{案件名}/basic-design.md`（ジョブ一覧・運用設計）、要件定義書の業務フロー |
| 出力 | `docs/projects/{案件名}/system-test/scenarios.md`（テンプレート: `templates/system-test-scenario-template.md`）と実施記録 |
| 出力 | テストデータ生成スクリプト（必要時）: `docs/projects/{案件名}/system-test/data/` |

## シナリオ設計の観点

### 業務シナリオ
- 業務の1サイクル（例: 日次締め）をジョブの実行順どおりに通す
- 前続ジョブの出力を後続ジョブが正しく受け取れるか（IF整合）
- 件数・金額が業務上の期待値と一致するか（入出力の突合）

### 運用観点（必ず含める）
| 観点 | 確認内容 |
|---|---|
| 終了コード連携 | 正常0/警告2/異常1 が スケジューラ（EventBridge/Step Functions）に正しく伝播 |
| リラン | 異常終了 → 原因除去 → 同一パラメータ再実行で再開・完走（運用手順書どおりに実施） |
| 二重起動 | 実行中に同一ジョブを起動して防止されること |
| 警告終了の運用 | エラーレコードファイルの確認 → 修正 → 再取込の一連の流れ |
| 処理時間 | 本番相当データ量での処理時間が制約内か（チャンクサイズ調整の要否） |
| ログ・監視 | CloudWatch で件数・失敗が確認できるか（構造化ログの項目） |

### テストデータ
- 本番相当の件数・分布（偏り）を再現する（性能確認シナリオ用）
- 個人情報は使用しない（生成データまたはマスキング済みデータ）
- 生成はスクリプト化して再現可能にする（SQL / スクリプトを成果物として残す）

## 進め方

1. 基本設計書のジョブ一覧・運用設計からシナリオ一覧を作成しユーザーと合意する
2. シナリオごとに 事前条件 / 手順 / 期待結果 をテンプレートへ記述する
3. 実施はユーザー（またはローカル/検証環境で本 Skill が）行い、結果と証跡を記録する
4. 不具合は Issue 化し、修正は `/implementation` 以降の工程を再度通す
